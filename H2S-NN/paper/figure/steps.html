Step-by-Step Process of the H2SNN Framework

  1. Input the heterogeneous graph
    1. The framework starts with a graph that has different node types, such as papers, authors, subjects, movies, actors, or directors.
    2. The graph also has different link types, such as paper-author, paper-subject, movie-actor, and movie-director.
    3. The model keeps the type of every node and every link, because each type has a different meaning.
  2. Prepare node features
    1. Each node starts with its own raw features.
    2. Different node types may have different feature sizes, so the framework first converts them into one shared hidden size.
    3. After this step, all nodes can be processed together, while their original node types are still remembered.
  3. Build the type map of the graph
    1. The framework looks only at node types and link types.
    2. For example, it sees that Paper can connect to Author, and Author can connect back to Paper.
    3. This creates a small type-level map that shows which type-to-type moves are possible.
  4. AMPSS: generate possible path patterns
    1. AMPSS means Adaptive Meta-Path Schema-to-Cell Selection.
    2. It automatically creates possible typed path patterns from the type map.
    3. For example, in ACM, possible patterns may include Paper-Author-Paper and Paper-Subject-Paper.
    4. AMPSS only keeps patterns that satisfy the allowed length range, such as two-hop, three-hop, or four-hop paths.
    5. It can also require paths to start or end at the target node type, depending on the task.
    6. This step creates a candidate list of path patterns, but they are not selected yet.
  5. AMPSS: find real examples of each path pattern
    1. For every candidate path pattern, AMPSS searches the real graph for actual paths that match it.
    2. For example, if the pattern is Paper-Author-Paper, AMPSS finds real cases where two papers are connected through an author.
    3. These real examples are limited by a budget, so the framework does not collect too many paths and become too slow.
    4. AMPSS counts how many real examples each pattern has.
  6. AMPSS: measure how useful each path pattern looks
    1. AMPSS checks whether a path pattern reaches many useful target nodes.
    2. It checks whether the pattern covers different parts of the graph instead of only repeating the same small area.
    3. It checks whether the pattern uses meaningful type variety, such as passing through different node or link types.
    4. For node classification, it uses only training-label information to estimate whether the path connects nodes with useful label differences.
    5. Validation labels and test labels are not used in this selection step.
    6. The result is a usefulness score for every candidate path pattern.
  7. AMPSS: remove repeated or overlapping patterns
    1. Some path patterns may reach almost the same nodes and give almost the same information.
    2. AMPSS compares candidate patterns with already selected patterns.
    3. If a new pattern overlaps too much with an existing selected pattern, its score is reduced.
    4. This encourages AMPSS to keep a diverse set of useful patterns instead of many copies of the same idea.
  8. AMPSS: select the final path-pattern pool
    1. AMPSS starts with an empty selected pool.
    2. It picks the best remaining path pattern based on usefulness, coverage, diversity, and low overlap.
    3. Then it repeats the process until the selected pool reaches the configured size.
    4. The output is a compact set of useful path patterns.
  9. Convert selected path patterns into path groups
    1. For every selected path pattern, the framework keeps the real path examples found in the graph.
    2. Each real path example stores its ordered nodes and ordered links.
    3. The order matters, because Paper-Author-Paper is not treated as a random set of nodes.
    4. The framework also adds a closing link from the last node back to the first node, so the path can be treated as a complete higher-level structure.
    5. The output is a set of selected path groups that will guide information spreading later.
  10. Learn one importance weight for each selected path pattern
    1. AMPSS does not force every selected pattern to be equally important.
    2. The model learns one pattern-level weight for each selected path pattern.
    3. A useful pattern receives a stronger weight.
    4. A weak or noisy pattern receives a smaller weight.
  11. Learn one importance weight for each real path example
    1. Even if a path pattern is useful, not every real example of that pattern is useful.
    2. For example, Paper-Author-Paper may be helpful overall, but some paper pairs connected by the same author may still be unrelated.
    3. So the model also learns an example-level weight for every real path instance.
    4. This weight is based on the start node, the end node, and the selected path pattern.
    5. The final path weight combines the pattern-level weight and the example-level weight.
  12. Translate information across direct links
    1. Different node types do not mean the same thing, so their information cannot simply be copied directly.
    2. The framework learns type-aware translators for each link type.
    3. These translators decide how information from the source node and target node should be compared through that link.
    4. This produces an initial link representation that describes the relationship between the two endpoint nodes.
  13. Translate information from links into selected path groups
    1. Each selected real path is made of several ordered links.
    2. The framework reads the links in order, from the first link to the last link.
    3. It learns which positions in the path are more important.
    4. Then it builds a translator from each link into the whole path group.
    5. This allows links inside the same selected path to influence each other.
  14. Spread information through the graph
    1. The model updates node information using direct links.
    2. It also updates link information using the selected path groups from AMPSS.
    3. This means a node learns from direct neighbors, while links learn from larger multi-step structures.
    4. The selected AMPSS weights control how strongly each path pattern and each real path example affects this update.
  15. Repeat the update process several times
    1. The framework repeats the information-spreading step for several rounds.
    2. After each round, node information becomes richer.
    3. Link information also becomes richer because it has seen both direct endpoint information and selected path-group information.
    4. The final result is an updated node representation and an updated link representation.
  16. Make task-specific predictions
    1. For node classification, the model reads the final representation of the target nodes.
    2. It combines the final node information, the original encoded node information, and nearby link information.
    3. For link prediction, the model compares the final representations of two candidate nodes.
    4. For graph classification, the model sends the final node and link information into SheafCovPool.
  17. SheafCovPool: prepare graph-level information
    1. SheafCovPool is used when the output is a graph label.
    2. It does not create a smaller graph hierarchy.
    3. Instead, it acts as the final graph summarizer.
    4. For each node, it collects three views: final node information, initial node information, and nearby link information.
    5. For each link, it collects three views: final link information, initial link-difference information, and final link-difference information.
  18. SheafCovPool: create stable node and link summaries
    1. For every node, SheafCovPool compares its three views with each other and creates a small 3-by-3 summary.
    2. For every link, it does the same and creates a small 3-by-3 summary.
    3. These summaries describe how the different views agree or differ.
    4. This helps the graph summary stay stable even when the internal coordinate system changes.
  19. SheafCovPool: choose important nodes and links
    1. The 3-by-3 node summaries are converted into compact node tokens.
    2. The 3-by-3 link summaries are converted into compact link tokens.
    3. SheafCovPool learns attention scores for nodes and links.
    4. Important nodes and links receive stronger attention.
    5. Noisy or less useful nodes and links receive weaker attention.
  20. SheafCovPool: summarize the whole graph
    1. SheafCovPool computes an attention-weighted average of node tokens.
    2. It also computes how much the node tokens vary across the graph.
    3. It repeats the same process for link tokens.
    4. The final graph summary contains four parts: average node information, node variation, average link information, and link variation.
  21. Output the final prediction
    1. The final representation is passed into a classifier.
    2. The classifier produces the final output.
    3. The output can be a node class, a link score, or a graph class, depending on the task.
