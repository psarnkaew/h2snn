Implementation specification

H2S-Pool: Gauge-Equivariant Typed Sheaf Pooling for Graph Classification

A detailed design document for implementing a true hierarchical sheaf pooling layer that produces graph-level representations while respecting permutation symmetry, gauge symmetry, heterogeneous node/edge types, and heterophilous structure.

Intended users: Codex, Claude Code, and human researchers implementing H2S-NN-style graph classification models.

Historical status: superseded

This document records an abandoned hierarchical pooling exploration and is not the current H2S-NN graph readout. The finalized method is SheafCovPool, a single-level, attention-based mean-and-covariance readout over orthogonal-gauge-invariant Gram descriptors. See the current mechanism specification. THS-Pool, Galerkin coarsening, spectral pooling, and other hierarchical variants below are retained only as historical design work.

Core idea in one paragraph

SHEAFPOOL-style readout solves a useful but limited problem: it aggregates stalk-valued node embeddings into one graph representation. H2S-Pool is more ambitious. It performs actual hierarchical sheaf pooling: it maps a fine graph sheaf $(G,\mathcal F,H)$ into a smaller coarse graph sheaf $(G',\mathcal F',H')$, then optionally applies further sheaf message passing on the coarse graph. The intermediate hierarchy should be permutation-equivariant and gauge-equivariant, while only the final graph representation must be permutation-invariant and gauge-invariant.

1. Scope and design principle

The target problem is graph classification using a sheaf neural network on homogeneous, heterogeneous, or heterophilous graphs. The method should produce a graph representation $h_G$ for each input graph and should be compatible with hierarchical pooling.

1.1 Readout versus actual pooling

Operation Input Output Example Limitation
Terminal graph readout $\{H_v\}_{v\in V}$ $h_G$ Mean, sum, attention, SHEAFPOOL No smaller graph; no subsequent coarse sheaf diffusion
Hierarchical graph pooling $(G,\mathcal F,H)$ $(G',\mathcal F',H')$ with $|V'|<|V|$ DiffPool-style coarsening, MinCut-style coarsening, proposed H2S-Pool Requires valid coarse graph and valid coarse sheaf

Do not implement H2S-Pool as only global_pool(H). The intended contribution is a coarsening layer that can be placed between sheaf convolution blocks.

1.2 Main design principle

$$ \boxed{ \text{intermediate hierarchy: permutation-equivariant and gauge-equivariant} } $$ $$ \boxed{ \text{final graph representation: permutation-invariant and gauge-invariant} } $$

Intermediate layers should not collapse all gauge-dependent information into scalar invariants too early. Stalk-valued signals often need to remain vector- or matrix-valued so that later sheaf convolution layers can process them. The final classifier, however, must not depend on arbitrary node ordering or arbitrary stalk coordinate choices.

3. Required symmetries

3.1 Permutation equivariance and invariance

Let $P$ be a permutation matrix acting on nodes. A valid pooling layer should satisfy:

$$ \operatorname{Pool}(PH, PAP^\top, P\mathcal F P^\top) = P'\operatorname{Pool}(H,A,\mathcal F), $$

where $P'$ is the induced permutation of supernodes. For the final graph representation:

$$ h_G(PH, PAP^\top, P\mathcal F P^\top)=h_G(H,A,\mathcal F). $$

Implementation rule: assignment scores and pooling operations should use message passing, scatter operations, segment softmax, and symmetric reductions, never raw node indices as features.

3.2 Gauge transformations

A gauge transformation is a local change of stalk basis. For each node $v$:

$$ H_v \mapsto \widetilde H_v = G_v H_v, \qquad G_v\in \mathcal G_v. $$

For an edge transport map $F_{u\to v}$, the consistent transformation is:

$$ F_{u\to v}\mapsto \widetilde F_{u\to v} = G_v F_{u\to v}G_u^{-1}. $$

If $H_v$ changes by $G_v$ and $F_{u\to v}$ changes accordingly, the transported signal transforms consistently:

$$ \widetilde F_{u\to v}\widetilde H_u = G_vF_{u\to v}G_u^{-1}G_uH_u = G_vF_{u\to v}H_u. $$

3.3 Recommended gauge group

For exact implementation and testing, start with the orthogonal gauge group $O(d)$, not unrestricted $GL(d)$. Orthogonal gauge invariance is clean because Gram matrices and Frobenius norms are exactly invariant:

$$ (QH)^\top(QH)=H^\top H,\qquad Q^\top Q=I. $$

General $GL(d)$ invariance requires whitening or quotient constructions and is usually only approximate under rank deficiency and regularization. Do not overclaim exact $GL(d)$ invariance unless proven and tested.

3.4 Correct symmetry target

Stage Permutation behavior Gauge behavior Reason
Assignment network Equivariant Invariant Cluster membership should not depend on coordinate basis
Transported pooled stalks Equivariant Equivariant Coarse stalks should remain valid sheaf signals
Coarse sheaf maps Equivariant Equivariant Restriction maps must transform with coarse stalk bases
Final readout Invariant Invariant Graph label should not depend on ordering or basis

4. Proposed architecture

The full model should be implemented as a stack of sheaf convolution and sheaf pooling blocks:

$$ (G^{(0)},\mathcal F^{(0)},H^{(0)}) \xrightarrow{\text{SheafConv}} (G^{(0)},\mathcal F^{(0)},H^{(1)}) \xrightarrow{\text{H2S-Pool}} (G^{(1)},\mathcal F^{(1)},H^{(1)}_{pool}) $$ $$ \xrightarrow{\text{SheafConv}} (G^{(1)},\mathcal F^{(1)},H^{(2)}) \xrightarrow{\text{FinalReadout}} h_G \xrightarrow{\text{MLP}} \hat y_G. $$

4.1 Module pipeline

  1. Sheaf encoder: compute stalk-valued node embeddings $H_v$.
  2. Invariant descriptor builder: compute gauge-invariant node, edge, and role features.
  3. Type-aware assignment network: compute $S\in\mathbb R^{n\times m}$ with type constraints.
  4. Transport builder: compute or retrieve $T_{v\to a}$.
  5. Transported stalk pooling: compute $H'_a$.
  6. Coarse graph and coarse sheaf constructor: compute $A'$, $F'$, or $L_{\mathcal F'}$.
  7. Optional repeated hierarchy: apply another sheaf block on the coarse graph.
  8. Final invariant readout: produce $h_G$ for graph classification.

The strongest implementation path is incremental: first implement a terminal invariant readout baseline, then implement type-aware assignments, then transported stalk pooling, then coarse sheaf maps, then Galerkin coarsening.

5. Gauge-invariant descriptors

The assignment matrix should be computed from gauge-invariant descriptors. This prevents cluster membership from changing under arbitrary local basis changes.

5.1 Node Gram descriptor

For orthogonal gauges $Q_v\in O(d)$, the simplest invariant descriptor is the channel Gram matrix:

$$ K_v = H_v^\top H_v \in \mathbb R^{C\times C}. $$ $$ (Q_vH_v)^\top(Q_vH_v)=H_v^\top Q_v^\top Q_vH_v=H_v^\top H_v. $$

Use either the full symmetric matrix or its upper-triangular vectorization:

$$ k_v=\operatorname{vec}_{\mathrm{sym}}(K_v). $$

Avoid using only $\operatorname{diag}(K_v)$ as the main descriptor. The diagonal keeps per-channel energies but discards cross-channel geometry.

5.2 Normalized Gram descriptor

To reduce scale sensitivity, use a normalized Gram:

$$ \bar K_v = \frac{H_v^\top H_v}{\operatorname{tr}(H_v^\top H_v)+\epsilon}. $$

This is useful when graph size, node degree, or feature magnitude varies substantially across datasets.

5.3 Edge residual descriptor

Sheaf information is not only in node stalks; it is also in edge-level disagreement. For edge $e=(u,v)$:

$$ r_e = F_{u\to e}H_u - F_{v\to e}H_v. $$

If using directed node-to-node transport maps $F_{u\to v}$, a simplified residual is:

$$ r_{u\to v}=F_{u\to v}H_u-H_v. $$

Gauge-invariant residual descriptors include:

$$ E_e=\|r_e\|_F^2, \qquad R_e=r_e^\top r_e. $$

These descriptors are especially important for heterophily, where disagreement is not always noise; it may be task-relevant signal.

5.4 Node role descriptor

For heterophilous graphs, assignment should rely on structural role, not just feature similarity. Construct:

$$ \operatorname{role}(v)= \operatorname{concat} \left[ \{\deg_r(v)\}_{r\in\mathcal R}, \{\bar E_{v,r}\}_{r\in\mathcal R}, \operatorname{PE}(v), \operatorname{typeEmb}(\tau(v)) \right]. $$

Here $\bar E_{v,r}$ is the average relation-specific sheaf residual energy around node $v$:

$$ \bar E_{v,r} = \frac{1}{|\mathcal N_r(v)|+\epsilon} \sum_{u\in\mathcal N_r(v)} \|F_{u\to v}^{(r)}H_u-H_v\|_F^2. $$

5.5 Assignment input feature

The assignment network should receive only invariant or type/structure information:

$$ z_v^{assign} = \operatorname{concat} \left[ \operatorname{vec}_{sym}(\bar K_v), \operatorname{role}(v), \operatorname{typeEmb}(\tau(v)) \right]. $$

Do not feed raw flattened $H_v$ to the assignment network unless you explicitly allow gauge-dependent assignments.

6. Type-aware assignment matrix

The assignment matrix $S\in\mathbb R^{n\times m}$ maps fine nodes to coarse supernodes.

$$ S_{va}\ge 0, \qquad \sum_{a=1}^{m}S_{va}=1. $$

6.1 Type-preserving assignment

For heterogeneous graphs, the safest formulation is type-preserving pooling. Let coarse supernode $a$ have type $\tau'(a)$. Then:

$$ S_{va}=0 \quad\text{if}\quad \tau(v)\ne \tau'(a). $$

This prevents invalid merges such as pooling author nodes and venue nodes into the same uninterpretable supernode.

6.2 Type-specific cluster counts

For each node type $t$, choose a pooling ratio $r_t\in(0,1]$ and define:

$$ m_t=\max\left(1,\left\lceil r_t n_t\right\rceil\right), \qquad n_t=|\{v:\tau(v)=t\}|. $$

The total number of coarse nodes is:

$$ m=\sum_{t\in\mathcal T_V}m_t. $$

6.3 Prototype-based assignment

For each type $t$, maintain learnable cluster prototypes $c_{t,1},\dots,c_{t,m_t}$. Compute:

$$ q_v=\phi_t(z_v^{assign}), \qquad \ell_{v,a}=q_v^\top c_{t,a}, \quad a\in\mathcal C_t. $$

Then apply a type-restricted softmax:

$$ S_{v,a} = \frac{\exp(\ell_{v,a}/\tau_S)} {\sum_{b\in\mathcal C_{\tau(v)}}\exp(\ell_{v,b}/\tau_S)}. $$

$\tau_S$ is a temperature. Lower values create harder assignments; higher values create smoother assignments.

6.4 Assignment regularization

Avoid cluster collapse with a balance loss:

$$ \mathcal L_{bal} = \sum_{t\in\mathcal T_V} \left\| \frac{1}{n_t}S_t^\top\mathbf 1_{n_t} - \frac{1}{m_t}\mathbf 1_{m_t} \right\|_2^2. $$

Optionally encourage interpretable assignments with entropy:

$$ \mathcal L_{ent} = -\frac{1}{n} \sum_{v=1}^{n}\sum_{a=1}^{m} S_{va}\log(S_{va}+\epsilon). $$

Usually minimize entropy weakly. Do not over-penalize entropy early in training because hard assignments can destabilize sheaf coarsening.

7. Transport-before-pooling

A core issue in sheaf pooling is that stalk embeddings at different nodes live in different local coordinate systems. Therefore, the expression

$$ \sum_v S_{va}H_v $$

is generally not geometrically meaningful. We must transport all node stalks into the supernode stalk before addition.

7.1 Main pooling formula

$$ H'_a = \frac{1}{Z_a} \sum_{v=1}^{n} S_{va}\,T_{v\to a}H_v, \qquad Z_a=\sum_{v=1}^{n}S_{va}+\epsilon. $$

Here $T_{v\to a}\in\mathbb R^{d'_a\times d_v}$ maps from node $v$'s stalk to supernode $a$'s stalk.

7.2 Gauge-equivariance condition

Suppose:

$$ H_v\mapsto \widetilde H_v=G_vH_v, \qquad H'_a\mapsto \widetilde H'_a=G'_aH'_a. $$

The transport map must transform as:

$$ T_{v\to a}\mapsto \widetilde T_{v\to a} = G'_aT_{v\to a}G_v^{-1}. $$

Then the pooled stalk transforms equivariantly:

$$ \widetilde H'_a = \frac{1}{Z_a}\sum_v S_{va}\widetilde T_{v\to a}\widetilde H_v = \frac{1}{Z_a}\sum_v S_{va}G'_aT_{v\to a}G_v^{-1}G_vH_v = G'_aH'_a. $$

This is the key theorem that makes the pooling layer mathematically clean.

7.3 Practical transport variants

Variant Description Difficulty Recommended use
A. Identity transport baseline Assume all stalks of the same type share a common frame; $T_{v\to a}=I$ for same type. Low Debugging baseline only; not full gauge-equivariant sheaf pooling
B. Existing sheaf-map transport Build $T_{v\to a}$ from products or averages of learned restriction maps along paths. Medium Best first serious implementation
C. Cluster barycentric transport Estimate local cluster frames by minimizing transport disagreement inside each cluster. High Research-grade extension
D. Invariant-statistic pooling Pool $H_v^\top H_v$ and residual energies instead of stalk vectors. Low-Medium Terminal readout or ablation, not intermediate sheaf coarsening

7.4 Path-based transport

If there is a path $p=(v=v_0,v_1,\dots,v_k=a)$ from node $v$ to a representative or anchor of cluster $a$, define:

$$ T_{v\to a}^{(p)} = F_{v_{k-1}\to v_k}\cdots F_{v_0\to v_1}. $$

If multiple paths exist, use attention-weighted path transport:

$$ T_{v\to a} = \sum_{p\in\mathcal P(v,a)}\alpha_p T_{v\to a}^{(p)}, \qquad \sum_p\alpha_p=1. $$

The path attention $\alpha_p$ should be computed from gauge-invariant path descriptors, such as path type, path length, and transported residual energies.

7.5 Cluster representative approximation

For implementation simplicity, each soft cluster $a$ may choose a representative node $r(a)$ by maximum assignment:

$$ r(a)=\arg\max_v S_{va}. $$

Then approximate $T_{v\to a}$ by transport from $v$ to $r(a)$ using shortest paths or relation-specific message passing. This is useful for early experiments, but it makes the method less differentiable because of the hard representative choice. A differentiable approximation uses a weighted mixture over possible representatives:

$$ T_{v\to a} = \sum_{r=1}^{n} \beta_{r|a}T_{v\to r}, \qquad \beta_{r|a}=\frac{S_{ra}}{\sum_u S_{ua}+\epsilon}. $$

8. Coarsening the sheaf

A real sheaf pooling layer must output a coarse graph and a coarse sheaf, not only pooled node features.

8.1 Coarse adjacency

For each relation type $r$, let $A^{(r)}\in\mathbb R^{n\times n}$ be the fine adjacency matrix. The coarse relation adjacency is:

$$ A'^{(r)} = S^\top A^{(r)} S. $$

Entrywise:

$$ A'^{(r)}_{ab} = \sum_{u,v}S_{ua}A^{(r)}_{uv}S_{vb}. $$

In type-preserving pooling, $A'^{(r)}_{ab}$ is only valid if the coarse source and target types match the schema of relation $r$.

8.2 Coarse restriction maps

For directed edge type $r:u\to v$, aggregate fine restriction maps into a coarse transport map:

$$ F'^{(r)}_{a\to b} = \frac{1}{Z_{ab}^{(r)}} \sum_{(u,v)\in E_r} S_{ua}S_{vb} T_{v\to b} F^{(r)}_{u\to v} T_{u\to a}^{\dagger}, $$ $$ Z_{ab}^{(r)}= \sum_{(u,v)\in E_r}S_{ua}S_{vb}+\epsilon. $$

$T_{u\to a}^{\dagger}$ is a pseudoinverse or adjoint transport from the supernode frame back to node $u$'s frame. If transports are orthogonal, $T^\dagger=T^\top$.

8.3 Gauge behavior of coarse restriction maps

If the fine maps transform as:

$$ F_{u\to v}\mapsto G_vF_{u\to v}G_u^{-1}, $$

and transports transform as:

$$ T_{u\to a}\mapsto G'_aT_{u\to a}G_u^{-1}, \qquad T_{v\to b}\mapsto G'_bT_{v\to b}G_v^{-1}, $$

then the coarse map should transform as:

$$ F'_{a\to b}\mapsto G'_bF'_{a\to b}(G'_a)^{-1}. $$

This is the desired gauge-equivariance condition for the coarse sheaf.

8.4 Galerkin coarsening alternative

Instead of explicitly aggregating every restriction map, define a block pooling operator $\Pi$ that maps fine stalk signals to coarse stalk signals.

$$ (\Pi H)_a = \sum_v S_{va}T_{v\to a}H_v. $$

In block matrix notation, $\Pi$ contains blocks:

$$ \Pi_{a v}=S_{va}T_{v\to a}. $$

Then define the coarse sheaf Laplacian by Galerkin projection:

$$ L_{\mathcal F'}=\Pi L_{\mathcal F}\Pi^\dagger $$

or, if using the convention that $\Pi$ maps coarse-to-fine:

$$ L_{\mathcal F'}=\Pi^\top L_{\mathcal F}\Pi. $$

Choose one convention and keep it consistent throughout the implementation.

8.5 Energy preservation

The sheaf Dirichlet energy is:

$$ \mathcal E_{\mathcal F}(H) = \sum_{(u,v)\in E} \|F_{u\to v}H_u-H_v\|_F^2 = \langle H,L_{\mathcal F}H\rangle. $$

The coarse sheaf should preserve task-relevant energy:

$$ \mathcal L_{energy} = \left| \mathcal E_{\mathcal F}(H) - \mathcal E_{\mathcal F'}(H') \right|. $$

Relation-specific energy preservation is better for heterogeneous graphs:

$$ \mathcal L_{energy}^{rel} = \sum_{r\in\mathcal R} \omega_r \left| \mathcal E_{\mathcal F}^{(r)}(H) - \mathcal E_{\mathcal F'}^{(r)}(H') \right|. $$

9. Heterogeneous graph handling

Heterogeneous graphs have node types and relation types. Pooling must preserve the semantic schema.

9.1 Type-preserving pooling as default

Use type-preserving pooling for the first implementation:

$$ S_{va}=0\quad\text{unless}\quad\tau(v)=\tau'(a). $$

This ensures that author nodes pool into author supernodes, paper nodes into paper supernodes, etc.

9.2 Relation-specific coarse edges

For each relation type $r=(t_s,t_d)$, create coarse edges only between coarse nodes of types $t_s$ and $t_d$:

$$ E'_{r}\subseteq \{(a,b):\tau'(a)=t_s,\tau'(b)=t_d\}. $$

Use thresholding or top-$k$ sparsification on $A'^{(r)}_{ab}$ to avoid a dense coarse graph:

$$ (a,b)\in E'_r \quad\text{if}\quad A'^{(r)}_{ab}>\eta_r $$

or keep the top $k_r$ coarse neighbors for each coarse node and relation.

9.3 Type-specific stalk dimensions

If each type has a different stalk dimension $d_t$, use type-specific modules:

$$ H_v\in\mathbb R^{d_{\tau(v)}\times C}, \qquad H'_a\in\mathbb R^{d'_{\tau'(a)}\times C}. $$

For early implementation, using a shared $d$ for all types is acceptable. For a paper-level implementation, supporting type-specific $d_t$ is better.

9.4 Type-compositional pooling as extension

Later, allow motif-level supernodes with compositional types, such as Author-Paper or Paper-Venue. This is more expressive but requires defining new coarse stalk spaces and relation schemas. Do not implement this in the first version.

10. Heterophily-aware pooling

Heterophilous graphs violate the assumption that neighboring nodes should have similar labels or features. Pooling must not simply merge adjacent similar nodes.

10.1 Avoid homophily-biased losses

Avoid using a naive smooth assignment loss such as

$$ \sum_{(u,v)\in E}\|S_u-S_v\|^2. $$

This loss encourages connected nodes to be assigned to the same cluster and is often inappropriate for heterophily.

10.2 Cluster by structural role

In heterophily, two nodes may be similar because they play the same structural role, not because they are adjacent or feature-similar. Use role descriptors:

$$ z_v^{role} = \operatorname{concat} \left[ \deg_1(v),\dots,\deg_R(v), \bar E_{v,1},\dots,\bar E_{v,R}, \operatorname{PE}(v) \right]. $$

10.3 Preserve disagreement energy

In homophilous graphs, edge disagreement may be noise. In heterophilous graphs, edge disagreement can encode class boundaries or role complementarity. Preserve it through:

$$ \mathcal L_{disagree} = \sum_{r\in\mathcal R} \left| \sum_{e\in E_r}\|r_e\|_F^2 - \sum_{e'\in E'_r}\|r'_{e'}\|_F^2 \right|. $$

10.4 Relation-conditioned attraction and repulsion

Let $\gamma_r\in[-1,1]$ be a learned or predefined relation-specific tendency. If $\gamma_r>0$, relation $r$ encourages same-cluster assignment. If $\gamma_r<0$, relation $r$ encourages separation.

$$ \mathcal L_{rel} = \sum_{(u,v,r)\in E} \gamma_r\|S_u-S_v\|_2^2. $$

If using this loss, constrain or regularize $\gamma_r$ carefully. A negative $\gamma_r$ makes the objective nonstandard and can destabilize training. A safer formulation is:

$$ \mathcal L_{rel} = \sum_{(u,v,r)\in E} \left[ \max(0,\gamma_r)\|S_u-S_v\|_2^2 + \max(0,-\gamma_r)\max(0,m_0-\|S_u-S_v\|_2)^2 \right]. $$

11. Final invariant readout

At the final scale, convert the coarse sheaf into a graph representation $h_G$ that is invariant to node permutations and gauge transformations.

11.1 Type-wise Gram readout

For each coarse node $a$, compute:

$$ K'_a=(H'_a)^\top H'_a. $$

Then aggregate by type:

$$ g_t = \rho_t \left( \sum_{a:\tau'(a)=t} \phi_t\left(\operatorname{vec}_{sym}(K'_a)\right) \right). $$

This is permutation-invariant over coarse nodes of the same type and gauge-invariant under orthogonal gauge transformations.

11.2 Edge energy readout

Add relation-specific sheaf energy summaries:

$$ e_r = \sum_{(a,b)\in E'_r} \|F'^{(r)}_{a\to b}H'_a-H'_b\|_F^2. $$

Use a neural embedding:

$$ q_r=\psi_r(e_r,\operatorname{stats}_r(E'_r)). $$

11.3 Final graph representation

Combine type and relation summaries:

$$ h_G = \operatorname{MLP} \left( \operatorname{concat} \left[ \{g_t:t\in\mathcal T_V\}, \{q_r:r\in\mathcal R\} \right] \right). $$

Alternatively, use a small transformer over type/relation tokens:

$$ h_G = \operatorname{ReadoutTransformer} \left( [\mathrm{CLS}], \{g_t\}_{t\in\mathcal T_V}, \{q_r\}_{r\in\mathcal R} \right)_{\mathrm{CLS}}. $$

11.4 Classifier

$$ \hat y_G=\operatorname{softmax}(W h_G+b). $$

12. Training losses

The total loss for graph classification is:

$$ \mathcal L = \mathcal L_{task} + \lambda_{bal}\mathcal L_{bal} + \lambda_{ent}\mathcal L_{ent} + \lambda_{energy}\mathcal L_{energy} + \lambda_{spec}\mathcal L_{spec} + \lambda_{rel}\mathcal L_{rel}. $$

12.1 Task loss

For graph classification:

$$ \mathcal L_{task} = -\sum_{G}\sum_{c=1}^{C_y} y_{G,c}\log \hat y_{G,c}. $$

12.2 Balance loss

Prevent cluster collapse:

$$ \mathcal L_{bal} = \sum_t \left\| \frac{1}{n_t}S_t^\top\mathbf 1 - \frac{1}{m_t}\mathbf 1 \right\|_2^2. $$

12.3 Entropy loss

Encourage sharp assignments only after warm-up:

$$ \mathcal L_{ent} = -\frac{1}{n}\sum_{v,a}S_{va}\log(S_{va}+\epsilon). $$

Recommended schedule: set $\lambda_{ent}=0$ for the first 20-40% of training, then gradually increase it.

12.4 Energy preservation loss

Preserve sheaf residual energy:

$$ \mathcal L_{energy} = \sum_r \left| \mathcal E_r(H,F)-\mathcal E'_r(H',F') \right|. $$

12.5 Spectral consistency loss

If computing Laplacians, preserve low-frequency diffusion behavior:

$$ \mathcal L_{spec} = \left\| U_k^\top U_k - \widetilde U_k^\top \widetilde U_k \right\|_F^2 $$

or approximate Rayleigh quotient preservation:

$$ \mathcal L_{rayleigh} = \mathbb E_x \left[ \left( \frac{x^\top L_{\mathcal F}x}{x^\top x+\epsilon} - \frac{(\Pi x)^\top L_{\mathcal F'}(\Pi x)}{(\Pi x)^\top(\Pi x)+\epsilon} \right)^2 \right]. $$

This is optional. Start without it because it can be computationally expensive.

13. PyTorch implementation plan

13.1 Recommended implementation order

  1. Version 0: implement final invariant Gram readout only. Confirm graph classification runs.
  2. Version 1: implement type-aware assignment $S$ using invariant descriptors.
  3. Version 2: implement transported feature pooling with identity transport for debugging.
  4. Version 3: replace identity transport with sheaf-map/path-based transport.
  5. Version 4: construct coarse adjacency $A'=S^\top AS$.
  6. Version 5: construct coarse sheaf maps $F'$ or coarse Laplacian $L_{\mathcal F'}$.
  7. Version 6: stack multiple pooling layers and evaluate hierarchy.

Shared stalk dimension H: [N, d, C] Simple and fast Less flexible for heterogeneous types
Type-specific tensors H_by_type[t]: [N_t, d_t, C] Mathematically cleaner for heterogeneous graphs More complex batching and indexing
Padded type-specific H: [N, d_max, C] plus mask Compromise between simplicity and flexibility Some wasted computation

Recommended first version: shared stalk dimension $d$ for all types. After validating the method, move to type-specific stalk dimensions.

13.4 Dense versus sparse assignment

Dense $S\in\mathbb R^{n\times m}$ is convenient for small graphs. For large graphs, use top-$k$ sparse assignments.

$$ S_{va}=0\quad\text{except for top-}k\text{ clusters of node }v. $$

For TU-style graph classification datasets, dense assignment is acceptable. For OGB-scale graphs, sparse assignment is necessary.

14. Pseudocode

14.1 Invariant descriptor

def gram_descriptor(H, eps=1e-8):
    # H: [N, d, C]
    # K: [N, C, C]
    K = torch.matmul(H.transpose(-1, -2), H)
    trace = K.diagonal(dim1=-2, dim2=-1).sum(-1).clamp_min(eps)
    K_norm = K / trace[:, None, None]
    z = vectorize_symmetric(K_norm)  # [N, C*(C+1)//2]
    return z

14.2 Type-aware assignment

def type_aware_assignment(z, node_type, batch, type_mlps, prototypes, temperature):
    # z: [N, assign_dim]
    # node_type: [N]
    # batch: [N]
    # prototypes[t]: [m_t, q_dim]
    # returns a block-sparse representation of S

    rows, cols, vals = [], [], []
    coarse_offset = compute_coarse_offsets_per_graph_and_type(batch, node_type)

    for graph_id in unique(batch):
        node_idx_g = where(batch == graph_id)
        for t in unique(node_type[node_idx_g]):
            idx = node_idx_g[node_type[node_idx_g] == t]
            q = type_mlps[t](z[idx])                 # [n_t, q_dim]
            c = prototypes[t]                       # [m_t, q_dim]
            logits = q @ c.T / temperature          # [n_t, m_t]
            S_local = softmax(logits, dim=-1)       # row-stochastic

            local_cols = coarse_offset[(graph_id, t)] + arange(m_t)
            append_sparse_entries(rows, cols, vals, idx, local_cols, S_local)

    return SparseAssignment(rows, cols, vals)

14.3 Transported pooling

def transported_pool(H, assignment, transports, num_coarse, eps=1e-8):
    # H: [N, d, C]
    # assignment entries: (v_idx, a_idx, S_va)
    # transports for each nonzero assignment: T_va [d_prime, d]
    # output Hc: [M, d_prime, C]

    Hc = zeros([num_coarse, d_prime, C], device=H.device)
    Z = zeros([num_coarse], device=H.device)

    for entry_id, (v, a, s) in enumerate(assignment.entries()):
        T = transports[entry_id]          # [d_prime, d]
        Hv_to_a = T @ H[v]                # [d_prime, C]
        Hc[a] += s * Hv_to_a
        Z[a] += s

    Hc = Hc / Z.clamp_min(eps)[:, None, None]
    return Hc

14.4 Coarse adjacency

def coarse_adjacency(edge_index, edge_type, assignment, num_coarse, threshold=1e-6):
    # Computes A'_ab^r = sum_(u,v in E_r) S_ua S_vb
    # Use sparse assignment lists for scalability.

    accum = defaultdict(float)
    for e in range(edge_index.size(1)):
        u, v = edge_index[:, e]
        r = edge_type[e]
        for a, S_ua in assignment.clusters_of_node(u):
            for b, S_vb in assignment.clusters_of_node(v):
                accum[(a, b, r)] += S_ua * S_vb

    coarse_edges = []
    coarse_edge_types = []
    coarse_edge_weights = []
    for (a, b, r), w in accum.items():
        if w > threshold:
            coarse_edges.append((a, b))
            coarse_edge_types.append(r)
            coarse_edge_weights.append(w)

    return coarse_edges, coarse_edge_types, coarse_edge_weights

14.5 Final invariant readout

def final_invariant_readout(Hc, coarse_node_type, batch_coarse, type_readout_mlps):
    # Hc: [M, d, C]
    K = torch.matmul(Hc.transpose(-1, -2), Hc)       # [M, C, C]
    z = vectorize_symmetric(K)                       # [M, C*(C+1)//2]

    graph_tokens = []
    for graph_id in unique(batch_coarse):
        tokens = []
        for t in all_node_types:
            idx = where((batch_coarse == graph_id) & (coarse_node_type == t))
            if len(idx) == 0:
                token_t = zeros([hidden_dim])
            else:
                token_t = type_readout_mlps[t](z[idx]).sum(dim=0)
            tokens.append(token_t)
        graph_tokens.append(concat(tokens))

    hG = stack(graph_tokens, dim=0)
    return hG

15. Unit tests and invariance checks

These tests are essential. They should be implemented before large experiments.

15.1 Permutation test

Randomly permute nodes within each graph and verify that graph logits do not change:

$$ \frac{\|f(G)-f(PG)\|_2}{\|f(G)\|_2+\epsilon}<\delta. $$ 
def test_permutation_invariance(model, data):
    logits1 = model(data)
    data_perm = permute_nodes(data)
    logits2 = model(data_perm)
    assert relative_error(logits1, logits2) < 1e-5

15.2 Orthogonal gauge invariance of final readout

Sample random orthogonal matrices $Q_v$ and transform:

$$ H_v\leftarrow Q_vH_v, \qquad F_{u\to v}\leftarrow Q_vF_{u\to v}Q_u^\top. $$

Verify final logits are unchanged: 

def random_orthogonal(d):
    A = torch.randn(d, d)
    Q, R = torch.linalg.qr(A)
    return Q

def test_gauge_invariance(model, data):
    logits1 = model(data)
    data_gauge = apply_random_orthogonal_gauge(data)
    logits2 = model(data_gauge)
    assert relative_error(logits1, logits2) < 1e-4

15.3 Gauge equivariance of pooled stalks

If $H'_a$ is the pooled representation and $\widetilde H'_a$ is the pooled representation after gauge transformation, verify:

$$ \widetilde H'_a\approx G'_aH'_a. $$

This requires knowing or constructing the induced coarse gauge $G'_a$.

15.4 Type-mask test

Verify that assignments violating type constraints are exactly zero: 

def test_type_mask(S, node_type, coarse_type):
    for v, a, s in S.entries():
        if node_type[v] != coarse_type[a]:
            assert abs(s) == 0.0

15.5 Cluster collapse test

Monitor effective cluster usage:

$$ n^{eff}_a=\sum_v S_{va}. $$

Raise a warning if too many $n^{eff}_a$ values are near zero.

15.6 Gradient stability test

Check that loss, logits, assignment values, transports, and coarse maps remain finite: 

def test_finite_gradients(model, data):
    loss = compute_loss(model(data), data.y)
    loss.backward()
    for name, p in model.named_parameters():
        if p.grad is not None:
            assert torch.isfinite(p.grad).all(), name

16.6 Gauge invariance error metric

$$ \operatorname{Err}_{gauge} = \mathbb E_{G,\{Q_v\}} \left[ \frac{\|f(G,H,F)-f(G,\widetilde H,\widetilde F)\|_2} {\|f(G,H,F)\|_2+\epsilon} \right]. $$

This should be near numerical precision for exact orthogonal gauge-invariant final readouts.

17. Extension to node classification and link prediction

17.1 Is pooling only for graph classification?

No. Pooling is most natural for graph classification, but hierarchical pooling can also help node classification and link prediction if paired with unpooling and skip connections.

17.2 Node classification with sheaf unpooling

Use an encoder-decoder architecture:

$$ H^{(0)}\rightarrow H^{(1)}_{coarse}\rightarrow \widehat H^{(0)}. $$

Unpool from supernodes to nodes using reverse transport:

$$ \widehat H_v = \sum_a S_{va}T_{a\to v}H'_a. $$

Combine with skip connections:

$$ Z_v=\operatorname{MLP}\left([H_v^{skip},\widehat H_v]\right). $$

Then predict node labels from $Z_v$.

17.3 Link prediction

For link prediction, pooling can provide multiscale endpoint representations:

$$ z_u=\operatorname{concat}\left[H_u^{(0)},\widehat H_u^{(1)},\widehat H_u^{(2)}\right]. $$

Then use a relation-specific decoder:

$$ s(u,v,r)=\operatorname{Decoder}_r(z_u,z_v). $$

For a first paper, keep link prediction as future work unless graph classification experiments are already complete and strong.

18.2 Common implementation pitfalls

  • Pitfall: summing $H_v$ directly across nodes. Fix: transport into a common supernode stalk before aggregation.
  • Pitfall: computing assignments from flattened $H_v$. Fix: use $H_v^\top H_v$ and role descriptors.
  • Pitfall: merging incompatible node types. Fix: enforce type masks.
  • Pitfall: using homophily-biased assignment smoothing. Fix: use role descriptors and energy preservation instead.
  • Pitfall: creating dense coarse graphs that explode memory. Fix: threshold or top-$k$ sparsify $A'$.
  • Pitfall: claiming exact $GL(d)$ invariance. Fix: claim exact $O(d)$ invariance and test it.

We introduce a hierarchical sheaf pooling framework that learns type-aware soft graph coarsenings using gauge-invariant assignment scores while transporting stalk-valued signals into gauge-equivariant supernode representations. The resulting coarse sheaf preserves permutation symmetry, heterogeneous relation semantics, and multiscale sheaf disagreement energy without requiring global canonical gauge fixing.

Final recommended implementation strategy

For the first working version, implement the following in order:

  1. Sheaf encoder producing $H_v\in\mathbb R^{d\times C}$.
  2. Full normalized Gram descriptor $\bar K_v$.
  3. Type-preserving soft assignment $S$.
  4. Identity-transport pooling baseline.
  5. Coarse adjacency $A'=S^\top AS$.
  6. Final type-wise Gram readout.
  7. Permutation and orthogonal gauge tests.
  8. Replace identity transport with sheaf-map/path-based transport.
  9. Add energy preservation loss.

The first complete experimental claim should be about graph classification. Node classification and link prediction require unpooling and should be treated as extensions, not as the first target.

Appendix A. Comparison with existing graph pooling methods

This appendix is intentionally appended after the original specification. It should help coding agents and researchers understand how the proposed H2S-Pool differs from standard PyG pooling layers, MVPool, HINPool, and SHEAFPOOL. The main point is that most existing pooling layers operate on ordinary vector-valued node embeddings $h_v\in\mathbb R^C$, whereas H2S-NN produces typed sheaf-valued node embeddings $H_v\in\mathbb R^{d\times C}$ together with learned restriction maps or transport maps. Therefore, the proposed method must pool not only node features, but also the sheaf structure.

Core distinction. Existing methods usually implement one of the following operations:

  • Flat readout: $\{h_v\}_{v\in V}\mapsto h_G$.
  • Node-selection pooling: $(G,X)\mapsto (G[\mathrm{idx}],X_{\mathrm{idx}})$.
  • Soft cluster pooling: $(A,X)\mapsto (S^\top A S,S^\top X)$.

H2S-Pool should instead implement a sheaf coarsening:

$$ (G,\mathcal F,H,\tau,\rho) \longrightarrow (G',\mathcal F',H',\tau',\rho'), $$

where $G'$ is a smaller graph, $H'$ is a set of pooled supernode stalk embeddings, and $\mathcal F'$ is a coarse sheaf containing induced restriction maps or an induced sheaf Laplacian.

A.2 Why standard global pooling is insufficient

For ordinary GNNs, a graph representation can be constructed as:

$$ h_G^{\mathrm{mean}}=\frac{1}{|V|}\sum_{v\in V}h_v, \qquad h_G^{\mathrm{sum}}=\sum_{v\in V}h_v, \qquad h_G^{\mathrm{max}}=\max_{v\in V}h_v. $$

These are valid permutation-invariant readouts when all node embeddings lie in a common latent vector space $\mathbb R^C$. In H2S-NN, however, the node representation is stalk-valued:

$$ H_v\in\mathbb R^{d\times C}. $$

If each node stalk undergoes a local change of basis,

$$ H_v\mapsto G_vH_v, $$

then naïve pooling gives:

$$ \sum_v G_vH_v\neq G\sum_vH_v $$

for any single global matrix $G$ in general. This means that direct addition, averaging, max pooling, or flattening of stalks is not geometrically well-defined unless the stalks are first transported or converted into invariant descriptors. Therefore, global pooling should be used only as a lower-bound baseline.

A.3 Relation to TopKPooling and Graph U-Nets

TopKPooling and Graph U-Nets use a learnable score to select important nodes. A typical simplified scoring rule is:

$$ s_v=\frac{x_v^\top p}{\|p\|}, \qquad \mathrm{idx}=\operatorname{TopK}(s,k), $$

followed by:

$$ X'=X_{\mathrm{idx}}, \qquad A'=A_{\mathrm{idx},\mathrm{idx}}. $$

A direct sheaf adaptation would flatten each stalk:

$$ x_v=\operatorname{vec}(H_v), $$

and then apply the same top-$k$ mechanism. This is not recommended as the proposed method because the score is gauge-dependent:

$$ f(\operatorname{vec}(G_vH_v))\neq f(\operatorname{vec}(H_v)). $$

The H2S-Pool analogue should compute node scores from gauge-invariant descriptors:

$$ K_v=H_v^\top H_v, \qquad s_v=f_{\tau(v)}\left(\operatorname{vec}_{\mathrm{sym}}(K_v),r_v,e_v,p_v\right), $$

where $r_v$ is a typed structural-role descriptor, $e_v$ is a local sheaf-energy descriptor, and $p_v$ is a positional, path-level, or cell-level descriptor. This gives a TopK-like baseline that is type-aware and gauge-invariant at the scoring stage.

A.4 Relation to SAGPooling

SAGPooling improves TopKPooling by using a graph neural network to compute the selection score:

$$ s=\operatorname{GNN}(X,A). $$

The benefit is that node importance depends on graph structure, not just a single projection vector. However, if the input is a flattened sheaf stalk, the scorer remains gauge-dependent. H2S-Pool should instead use a sheaf-compatible scorer:

$$ s_v= \operatorname{SheafScore}_{\tau(v)} \left( H_v^\top H_v, \{\|F_{v\triangleleft e}H_v-F_{u\triangleleft e}H_u\|_F^2:e=(v,u)\}, \{\deg_\rho(v)\}_{\rho\in\mathcal R} \right). $$

This keeps the good idea of structure-aware scoring while replacing ordinary vector features with gauge-invariant sheaf statistics.

A.5 Relation to ASAPooling

ASAPooling is closer to substructure pooling than pure node dropping. This is useful because graph-level labels often depend on motifs or local functional units rather than isolated high-score nodes. However, ASAPooling still operates on ordinary node features and ordinary graph adjacency. It does not define a coarsened sheaf.

H2S-Pool should generalize this idea from local structural pooling to local sheaf pooling. Instead of merely constructing $(A',X')$, the layer should construct:

$$ (A',H',\mathcal F') $$

where $H'$ is obtained after transporting fine node stalks into supernode stalks, and $\mathcal F'$ describes restriction maps between pooled stalks.

A.6 Relation to MVPool

MVPool is valuable because it observes that a single node-ranking view can be biased. It ranks nodes using multiple contextual views, combines them with attention, selects top-ranked nodes, and then learns a refined graph structure after pooling. This addresses the failure mode where top-$k$ pooling produces disconnected or structurally distorted induced subgraphs.

H2S-Pool should borrow the multi-view ranking principle, but the views should be sheaf-aware:

MVPool-style view H2S-Pool replacement Reason
Feature view $\operatorname{vec}_{\mathrm{sym}}(H_v^\top H_v)$ Gauge-invariant node-stalk descriptor.
Structure view $\{\deg_\rho(v)\}_{\rho\in\mathcal R}$ and typed path participation Captures heterogeneous relation profile.
Structure-feature view Sheaf residual profile $\sum_{e\ni v}\|\delta_e\|_F^2$ Captures compatibility or disagreement under restriction maps.
Global view Multiscale sheaf energy, spectral summaries, or coarse role descriptors Captures information beyond immediate neighbors.
Structure learning Coarse sheaf construction or sheaf-aware adjacency refinement Repairs topology and preserves sheaf diffusion geometry.

The important distinction is that MVPool learns a refined graph structure, whereas H2S-Pool should learn or induce a refined coarse sheaf structure:

$$ L_{\mathcal F'}\approx \Pi^\top L_{\mathcal F}\Pi, $$

or explicitly:

$$ F'_{a\to b} = \frac{1}{Z_{ab}} \sum_{(u,v)\in E} S_{ua}S_{vb} T_{v\to b}F_{u\to v}T_{u\to a}^{\dagger}. $$

A.7 Relation to HINPool / HINPooling

HINPool is highly relevant because it explicitly treats graph classification datasets as heterogeneous information networks. Its useful design ideas are type-aware node selection, type-aware readout, and cross-layer fusion. H2S-Pool should borrow these ideas but generalize them to sheaf-valued embeddings.

HINPool-style type-aware selection can be written as:

$$ S_t^\ell=\operatorname{MLP}_t(Z_t^\ell), \qquad Z_t^{\ell'}=\operatorname{TopK}(Z_t^\ell,K_t). $$

The H2S-Pool replacement should be:

$$ q_v=\phi_{\tau(v)}\left(\operatorname{vec}_{\mathrm{sym}}(H_v^\top H_v),r_v,e_v,p_v\right), \qquad S_{va}=0\quad\text{if }\tau(v)\not\sim\tau'(a). $$

Here $\tau(v)\not\sim\tau'(a)$ means that node $v$ is not type-compatible with supernode $a$. This preserves heterogeneous semantics and prevents early collapse of distinct entity types.

HINPool-style readout fusion can also be adapted. For each coarse node type $t$, compute a type-wise invariant readout:

$$ g_t^\ell = \rho_t\left( \sum_{a:\tau'(a)=t} \phi_t\left(\operatorname{vec}_{\mathrm{sym}}((H_a^\ell)^\top H_a^\ell)\right) \right). $$

Then combine type-wise summaries and cross-layer summaries:

$$ h_G= ho_{\mathrm{CL}} \left( \{\operatorname{Fuse}_{t\in\mathcal T}(g_t^\ell):\ell=0,1,\ldots,L\} \right). $$

This preserves the practical value of HINPool's cross-layer fusion while making the graph representation gauge-invariant.

A.8 Relation to SHEAFPOOL

SHEAFPOOL is the closest conceptual baseline because it directly addresses the problem of pooling sheaf-valued node embeddings. Its typical pipeline is:

$$ S_i=H_iH_i^\top+\epsilon I_d, \qquad Z_i=S_i^{-1/2}H_i, $$
$$ R_i^*=\arg\min_{R\in O(d)}\|R^\top Z_i-A\|_F^2, \qquad \widetilde Z_i=(R_i^*)^\top Z_i, $$
$$ P_G=\sum_i\alpha_i\widetilde Z_i, \qquad g_G=\operatorname{diag}(\widehat T_G^\top\widehat T_G). $$

This is useful as a terminal gauge-aware readout. However, it is not actual hierarchical sheaf pooling because it does not output a coarse graph, pooled stalks for later sheaf convolution, or coarse restriction maps. H2S-Pool should differ from SHEAFPOOL in three ways:

  1. No global anchor as the main mechanism. Prefer invariant assignment and transport-before-pooling over global Procrustes gauge fixing.
  2. Intermediate equivariance rather than early invariance. Coarse stalks $H'_a$ should remain gauge-equivariant so that later sheaf layers can process them.
  3. True sheaf coarsening. The output should include $\mathcal F'$ or $L_{\mathcal F'}$, not only $h_G$.

A.9 How the proposed H2S-Pool should be positioned

The method should not be presented as simply replacing global_mean_pool with a more complicated readout. It should be presented as a new pooling class for sheaf neural networks:

$$ \boxed{ \text{ordinary pooling: }(G,X)\mapsto(G',X') } $$
$$ \boxed{ \text{H2S-Pool: }(G,\mathcal F,H,\tau,\rho)\mapsto(G',\mathcal F',H',\tau',\rho') } $$

The intended novelty is the simultaneous satisfaction of the following properties:

  • Permutation equivariance during hierarchical coarsening.
  • Permutation invariance at final graph prediction.
  • Gauge-invariant assignment scores using descriptors such as $H_v^\top H_v$.
  • Gauge-equivariant intermediate pooled stalks using transport-before-pooling.
  • Heterogeneous type preservation through type-compatible assignment masks.
  • Heterophily preservation through sheaf disagreement energy and role descriptors.
  • Coarse sheaf construction through induced restriction maps or Galerkin sheaf Laplacian coarsening.

A.11 Minimal ablation sequence for the paper

To make the comparison convincing, implement the following ablations in order:

  1. Naïve flatten readout: $h_G=\operatorname{global\_mean\_pool}(\operatorname{vec}(H_v))$.
  2. Gram readout: $h_G=\rho(\sum_v\phi(H_v^\top H_v))$.
  3. Type-wise Gram readout: $h_G=\rho(\bigoplus_t\sum_{v:\tau(v)=t}\phi_t(H_v^\top H_v))$.
  4. Gauge-invariant TopK: select nodes using $s_v=f_{\tau(v)}(H_v^\top H_v,r_v,e_v)$.
  5. Soft assignment without transport: $H'_a=\sum_vS_{va}H_v$; include only as a negative or diagnostic ablation.
  6. Transport-before-pooling: $H'_a=Z_a^{-1}\sum_vS_{va}T_{v\to a}H_v$.
  7. Transport plus coarse adjacency: $A'=S^\top AS$ or sparse thresholded version.
  8. Transport plus coarse sheaf maps: construct $F'_{a\to b}$ from fine maps.
  9. Energy preservation loss: add $\mathcal L_{\mathrm{energy}}$.
  10. Cross-layer type-wise invariant readout: combine all hierarchy levels.

A.12 Claims to make and claims to avoid

Safe claim Unsafe claim Reason
H2S-Pool is designed to be permutation-equivariant during coarsening and permutation-invariant at final readout. H2S-Pool is invariant at every layer. Intermediate stalks should be equivariant, not invariant, otherwise useful sheaf information may be destroyed.
Assignment scores are gauge-invariant under the stated gauge group, e.g., orthogonal gauge if using Gram descriptors. The method is exactly invariant to all $GL(d)$ transformations. Exact $GL(d)$ invariance is much harder and requires additional assumptions.
The method performs actual sheaf coarsening if it outputs $G'$, $H'$, and $\mathcal F'$. The method is actual pooling if it only outputs $h_G$. Outputting only $h_G$ is terminal readout, not hierarchical sheaf pooling.
The method is type-aware and can preserve heterogeneous semantics through assignment masks and type-wise readouts. The method automatically solves all heterogeneous graph learning problems. Type construction, node features, and relation sparsity still matter.
Sheaf-energy preservation is intended to retain heterophilous disagreement structure. The method always improves heterophily performance. Performance must be verified under controlled heterophily benchmarks and ablations.

A.13 One-paragraph explanation for README or paper draft

Unlike standard graph pooling layers such as TopKPooling, SAGPooling, ASAPooling, and global mean/sum/max readout, H2S-Pool is designed for sheaf-valued graph representations. Standard pooling assumes all node embeddings live in a shared coordinate space, whereas H2S-NN assigns each node a local stalk whose coordinates are meaningful only up to gauge transformations. H2S-Pool therefore computes type-aware assignment scores from gauge-invariant sheaf descriptors, transports node stalks into supernode stalks before aggregation, constructs a coarse sheaf with induced restriction maps or a Galerkin coarsened sheaf Laplacian, and performs a final type-wise invariant readout. Compared with MVPool, H2S-Pool replaces ordinary multi-view node ranking and graph-structure learning with sheaf-energy-aware ranking and coarse sheaf construction. Compared with HINPool, it extends type-aware heterogeneous pooling to gauge-compatible sheaf-valued representations. Compared with SHEAFPOOL, it performs actual hierarchical coarsening rather than only terminal graph readout.
