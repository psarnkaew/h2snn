Snapshot

Current Core

H2S-NN performs learned sheaf-Hodge diffusion on heterogeneous graphs. It learns typed node-to-edge maps, edge-to-face maps, node and edge states, and a node-level readout for classification.

Implemented Code-backed

Main Novelty

Meta-path instances are intended to become higher-order face-like structures that affect the edge Hodge operator through δ1, rather than only serving as semantic aggregation channels.

Research claim Needs formal cleanup

Exact Cochain Condition (Road A)

Closure edges are now first-class 1-cells inside the edge list, so they enter δ0 (and hence L0) like any data edge; CoboundaryOps.closure_L0 is deleted. δ1 spans the full boundary cycle, and edge-to-face maps are built by transport from one free per-instance map A_f, making them functorial. Consequently δ1·δ0 = 0 holds identically — measured at ~1e-7 relative (float32 roundoff) on ACM/DBLP/IMDB and AMPSS. Faces are simple paths; uniform +1 signs are asserted, not assumed.

What H2S-NN Is

One-sentence definition: H2S-NN is a heterogeneous sheaf-Hodge neural network that turns selected typed path instances into higher-order face-like structures and uses them to shape diffusion over node and edge cochains.

The model starts from a heterogeneous information network with typed nodes and typed directed edges. It embeds all nodes into a shared hidden dimension, learns sheaf restriction maps for relation-aware node-to-edge comparison, learns edge-to-face maps from ordered path instances, applies Hodge-style diffusion, and predicts labels for a target node type.

What It Is Not

  • It is not just HAN with extra meta-path attention.
  • It is not just HGT with typed relation attention.
  • It is not only a meta-path search method.
  • It should not yet be described as a fully validated automatic topology learner.

Best Reviewer-Facing Framing

Given typed schemas or a candidate schema pool, H2S-NN instantiates path instances as higher-order structures and performs learned sheaf-Hodge diffusion over the resulting heterogeneous node-edge-face incidence system.

Current Pipeline

1

Load Heterogeneous Dataset

src/data/dataset.py loads ACM, DBLP, or IMDB through PyTorch Geometric, flattens heterogeneous node and edge stores, and preserves node type and relation type metadata.

2

Build Node Features And Label-Derived Metrics

src/data/preprocessing.py pads features to a common dimension, performs training-label-only propagation, computes relation metrics, and appends those metrics to node features.

3

Create Face Groups From Schemas

In manual mode, configured meta-path templates such as PAP, PSP, APA, and MAM are enumerated or sampled into concrete path instances. In auto mode, a candidate schema pool is generated from the type graph.

4

Encode Nodes And Relations

TypeSpecificNodeEncoder maps typed node features into a shared hidden space, while relation IDs are embedded using a learnable relation embedding table.

5

Learn Node-To-Edge Sheaf Maps

NodeToEdgeSheaf produces source and target restriction maps for each edge. These maps define δ0, which measures relation-aware endpoint disagreement.

6

Learn Edge-To-Face Maps

SequenceEdgeToFaceSheaf concatenates each path's node states in order with its schema's relation embeddings and applies one MLP per distinct path length, yielding the single free per-instance map Af. The per-edge maps into the face stalk then follow by transport, and define δ1. Position is preserved structurally — every slot of the concatenation has its own parameters — and schema identity enters as input rather than as per-schema weights, since a face group fixes its relation sequence. Set model.face_encoder='lstm' to restore the superseded LSTM + attention-pool encoder; it is retained only so the sequence-encoder ablation can be run. Measured on the replacement: IMDB d=16 K=4 5.70 → 5.11 GiB, ACM d=8 K=1 6.04 → 5.10 GiB, with the chain residual unchanged at float32 roundoff. model.face_map_param='triangular' additionally gauge-fixes Af to upper triangular: the model consumes it only through AfTAf, so a full d×d output carries d(d-1)/2 directions no gradient can see. This is lossless (every PSD matrix is RTR for upper triangular R) and cuts face-encoder parameters by a further ~36% at d=16, but it does not reduce peak activation memory.

7

Run Hodge Diffusion

HodgeDiffusion iteratively updates node states with L0 and edge states with L1, where L1 combines a down term from δ0 and an up term from δ1.

8

Apply a Task-Specific Readout

NodeReadout predicts target-node labels, LinkPredictionReadout decodes shared endpoint projections of final node and incident extended-edge states, and SheafCovPool produces graph logits from single-level node and edge summaries. All three readouts transport incident edge states into each endpoint's node stalk through the transpose restriction map before aggregation. Only SheafCovPool claims gauge invariance; the node and link heads use ordinary learned projections after constructing their stalk-consistent inputs.

Pooling status. SheafCovPool is a terminal readout, not a graph hierarchy: it does not construct supernodes, a coarse sheaf, or a Galerkin operator. THS-Pool, Galerkin coarsening, spectral pooling, and related hierarchical variants are retained only as superseded historical experiments. Their recorded numerical evidence is unchanged.
Why the raw Gram matrix stays 3×3. Its order is the number of semantic stalk-valued views, not a free model width. The node stack contains final node state, initial node state, and transported incident-edge state; the edge stack contains δ0x*, δ0h(0), and final edge state. Their Gram matrix therefore contains three energies and three pairwise alignments. A 5×5 or 7×7 matrix would require adding new views and would change the readout architecture; padding, repeating, or linearly expanding the three existing views adds no new invariant information. Graph-classification tuning instead varies the post-Gram projection width model.sheafcov_feat_dim over {4, 8, 16}. This width changes capacity after the fixed semantic descriptor.
What the gauge invariance assumes. Both view stacks must consist of sections expressed in one common stalk. The edge stack (δ0x*, δ0h(0), s*) already is: all three move by that edge's Re. The node stack's third column is made so by endpoint-adjoint transport, since with F' = Re F QvT we get (F')Ts' = QvFTs. The condition is on the gauge group being orthogonal, not on the restriction maps: use_orthogonal: True yields conformal-orthogonal maps F = cQ with a learned scale, and the argument holds for arbitrary F regardless. Both endpoints contribute with a + sign — this is an incident-edge context summary, not the signed coboundary adjoint δ0Ts. The invariance is a property of the readout as a function of cochains; the network as a whole is not claimed to be gauge-equivariant, since the post-diffusion LayerNorm, coordinate-wise dropout, and the map-generating MLP do not commute with arbitrary basis changes.
Known defect — S2Pool is degenerate. Its descriptor P = XT(XXT)+X collapses to the constant identity whenever the stack has full column rank, which is the normal case (3 views, d ≥ 3): with the thin SVD X = UΣVT, P = VΣUT(UΣ2UT)+UΣVT = VVT = I3. Measured: max |P - I| = 3.6e-07, and logits differ by 1.5e-08 between unrelated batches where GramPool and SheafCovPool differ by ~2e-01. Its advertised GL(d) invariance is therefore invariance-by-constancy, which is also why an invariance test never caught it. Do not cite S2Pool as a baseline until this is fixed.

Core Operators

# Edge set is EXTENDED: real edges, then one closure 1-cell per face instance.
delta0(x)_e = F_tgt(e) x_tgt - F_src(e) x_src         # over the extended edge set
L0(x)       = delta0^T delta0 x                       # closure edges included mechanically

# Face maps by transport (functorial), for boundary v0 -> ... -> vL -> v0:
T[v0]       = A_f                                     # one free d x d map per instance
T[vi]       = T[v(i-1)] @ inv(F_src(ei)) @ F_tgt(ei)  # inv = F^T / lambda^2 (scaled-orthogonal)
F_{ei->f}   = T[v(i-1)] @ inv(F_src(ei))
F_cl_tgt    = I ; F_cl_src = holonomy ; F_{cl->f} = A_f

B(s)_f      = sum over boundary edges e of eta(e,f) * F_{e->f} s_e
delta1_w(s) = sqrt(w_f) * B(s)_f                    # exact zero remains exactly zero
L1(s)       = delta0 delta0^T s + B^T W B s         # linear and PSD in nonnegative w_f

Discovery weight during the operator ramp:
w_f(r) = (1-r) + r * a_tilde_{schema(f)} * b_f
Exact within the implemented face contract. δ1δ0 = 0 holds up to floating-point roundoff for the simple, forward-oriented, transport-composed faces and aligned closure edges built by the current materializers; this is not a guarantee for arbitrary external complexes. The lambda_co chain penalty is therefore gone. It was previously aimed at a target no non-degenerate face maps could reach: on an open path the two endpoint blocks of δ1δ0 each appear in a single term and the node-to-edge maps are invertible, so exact zero forced the face maps to zero. Fixing it required three things together: the closure 1-cell inside δ1's boundary, functorial (transport-composed) face maps, and simple-path faces. Note this supersedes the earlier claim that H2SNN_corrected_algorithm.md §2.3/§4.2 makes the path-edge-only δ1 spec-correct — that design cannot satisfy the cochain condition. Verified by tests/test_coboundary_chain.py (L=2,3,4 plus adjointness) and end-to-end on all three datasets.

AMPSS Schema Discovery (schema_conditioned_v1)

AMPSS is a two-stage method. Stage I is a non-differentiable, task-aligned probe selector that fixes a candidate pool and materialized faces under exact joint face/incidence quotas. Every trial's features, coverage, and cost come from the same deterministic post-quota prefix accepted by final materialization. The greedy selector ranks feasible additions by held-out task-loss reduction and stops when no candidate has positive task gain. Coverage and Jaccard overlap are diagnostics only. Because the probe is refit for each subset, this is a deterministic forward-selection heuristic rather than a submodular objective with an approximation guarantee.

Stage II learns one positive weight for each retained concrete path instance. Let z_f be the ordered path latent and e_s the embedding of its selected schema: 

learned weight(f) = 2 * sigmoid(g_w(concat(z_f, e_schema(f))))
operator weight(f, r) = (1-r) + r * learned weight(f),  0 <= r <= 1
training loss = task loss
Operator semantics. The instance weights affect only the upper edge-Hodge term BTWB. They do not remove the closure 1-cell from δ0, L0, the lower edge term, or the edge readout, and they never create, delete, or prune faces. The output layer of g_w is zero-initialized, so every learned weight starts at one. The post-warm-up operator ramp starts at the all-ones operator and reaches the learned weights continuously over operator_anneal_epochs. The task loss reaches g_w only through this ramp; validation, test, and standalone inference use the full operator (r=1).
No auxiliary discovery objective. AMPSS has no schema gate, sparsity penalty, incidence-mass penalty, coverage reward, partial-schema dropout, or separate discovery loss. Incidence remains a hard Stage-I budget, while coverage remains a reported property of the selected support.

This is a structural-complexity budget, not an inference-speed guarantee: Stage II does not prune operator tensors.

Candidate safety Typed-schema enumeration is streaming and raises immediately upon encountering identity or viable candidate guard+1. Candidate limits are fail-fast guards; silent order-based truncation is disabled. Values such as 128 or the next power of two are shipped engineering margins, not scientific requirements and not tuning parameters.
Reproducibility Selector and materialization seeds are separate from the training seed. Reports record candidate/selected statistics, coverage/Jaccard diagnostics, selector-unit, selector-support, final-materialization, and face-set hashes. Checkpoints bind the ordered selected identities, both support hashes, the operator schedule state, and the manifest SHA-256 before loading parameters. selector_report.json, selector_manifest.json, and its manifest hash are run artifacts. Stage-II ablations 3--5 must share these Stage-I identities and hashes. Filtering to selected graph templates does not release the per-anchor sampling quota, so it cannot change the frozen path pool.

Configurations containing obsolete gate/loss keys, checkpoints from another protocol version, and legacy tuning states are rejected with a migration error. Historical DCV code is diagnostics-only and is not an active selector strategy.

W&B campaign resume is per-run: compatible fingerprinted states resume their stored sweeps, missing run states create fresh sweeps, and incompatible existing states are preserved while numbered continuation sweeps are created. An explicit --sweep_id remains strict exact-resume mode.

A fixed multi-machine campaign can be partitioned with --run_start and --run_count while keeping --num_runs and --base_seed unchanged. For example, machines can process run indices 0--1 and 2--4 separately while sharing the same state directory.

Research Position

H2S-NN sits between heterogeneous graph learning, heterophily-aware GNNs, meta-path search, sheaf neural networks, and higher-order Hodge diffusion.

Research Line What It Solves Gap H2S-NN Targets
HAN / MAGNN style meta-path HGNNs Use expert-defined meta-paths as semantic message-passing views. They do not turn each concrete path instance into an operator-shaping higher-order cell.
HGT style transformer HGNNs Use typed node and edge attention without hand-designed meta-paths. They remain edge/message-passing models rather than Hodge models over faces.
Meta-path search methods such as LMSPS and PMMM Search useful semantic paths or meta-multigraphs. Selected schemas usually become aggregation channels, not cells in a learned Hodge operator.
HetSheaf Learns heterogeneous sheaf maps and handles heterophily through local spaces. Closest baseline, but H2S-NN aims to add path-induced higher-order structure and δ1.
HeterSEED / AHGNN / H2SGNN Recent heterophily-aware heterogeneous models with strong graph-level mechanisms. They address heterophily, but not through weighted typed path instances as Hodge faces.

Benefits

1. Operator-Level Higher-Order Modeling

Existing meta-path methods often use schemas as routes for aggregation. H2S-NN's strongest idea is to make selected path instances affect the operator that controls diffusion. This is a deeper use of meta-path information.

2. Better Inductive Bias For Heterophily

Sheaf restriction maps allow two connected nodes to disagree in raw feature space while still being compatible after relation-specific transport. This is more flexible than direct neighbor averaging.

3. Heterogeneous Type Awareness

Node types, relation types, and typed path sequences are preserved. The model does not collapse the heterogeneous graph into a single untyped adjacency matrix.

4. Instance-Level Interpretability

If discovery is validated, Stage-I task gains show which schemas entered the pool, while learned instance weights show which retained concrete paths shape diffusion.

5. Bridge Between Search And Sheaf Geometry

H2S-NN can be positioned as a unification of meta-path search and heterogeneous sheaf learning: search decides what higher-order support exists, sheaf-Hodge diffusion decides how signals move through it.

6. Strong Ablation Story

The method naturally supports ablations: remove faces, remove δ1, replace maps with identity maps, use uniform instance weights, or compare manual schemas against discovered schemas.

Limitations And Bugs

Priority Issue Why It Matters Suggested Fix
Resolved Closure edges were generated but not used anywhere in the model. The strict 2-cell/cellular-complex claim depends on closed boundaries. Closure edges are now appended to the edge list as real 1-cells with their own stalks, so they enter δ0, L0, and δ1's boundary. CoboundaryOps.closure_L0 is deleted. Their restriction maps are defined as the path holonomy (no new parameters). This supersedes the earlier reading of H2SNN_corrected_algorithm.md §2.3-§2.5, under which closure edges stayed outside δ1 — that design makes δ1δ0 = 0 unreachable.
Resolved Orientation signs were implicitly hardcoded as +1 inside δ1, with no explicit sign field. Hodge/cellular coboundary operators require signed incidence for mathematical correctness. Added an explicit face_edge_sign tensor threaded through FaceGroup/FaceMapCache/CoboundaryOps.delta1/delta1_T. Production data always yields +1, and this is now correct rather than merely convenient: all three enumerators walk forward through stored src→dst, and the closure cell is stored (last, first), i.e. oriented along the cycle. src/data/face_geometry.py::validate_face_orientation asserts this per face group, so introducing reverse traversal fails loudly instead of silently invalidating the boundary map.
Resolved The former hierarchical gate objective stacked four auxiliary terms around schema and instance gates. The extra scales obscured attribution and did not establish useful schema ranking. Removed both gates and all auxiliary terms. Stage II now reports effective per-schema instance-weight mean/std while task gradients train a single schema-conditioned weight network.
P1 Schema preselection is non-differentiable and has no approximation guarantee. The refitted held-out probe loss is not known to be monotone submodular. Frame Stage I as deterministic task-aligned candidate-pool construction under hard budgets. Compare manual, uniform-weight, schema-agnostic, and full schema-conditioned variants with a frozen Stage-I manifest.
Resolved closure_scale existed in config but was not used by the model. This made the closure-edge design incomplete and confusing. Now the scale on the closure 1-cell's restriction maps, defaulting to 1.0 (the old 1e-6 effectively switched them off). The face map absorbs a compensating 1/closure_scale, so δ1δ0 = 0 holds for any positive value; only the closure edge's L0 contribution varies (quadratically). It must stay strictly positive — use ablate_no_delta1 to remove faces and closure edges together.
P2 Maps described as orthogonal are actually scaled orthogonal. Scaled maps may be useful, but the paper should not overstate strict orthogonality. Rename claim to "scaled orthogonal restriction maps" or remove scaling for strict orthogonality.
Resolved locally The h2snn Conda environment exercises the current API with unittest. The hierarchical objective, sparse metadata, task coverage, per-graph quota, versioning, and gradients have focused regressions. Continue running the complete suite before each implementation phase; Application Control can still block PyG imports on some Windows hosts.
P2 Evaluation evidence is still narrow. ACM manual-schema results are not enough for broad claims about heterophilic heterogeneous learning. Add HetSheaf, HeterSEED, AHGNN, H2SGNN, LMSPS, and PMMM baselines where feasible.
Do not claim yet: "H2S-NN is a fully validated automatic schema-to-cell discovery model." The closure/orientation mathematical fixes are complete and dense-reference tested (see Update Log), so the "closed 2-cell" claim is now code-grounded; what remains open is breadth of experiments — baselines and evaluation beyond the ACM manual-schema results (see P2 rows above).

Validation Plan

Minimum Ablations

  • H2S-NN without faces: remove δ1 and compare with graph-only sheaf diffusion.
  • Identity maps: replace learned sheaf maps with identity matrices.
  • Diagonal or scalar maps: test cheaper parameterizations.
  • Uniform instance weights: isolate the selected Stage-I support from Stage-II weighting.
  • Schema-agnostic instance weights: test whether schema identity adds value beyond the ordered path latent.
  • Manual schemas versus auto-discovered schemas.
  • Learned upper-Hodge weights versus an all-ones upper-Hodge operator.

Minimum Baselines

  • HAN or MAGNN for manual meta-path aggregation.
  • HGT for typed attention without meta-paths.
  • HetSheaf for the closest heterogeneous sheaf baseline.
  • HeterSEED, AHGNN, or H2SGNN for recent heterophily-aware heterogeneous baselines.
  • LMSPS or PMMM for automatic meta-path/search baselines.

Reporting Checklist

  • Macro-F1 and micro-F1 across repeated seeds for HGB node classification; accuracy is optional logging only.
  • Runtime and memory usage with face counts.
  • For node and link prediction, report peak training memory for the complete-graph forward/backward step. Query or subcomplex minibatching is not part of the current primary tuning protocol and should be introduced only if profiling demonstrates that it is needed.
  • Number of schemas, number of faces, and average path length.
  • Effect of closure edges and orientation signs.
  • Stability and dispersion of effective instance weights within each schema.
  • No validation/test label use in schema scoring.
