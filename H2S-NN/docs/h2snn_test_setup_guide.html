H2SNN Local Testing Setup Guide

Follow these PowerShell steps to create a clean Conda environment, install the pinned PyTorch/PyG dependencies, verify CUDA, run unit tests, and launch a small H2SNN training run.

Do This First

Use a new environment, not base. The current base environment uses Python 3.13.9 and does not have torch or torch_geometric. This repo pins torch==2.6.* plus CUDA 12.4 PyG wheels, so a clean Python 3.12 Conda environment is the safer test target.

Open Windows PowerShell. Run every command from the repository root:

PowerShell 
cd "G:\My Drive\H2S-NN_test"

Create Environment

Create one dedicated Conda environment named h2snn. Reuse it for later tests by running only conda activate h2snn.

1. Create and activate the environment

PowerShell 
conda create -n h2snn python=3.12 -y
conda activate h2snn
python -m pip install --upgrade pip

2. Confirm you are not in base

PowerShell 
python --version
conda info --envs

Expected: Python should report 3.12.x, and the active environment marker should be next to h2snn.

Install Packages

The repository already contains the dependency file. It points pip to CUDA 12.4 PyTorch and PyTorch Geometric wheels.

PowerShell 
pip install -r requirements.txt
Why this should work on your GPU Your machine has an NVIDIA RTX 4060 Laptop GPU. The installed driver can run CUDA 12.4 PyTorch wheels even if nvidia-smi reports a newer maximum CUDA runtime.

Verify Torch And GPU

Run this exactly after installation. It checks that Python can import the graph stack and that PyTorch sees CUDA.

PowerShell 
@'
import torch
import torch_geometric
print("torch:", torch.__version__)
print("cuda available:", torch.cuda.is_available())
print("torch cuda:", torch.version.cuda)
print("gpu:", torch.cuda.get_device_name(0) if torch.cuda.is_available() else "CPU only")
'@ | python -
Good result cuda available: True and a GPU name similar to RTX 4060.
Still usable cuda available: False means CPU tests can run, but CUDA training will not.

Run Tests

Run discovery only from the tests folder. This avoids importing package directories as failed tests.

PowerShell 
python -m unittest discover -s tests -v

Expected: the data, model, and trainer smoke tests should run instead of skipping with No module named 'torch'.

Train H2SNN

Start with CPU if you only want to verify the code path. Use CUDA once the import and GPU checks pass.

CPU smoke training

PowerShell 
python scripts\train_h2snn.py --config configs\experiments\acm_h2snn.yaml --device cpu --exp_name acm_smoke_cpu

CUDA training

PowerShell 
python scripts\train_h2snn.py --config configs\experiments\acm_h2snn.yaml --device cuda --exp_name acm_h2snn_test
First dataset load can take time. PyTorch Geometric may process cached dataset files under data/ during the first run. Let it finish unless it shows a real traceback.

Success Criteria

  • python --version reports Python 3.12.x inside h2snn.
  • The verification snippet imports torch and torch_geometric.
  • torch.cuda.is_available() is True for GPU training.
  • python -m unittest discover -s tests -v runs the H2SNN tests without missing-torch skips.
  • Training creates experiments\<exp_name>\config.yaml, run.log, metrics.jsonl, and checkpoint files.
PowerShell 
Get-ChildItem experiments\acm_h2snn_test
Get-ChildItem experiments\acm_h2snn_test\checkpoints

Troubleshooting

Symptom Likely cause Fix
No module named 'torch' You are in base or install failed. Run conda activate h2snn, then rerun pip install -r requirements.txt.
conda activate fails in PowerShell Conda shell integration is not initialized. Run conda init powershell, close PowerShell, reopen it, then activate h2snn.
PyG packages fail to install Python version or wheel index does not match the repo pin. Confirm Python 3.12.x, then use the repo command pip install -r requirements.txt from the root folder.
cuda available: False CPU-only torch installed, driver issue, or GPU hidden from the environment. Run the CPU smoke command first. For GPU, reinstall from requirements.txt inside h2snn and confirm nvidia-smi works.
Tests error when using plain discovery python -m unittest discover -v may discover package directories. Use python -m unittest discover -s tests -v.
Training starts but is slow The ACM config uses epochs: 200 and the first data processing pass can be slow. Let the run continue, or make a temporary short config later if you only need a one-epoch smoke test.

Notes

This file is only a local guide. It does not install packages or modify your environment by itself. The actual setup happens when you copy the commands into PowerShell.
