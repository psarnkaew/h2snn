Heterogeneous Sheaf-Hodge Paper Evidence Plan

H2S-NN Paper Analysis Recommendations

A researcher-facing checklist for the analyses, plots, ablations, and studies that should support an H2S-NN paper. The central story is that typed path instances become higher-order Hodge cells, learned sheaf maps handle heterogeneous heterophily, and schema/instance gates make structure selection interpretable.

Created: 2026-07-05 Status: recommendations Scope: analyses and figures No invented benchmark numbers

Executive Takeaway

Paper Thesis

H2S-NN should be positioned as a heterogeneous sheaf-Hodge model where selected typed path instances are not just semantic views. They define face-like supports that shape delta1, L1, and the edge-state component of target-node prediction.

Core narrative

Reviewer Question

The paper must show why higher-order cells and sheaf maps help beyond standard HGNNs, heterogeneous sheaf baselines, and meta-path search methods. The strongest evidence will connect homophily/heterophily diagnostics to learned schema alpha and instance beta gates.

Evidence focus

Current Gap

Correctness tests support the operator implementation, but paper-level claims still need repeated seeds on ACM, DBLP, and IMDB, plus baseline comparisons and analysis plots that expose when H2S-NN succeeds or fails.

Needs experiments
Recommended paper structure: first prove the method is competitive, then explain performance through typed relation diagnostics, then show that the Hodge/sheaf components are necessary through ablations.

Literature Signals

The recent reference set points to a clear expectation: heterogeneous graph papers now need to measure the type-aware homophily or heterophily regime, not only report final accuracy. H2S-NN should therefore report both predictive performance and structure-aware explanations.

Research signal Implication for H2S-NN Paper evidence to add
Neural sheaf diffusion links heterophily and oversmoothing to graph geometry. H2S-NN should show that learned typed restrictions and Hodge diffusion avoid naive smoothing. Depth study across K; compare feature separation and performance under identity maps versus learned maps.
HetSheaf models heterogeneity with type-aware sheaf maps and reports parameter efficiency. H2S-NN needs to separate its contribution from heterogeneous sheaf learning alone. Compare against HetSheaf or an internal graph-only sheaf ablation without faces and delta1.
HDHGR, LatGRL, HGMS, H2SGNN, and CHR-style work all emphasize meta-path or cross-type homophily diagnostics. The paper should not treat ACM, DBLP, and IMDB as single homophily numbers. Per-relation, per-meta-path, and node-level homophily plots; correlate these diagnostics with schema selection and accuracy.
Meta-path search papers ask whether automatic schema selection improves over manual semantic paths. Automatic discovery should be framed as candidate-pool construction plus differentiable sheaf-Hodge refinement. Manual schemas versus auto schemas; random pool versus topology-aware pool; uniform gates versus learned gates.
Spectral heterogeneous-heterophily papers argue that different relations may require different filters. H2S-NN should show that typed path cells and gates adapt by schema rather than enforcing one global propagation pattern. Plot learned schema alpha by endpoint discrepancy, coverage, relation type, and relation homophily.

Ablation And Study Plan

Operator Ablations

  • Full H2S-NN with manual schemas and, separately, automatic schema discovery.
  • No faces: remove edge-to-face maps and delta1 contributions.
  • No L1 diffusion: keep edge states but disable the Hodge-1 update.
  • No closure correction: set closure contribution to zero while preserving path-edge faces.
  • Identity or scalar restriction maps: test whether learned sheaf maps are necessary.

Gate And Discovery Ablations

  • Learned schema alpha versus uniform schema weights.
  • Learned instance beta versus uniform face weights.
  • Topology-aware selected schema pool versus random selected schema pool.
  • Manual schema set versus automatic candidate-pool construction.
  • Partial schema propagation on versus off.

Heterophily Studies

  • Per-meta-path homophily and endpoint discrepancy for ACM, DBLP, and IMDB.
  • Single-schema performance versus meta-path homophily and cross-type informativeness.
  • Learned gate values grouped by homophilic, mixed, and heterophilic schemas.
  • Comparison with rewiring or spectral heterophily baselines where feasible.

Robustness And Sensitivity

  • Training-label sparsity sweep to stress train-label-only propagation metrics.
  • Noisy-edge and edge-drop perturbations for typed relations.
  • Schema length and selected-schema-count sweeps for automatic discovery.
  • Stalk dimension d, diffusion depth K, and closure-scale sweeps.
Instrumentation needed: current training logs report aggregate schema alpha and face weight means. For paper figures, add run-level export of selected schema names, schema stats, final alpha values, per-group beta summaries, face counts, and resource usage.

What To Avoid Claiming Yet

Do not claim broad benchmark superiority yet. The paper needs repeated-seed ACM, DBLP, and IMDB results against credible HGNN, sheaf, heterophily-aware, and search baselines before making broad performance claims.

Automatic Discovery

Frame automatic schema discovery as topology-aware candidate-pool construction followed by differentiable sheaf-Hodge refinement. Do not call the whole selection pipeline end-to-end differentiable unless the preselection step is replaced or relaxed.

Orientation

Report that current production meta-path enumeration walks stored directed relations forward, so generated face_edge_sign values are +1. Non-trivial signs are supported by the operator interface and tests, but they are not produced by the default DFS path generator.

Closed Cells

Closure edges enter the node-side correction through closure_L0, while delta1 remains path-edge-only by design. Describe this precisely to avoid implying a different boundary operator than the implementation uses.

Validation Scope

Correctness tests validate operator behavior, closure correction, orientation handling, and sparsity-gradient plumbing. They are not substitutes for repeated-seed experiments, baseline comparisons, or dataset-level robustness studies.
