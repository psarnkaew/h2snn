PyG heterogeneous dataset EDA and MLH report

Generated 2026-08-18 from torch_geometric.datasets loaders, locally stored PyG data, and the verified HeGAN source for Yelp4HeGAN.

Primary metric: metapath-based label heterophily (MLH). This report uses H2GB's MLH with mean aggregation. We enumerate every valid directed two-hop meta-path that starts and ends at the target type, form its thresholded endpoint graph, compute the fraction of endpoint pairs with different labels, and take the unweighted mean across schemas. A value close to 0 indicates homophily; a value close to 1 indicates heterophily.

AMiner provenance and task signal

The complete PyG AMiner heterogeneous graph is stored locally under data/aminer, including its processed HeteroData object. It contains paper, author, and venue nodes connected by four stored directed relation types. For author node classification, author-writes-paper-written_by-author (APA) is the only valid directed length-2 schema that returns to the author target type. Its MLH is 0.31514508; consequently, the unweighted mean across all valid author-returning schemas is also 0.31514508. This value indicates relatively homophilic label structure because it is closer to 0 than to 1.

The score uses 3,708,070 distinct APA endpoint pairs whose two authors both have labels; 1,168,580 pairs have different labels. The graph has 246,678 labeled authors across eight classes, but the downloaded data does not provide benchmark train/validation/test masks. Machine-readable calculation: mlh_ours.json.

Yelp4HeGAN provenance and task signal

The recovered HeGAN source represents five node types: business, user, service, star, and reservation. Businesses are the labeled target type. The raw triple file stores four business-centered relations and their inverses, so its 77,360 directed records correspond to 38,680 forward relations. The three business classes are sufficiently populated for node classification, but a reproducible train/validation/test split must be created because the source contains labels without split masks.

Local artifacts: dataset notes, MLH calculation, and reproduction script.

Datasets without a valid MLH score

  • DBP15K supplies entity correspondences across two knowledge graphs, not class labels for nodes. Its raw data downloaded through PyG; current Windows PyG preprocessing stops while decoding one GloVe text row, but this does not alter the task or homophily conclusion.
  • IGMCDataset Douban supplies rating labels on user–item edges. Treating an edge rating as a user or item class would change the task.
  • AmazonBook supplies user–book interactions only; it has no node feature or node-class target.
  • HM is an H&M recommendation dataset. PyG deliberately does not automate its Kaggle download; it requires customers.csv.zip, articles.csv.zip, and transactions_train.csv.zip supplied by an authorized user.
Use in the manuscript. Report homophily only for schemas whose endpoints share a defined label space. Do not report “0” for DBP15K, IGMC, AmazonBook, or HM: their label homophily is not defined under the stated formula. For IMDB, state that the displayed value uses exact multi-label-vector agreement.
Use in the manuscript. Report MLH only where endpoints share a defined label space. Do not report 0 for DBP15K, IGMC, AmazonBook, or HM: their MLH score is undefined. For IMDB, the calculation uses exact multi-label-vector equality; for OSE_GVCS, it uses the category proxy.
