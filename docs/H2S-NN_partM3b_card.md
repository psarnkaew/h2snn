## Goal
Make the eight H2GB node-classification datasets and the two large link-prediction tasks loadable through H2GB's own loaders, with every count verified, every leak audited, and the large-LP epoch loop written and tested on synthetic graphs. **Correctness of data and code only: no training run on real data, no metric reported as a result, no comparison between methods.** Reading real data to count, audit, derive splits and write negative files is a data check and is allowed (SLURM only).

### B6 — The two large LP tasks (ogbn-mag P–P, H-Pokec U–U) and the large-LP epoch loop
- **Tasks** (spec §6 LP; D7): built from the NC graphs of B2: ogbn-mag paper–paper citation, H-Pokec user–user friendship; one fixed split **by unordered pair** 81/9/10 with a recorded seed, transductive; held-out facts removed in both orientations from the message graph and from every sampled path; fixed validation file listing only the target relation (F13). Feature rule F17 and a leak audit F18 per task before any number: attribute inventory of the endpoint types (is any paper or user feature computed from the target relation, or an attribute of the other end?), written as evidence; a feature that violates F17 is a stop for the task, listed with its columns.
- **One relation per node pair** (decisions log, Part MB review): count, on both tasks, node pairs that carry more than one fact of the target relation (multi-edges, reverse copies, several relation types between the same pair). `remove_held_out_facts` removes every fact of a held-out pair, so a positive's duplicate must not stay in the message graph. Report the counts; if any pair carries more than one fact **and** the removal does not already cover it, stop the unit and list options.
- **Negatives:** HGB protocol (spec §6): 2-hop test negatives (`get_test_neigh`, seed 1) and random test negatives, validation negatives (`get_valid_neg`), written once per task by a job with `src/data/hgb_lp_negatives.py`; report heads without 2-hop candidates (count, share). Memory: state the peak; the 2-hop adjacency product must not be built densely.
- **Epoch loop** (MB4, D-MB3, D-MB4): per step 8,192 positive links and as many negatives (1:1); every endpoint of the step is a target with its own scope; a node in several links of the step is computed once; score = decoder(`x*_u`, `x*_v`) as in full batch (`dot`, DistMult); BCE; 40 epochs, patience 40 counted in epochs, evaluation every epoch on all validation links with scopes computed once per evaluation and shared by the links; the log-weight stop per forward; evaluation warm start off (MB6). Training positives stay in the message graph; held-out facts are removed before any draw.
**Tests (synthetic graph with a known held-out set):** (i) a node appearing in several links of a step is computed once and its score equals the score computed on its own, float64 `atol 1e-10` fixed in advance, with a negative control (a batch whose composition is changed must not change another node's score); (ii) `assert_no_held_out_facts` holds for every scope of the step in both orientations; (iii) epoch and patience counting (a scripted metric sequence stops at the expected epoch); (iv) the split is by unordered pair (a pair and its reverse always fall in the same part); (v) the decoder `concat_mlp` stays refused. **Mutations:** the loop scores each link's endpoints with scopes that include the other endpoint's facts → test (i) fails; the held-out removal restricted to one orientation → test (ii) fails.
Registry: the LP cells lose `DATA_PENDING_REASON` only with the task files and negatives in place.
