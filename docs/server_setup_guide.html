3. เชื่อม GitHub บน server

login01 สร้าง key ของ server (เก็บใน home เท่านั้น)

ssh-keygen -t ed25519 -C "h2snn-lab-server" -f ~/.ssh/id_ed25519_github
cat ~/.ssh/id_ed25519_github.pub

GitHub (เว็บ) → Settings → SSH and GPG keys → New SSH key → วางบรรทัด ssh-ed25519 ...

login01 สร้าง ~/.ssh/config (ถ้ายังไม่มีไฟล์ คำสั่งนี้จะสร้างให้)

cat >> ~/.ssh/config <<'EOF'

Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519_github
  IdentitiesOnly yes
  ProxyCommand none
EOF
chmod 700 ~/.ssh
chmod 600 ~/.ssh/config ~/.ssh/id_ed25519_github
chmod 644 ~/.ssh/id_ed25519_github.pub
ssh -T git@github.com

ต้องขึ้น Hi psarnkaew! You've successfully authenticated… (ครั้งแรกตอบ yes)

บรรทัดทำไมต้องมี
HostName ssh.github.com + Port 443เผื่อแล็บบล็อกพอร์ต 22 ขาออก
IdentitiesOnly yesบังคับให้ใช้ key ตัวนี้เท่านั้นกับ GitHub
ProxyCommand noneระบบตั้ง ssh ให้เรียก sss_ssh_knownhostsproxy ซึ่งพังบน compute node (Broken pipe) บรรทัดนี้ทำให้ทุก node ต่อ GitHub ได้

login01 ตั้งชื่อผู้ commit ให้ตรงกับเครื่องเรา

git config --global user.name "psarnkaew"
git config --global user.email "<อีเมลเดียวกับที่ใช้ commit บนเครื่องเรา>"

6. ใช้ srun / sbatch ให้ถูก

เรื่องทำอย่างไรเพราะอะไร
ทุก shell หรือ job ใหม่ต้องเปิด env เอง. ~/miniforge3/etc/profile.d/conda.sh แล้ว conda activate h2snnsrun --pty bash เปิด shell ใหม่ ส่วน sbatch ไม่อ่าน ~/.bashrc
ห้ามใช้ conda สองตัวปนกันห้ามมี . /opt/conda/... ใน shell หรือ script เดียวกันจะสลับไปใช้ conda ของ server ที่สร้าง env ไม่ได้
ระบุทรัพยากรทุกครั้ง--mem, --time (≤ 72 ชม.), --gres=gpu:<ชนิด>:1, --cpus-per-taskคู่มือบังคับ งานเกิน 72 ชม. ต้องมี checkpoint
ห้ามรันใน $HOMEใน script ให้ cd /mnt/data/peeradon/h2snn/H2S-NNคู่มือห้าม และ home มีโควตา 50 GB
ห้าม srun ซ้อนถ้า prompt เป็นชื่อ node แล้ว (เช่น g2tn01) แปลว่าอยู่บน compute node แล้ว อย่าสั่ง srun อีกsrun ที่ซ้อนจะค้างด้วย step creation temporarily disabled
วางคำสั่งทีละบรรทัดเมื่อมี srun --pty หรือ exitอย่าวางทั้งก้อนบรรทัดที่ตามหลังจะไปรันผิดเครื่อง
งาน interactive ยาวเปิด tmux บน login node ก่อน แล้วค่อย srun --pty bashเน็ตหลุดแล้ว job ไม่ตาย
โควตา homepip install --no-cache-dir, conda clean --all, du -sh ~env ที่มี torch ใช้ราว 6–8 GB

ตัวอย่าง sbatch

#!/bin/bash
#SBATCH --job-name=h2snn-tests
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=8
#SBATCH --mem=32G
#SBATCH --time=4:00:00
#SBATCH --output=/mnt/data/peeradon/h2snn/H2S-NN/logs/slurm-%j.out
. ~/miniforge3/etc/profile.d/conda.sh
conda activate h2snn
cd /mnt/data/peeradon/h2snn/H2S-NN
python -m unittest discover -s tests

สร้าง logs/ ก่อนส่ง (mkdir -p .../H2S-NN/logs) · ส่ง: sbatch file.sbatch · ดู: squeue -u $USER · ยกเลิก: scancel <JOBID> · ดูทรัพยากรของ node: sinfo

7. Claude Code บน server

  • Extension ใน VS Code: ในหน้าต่างที่ต่อ SSH อยู่ ให้ติดตั้ง Claude Code แบบ "Install in SSH: lab" extension มี CLI ของตัวเองติดมา ใช้ได้ทันที ครั้งแรกจะให้ login ด้วยบัญชี Claude
  • Native CLI (ไม่บังคับ): ลงตาม Advanced setup ได้คำสั่ง claude ใน terminal ซึ่งใช้ใน tmux ได้ งานยาวจึงไม่หยุดตอนหน้าต่าง VS Code หลุด ลงคู่กับ extension ได้ ใช้การตั้งค่า ~/.claude/ ชุดเดียวกัน
  • Claude Code ทำงานบน login node: ให้ใช้ทำงาน git และแก้ไฟล์ ส่วน test หรือการเทรนต้องส่งผ่าน srun/sbatch เท่านั้น
  • เช็คว่าเข้าถึง API ได้: curl -sI https://api.anthropic.com | head -1 ขึ้น HTTP/2 404 แปลว่าต่อได้

9. ปัญหาที่เจอและวิธีแก้

อาการสาเหตุแก้
PermissionError: ... /mnt/data/cache/cache/*.info.json ตอน conda create/opt/conda/.condarc: pkgs_dirs: #!final → /mnt/data/cache ซึ่งไฟล์เป็นของ user อื่นใช้ Miniforge ใน home (หัวข้อ 5) หรือขอ admin แก้สิทธิ์ของ /mnt/data/cache
CONDA_PKGS_DIRS หรือ ~/.condarc ไม่มีผล (package cache : /mnt/data/cache)ค่าถูกล็อกด้วย #!finalเหมือนข้างบน
srun: Job … step creation temporarily disabledสั่ง srun ซ้อนตอนอยู่บน compute node อยู่แล้วกด Ctrl+C, exit กลับ login node, squeue -u $USER, แล้วขอ node ใหม่ครั้งเดียว
SSLError ... UNEXPECTED_EOF ที่ data.dgl.aiserver ต่อเว็บของ DGL ไม่ได้ข้าม DGL ไปก่อน แล้วดาวน์โหลด wheel บนเครื่องเรา + scp
pip install -r requirements.txt ได้เวอร์ชันใหม่กว่าเครื่องเรา (เช่น numpy 2.5.4)ไฟล์ requirements ไม่ได้ล็อกเวอร์ชัน และ DGL ที่หาไม่เจอจะทำให้ล้มทั้งชุดใช้คำสั่งที่ล็อกเวอร์ชันในหัวข้อ 5 (ต่อไปจะมี requirements/linux-lock.txt)
banner exchange: Connection to UNKNOWN port 65535: Broken pipe ตอน git fetchsss_ssh_knownhostsproxy ของระบบเพิ่ม ProxyCommand none ใต้ Host github.com
ModuleNotFoundError: No module named 'torch' ใน env ใหม่env เพิ่งสร้าง ยังไม่มีแพ็กเกจรันคำสั่ง pip ในหัวข้อ 5 ใน env นั้น
RuntimeError: No CUDA GPUs are availableรันบน login node หรือขอ job โดยไม่มี --gres=gpu:1ขอ node พร้อม GPU
conda env list ไม่เห็น envenv นั้นเป็น venv ไม่ใช่ conda (ทางเก่าที่เลิกใช้แล้ว) หรือ activate ผิดตัว. ~/miniforge3/etc/profile.d/conda.sh แล้ว conda env list
VS Code ต่อไม่ติด: Resource temporarily unavailableprocess ค้างบน login nodeแจ้ง admin ให้ลบ process (คู่มือแล็บ)
Disk quota exceededhome เกิน 50 GBconda clean --all, ลบ cache ของ pip และ env ที่ไม่ใช้

ข้อความถึง admin (ถ้าต้องการให้ /opt/conda ใช้ได้):

conda create ล้มด้วย PermissionError: [Errno 13] Permission denied: '/mnt/data/cache/cache/497deca9.info.json'
เพราะ /opt/conda/.condarc ตั้ง pkgs_dirs: #!final ไว้ที่ /mnt/data/cache แต่ไฟล์ cache ในนั้นเป็นของ user อื่น
ช่วยตั้งสิทธิ์ให้ทุกคนในกลุ่มเขียนได้ หรือให้ user ใช้ cache ของตัวเองได้ไหมครับ

10. ย้อนกลับ / ลบทิ้ง
