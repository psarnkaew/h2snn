## 0. Rules of this document
1. Every component of the method answers a requirement in §2. A component without a requirement is removed.
2. Every requirement has a stated reason (the hypothesis, a theorem, or a data/protocol fact). No requirement exists because a variant scored well.
3. Every claim in §5 is fixed before the protocol in §6 runs, with the comparison that tests it and the result that falsifies it, and with what the paper says if it is falsified.
4. Results never change the method within a protocol run. A design change requires a new version of this document, written and committed before new runs.
5. Exploratory runs (e.g. the D11 screen of 2026-11-07) are recorded as exploratory and are not used to choose between designs.
6. A known-answer task, oracle or gate is pre-registered with (a) **reachability**: the parameter change the expected result needs and the change the run's optimizer and schedule can make (for one scalar under Adam, about Σ_t lr_t); an unreachable expectation is redesigned before running; and (b) an **information-route audit**: every route by which the label can reach a target within the receptive field (own features, facts, cells, `K` applications of `A`), per arm, including memorisation routes (unique per-node features against the number of training targets). (1.6; four synthetic misses in Parts H–I came from skipping this.)

## 1. Problem setting

**Data.** A heterogeneous graph `G = (V, E, φ, ψ)` with node types `φ : V → T_V`, relation types `ψ : E → T_R`, and per-type node attributes of different widths (featureless types get a learned vector per node). Benchmarks store each fact twice when a reverse relation exists; the method works on **facts**: `ρ(r) = r′` iff `E(r′)` is exactly the reversal of `E(r)`, and `(u, r, v) ≡ (v, ρ(r), u)` (D7).

**Tasks.** Main: node classification of a target type. Secondary: link prediction on heterogeneous graphs (§6). Appendix: graph classification, reported only as evidence that the model covers the task (generalizability); it carries no heterophily claim, and its "types" are atom and bond labels ("typed-by-label"), stated as such (1.5). No truly heterogeneous graph-classification benchmark is available; this is stated as a limitation (1.14).
**Dataset rule (1.14).** A dataset is used only if it has node attributes or target-node class labels (or both). LastFM (link prediction) has neither and is kept as the one stated exception; its heterophily statistics are "–".

**Thesis (hypothesis H).** On heterogeneous graphs, and especially under heterophily, label-relevant information is carried by **typed path instances** — their intermediate nodes and the order of their relations — and is lost when an instance is collapsed to a relation between its endpoints.

H is falsifiable: if it is false, a model that uses only endpoint relations of the same instances matches a model that uses the instances (claim C2).

**Heterophily (fixed in 1.5; closes `OPEN-1`).** Two measures, each exactly as defined and implemented by its source; never changed after.
- **ℋ² index** (H2GB, Lin et al., arXiv 2407.10916): `ℋ²(G) = mean_{P ∈ M₂} H_adj(G_P)`, where `M₂` is the set of length-2 meta-paths from the target type to the target type, `G_P` the meta-path-induced graph on target nodes, and `H_adj` adjusted heterophily (one minus the adjusted homophily of Platonov et al. 2023, which corrects for class imbalance). Near 0: homophilic; near or above 1: heterophilic.
- **MLH** (meta-path-based label homophily, Hetero²Net, Li et al., arXiv 2310.11664; used in heterophily form by H2GB): `Agg_{P ∈ M₂} H_edge(G_P)`. The aggregation, de-duplication and self-loop conventions are those of the reference code (recorded in the J0 report).
- **Primary measure for C6: ℋ²** (it is corrected for class imbalance; MLH can look homophilic under imbalance, e.g. IEEE-CIS-G: MLH 0.135, ℋ² 0.985 in H2GB Table 2). MLH is reported next to it.
- **Where reported.** Every dataset of every task whose nodes carry labels. Every value is computed by us with the reference code (1.15, author: no published or earlier value is reused, and no tolerance gate; a value is reported as "computed with <code> at <commit>"); graphs of H2GB size are computed on the server. For link prediction additionally the task-level `H_edge` of the target relation where both endpoint types carry labels (Freebase book–book, with the same fill convention and the labeled-only diagnostic; PubMed disease–disease is not measurable because its labels are unavailable, 1.8). Without node labels the label-based measures are "not measurable" (LastFM, PubMed), with the reason. Graph classification reports the 1-hop `H_edge` on the original bonds with label = atom type (the label-homophily formula of Hetero²Net without a meta-path), marked "1-hop, label = atom type, not the graph class"; MLH over meta-paths would be 1 by construction there (1.14).
- **Multilabel (IMDB) (1.8).** HGB, SeHGNN and HetSheaf all treat IMDB's labels as five independent binary genres (a 0/1 vector per movie). The heterophily measures follow that partition: for each genre g, `H_adj` and `H_edge` are computed with the reference function on the binary label `1(g ∈ Y_v)`, and IMDB's ℋ² and MLH are the means over the five genres (and over `M₂`). Per-genre values are reported. Hetero²Net's exact-match rule (`1(Y_u = Y_v)`, which gives its published 0.24) is kept only as the reproduction check; Zhao et al.'s Jaccard label homophily (arXiv 2304.10398, Definition 1) is reported in the appendix for comparability.
- **Unlabeled target nodes (1.8; author decision: follow the reference code).** Target-type nodes without a label (Freebase: 32,448 of 40,402 books; IMDB: 359 of 4,932 movies) receive a uniformly random class exactly as H2GB's `calcHomophily` does (`H2GB/calcHomophily.py:110-113`, commit `d3b49db`), so the values are comparable with H2GB Table 2 (which uses the same code). For IMDB the fill acts on each binary genre label. The fill seed is fixed and recorded, and the spread over 5 fill seeds is reported. Because the fill dominates Freebase (80 % random labels; ℋ² ≈ 0.999), the labeled-only value (pairs whose two endpoints are labelled; Freebase ≈ 0.89) is reported beside it as a diagnostic, never as the primary value. Node types without labels play no role: `G_P` is built on target nodes only.
- **Meta-path set and graph (1.14, replaces 1.8).** `M₂` is Hetero²Net's predefined list where it has one (DBLP: APA; ACM: PAP, PSP, PTP; IMDB: MDM, MAM, MKM; ogbn-mag: PFP, PAP; Hetero²Net Appendix B.1). Otherwise `M₂` is the output of Hetero²Net's `get_metapaths` (`vendor/Hetero2Net/hetero2net/homophily.py:51-63`): length-2 meta-paths that start and end at the target type and skip relations whose two endpoint types are equal (so e.g. paper–cite–paper–cite–paper is not counted). mag-year (same graph as ogbn-mag, not in Hetero²Net) therefore gets its own set by this rule; different values on the same graph are accepted (author, 2026-11-11). MLH and MDE use this `M₂` with Hetero²Net's code. **ℋ² (1.15, author)** uses H2GB's code with H2GB's own meta-path rule (`calcHomophily.extract_metapath`: every length-2 type sequence from the target type back to it, same-type relations included), so MLH/MDE and ℋ² of one dataset may rest on different meta-path sets; this is stated in the caption. The graph is symmetrised as the loaders build it (Freebase needs it). Self-pairs follow the reference code.
- **Attribute heterophily: MDE (1.14).** Metapath-based Dirichlet Energy of Hetero²Net (Eq. 3–4; code `homophily.py:4-14`): `MDE = mean_{P∈M₂} ¼ mean_{(u,v)∈G_P} ‖x_u/√|N_u| − x_v/√|N_v|‖²`, on raw features of the target type, same `M₂` as MLH. Reported for every dataset whose target type has features; "–" otherwise (Freebase, LastFM, graph classification, whose features are constant). Link prediction: computed on the task's files after the F17 feature rule (author decision D1), per endpoint type that keeps features, on the training graph; a type whose features are removed is "–". MDE depends on the feature scale and is a descriptor of each dataset, not a cross-dataset heterophily level; ℋ² remains the stratification variable of C6.

## 2. Requirements

| ID | Requirement | Reason |
|---|---|---|
| R1 | Path-instance information reaches **every** node of the instance, including intermediate nodes, during propagation, and **not** through an endpoint-to-endpoint shortcut | H; R2 W3 and the meta-review. Lemma A′: Hodge dynamics on the 2-complex cannot carry 2-cell information to nodes, so the energy couples faces to their nodes and facts directly (Thm 8); there is no closure edge (incidence poset, Thm 1; 1.13) |
| R2 | Each instance couples its nodes and facts with transports **forced by its observed facts** (order-dependent; no instance-specific orientation); the instance has a **state** of its own and a **strength** that depends on its intermediate nodes and relation sequence (R12) | H. Forced transport is what makes the instance a cell of the graph's own sheaf (Thm 1) and keeps the graph's global sections (Thm 3); R2 S1 praises exactly this construction |
| R3 | Adding path instances must not contradict the graph's own structure (no constraint that forces consistent states to zero) | Instances are additional evidence about the same graph, not new constraints on it (Thm 3) |
| R5 | Propagation has a **unique, well-defined output for all values of the learned parameters** | Learned maps and weights make the operator data-dependent; the output must not depend on luck in training or on an unrolling depth (Thm 5) |
| R6 | Each fact is represented once; no held-out fact (either orientation) is visible during training | Data faithfulness; leak-free evaluation |
| R7 | Memory and time linear in facts and path incidences; no per-incidence `d × d` tensors; memory independent of solver depth; a mini-batch applies the same model (same rule, same parameters) to each target's scope, a lower set of the incidence poset whose degrees, context and normalisation are its own (1.17) | Target datasets (H2GB) have tens of millions of edges; v1's 9.3 GB on ACM came from `d × d` maps per directed edge (code of commit 0172044), not from cells |
| R8 | Path instances are drawn from a stated distribution with an unbiased estimator of a stated target operator; **no schema list, label or trained model enters the target**; the number of candidate schemas does not enter the cost | Reproducibility; schema lists may be absent or incomplete (1.3) |
| R9′ | Propagation gives, per stalk coordinate, a low-pass response `1/(1+τλ)` and, at the head, the complementary high-pass `τλ/(1+τλ)` | Heterophily: part of the label signal lies in transported disagreement. | R10 | The geometry (restriction maps, fact weights, path weights) depends on each node's **typed neighbourhood**, and is computed **once** | One sheaf per forward pass keeps R5 and R7 and makes every theorem of §4 apply |
| R11 | A node's own features reach the nonlinear head separately from propagated ones | Heterophily: ego/neighbour separation (Zhu et al. 2020); also what provides R9′'s high-pass |
| R12 | Whether, and how strongly, an instance informs its nodes is a learned, non-linear function of the **whole instance** (all its nodes' `h₀` and its relation sequence), shared by all nodes and schemas, **with no structural ceiling**: a single instance can dominate a node's neighbourhood if its weight is large enough | H operationalised. ## 3. Method — each component from its requirement

```
h₀  = TypeEncoder(x)                                            # per-type linear encoder + type embedding
c   = RelCtx(h₀)                                                # per (relation, role): mean of neighbours' h₀
cells f, m_f  ←  WISP sampler (§3.2)                            # schema-free walks from target nodes; 1 walk = 1 cell
F_{v◁e}, a_e, β_f = w_f m_f  ←  computed once from [h₀, c] / h₀  # one sheaf: orthogonal factorized maps, fact weights, cell weights
T_{v,f}, R_{e,f}  ←  forced by F along each cell (Thm 1)        # matrix-free; no cell parameters
L   = ∇²E,  E(Y) = ½ Σ_e a_e Σ_{v∈e} ‖F_{v◁e} x_v − s_e‖²                                        (E, node–fact)
             + ½ Σ_f β_f [ Σ_{e∈f} ‖R_{e,f} s_e − z_f‖² + Σ_{v∈f} ‖T_{v,f} x_v − z_f‖² ]          (fact–cell, node–cell)
D   = diag(D_v, D_e, D_f),  D_v = Σ_{e∋v} a_e + Σ_{f∋v} β_f,  D_e = 2a_e + Σ_{f∋e} β_f,  D_f = β_f(2ℓ_f+1)
L̂   = D^{-1/2} L D^{-1/2}
Y*  = argmin_Y ½‖x − h₀‖² + τ/2 YᵀL̂Y   ⇔   (PᵀP + τL̂) Y* = Pᵀh₀      # PCG; implicit backward; τ = e^θ learned
y   = head([x*, h₀])                                            # MLP
```

**Task readouts and losses (1.15).** NC: `[x*, h₀]` → Linear(2d, 128) → GELU → Dropout → Linear; cross-entropy (IMDB: per-genre BCE, genre predicted iff logit > 0). LP: per endpoint Linear(2d, d) → GELU, then the decoder (dot or DistMult; `concat_mlp` open); BCE with 1:1 training negatives. GC: `[x*, h₀]` of every node → pooling (mean, max, add, or attention as HetSheaf's `AttentionPooling`: Linear → Tanh → Linear, 2 heads averaged) → **one Linear layer**; no BatchNorm, no MLP (as HetSheaf's `GraphClassifier` and every GC baseline); cross-entropy. **Not part of the method** (removed or comparison-only): gates (`G`, `B`), the Chebyshev filter bank and `K`, `η`, `γ`, edge cochains of the **Hodge** kind (`L₁`) and the closure edge as a computed 1-cell, AMPSS, SheafCovPool, multi-block structure, per-edge attention, fixed literature schema lists (comparison row), schema selection. Designated extensions (not in this version): multiple `τ` (band-pass, L13), `τ` per node type, the skew-symmetric directional term (L1′), per-node participation `κ`.

### 3.1 Where direction, heterogeneity and heterophily live
- **Direction** is geometry, not strength: separate frames per role (`R_{ψ,src} ≠ R_{ψ,tgt}`), a role code in the reflection input, adjoint transport on backward hops. The energy is symmetric in strength (`a_e` shared by both endpoints); "listen without broadcasting" is not expressible (L1′). This is the trade of MagNet/DSNN-type Hermitian models: direction in the rotation, symmetric magnitude, real spectrum and an energy. Ablation: `direction_blind_maps`.
- **Heterogeneity** lives in the sheaf: type encoder, relation-and-role frames, relational context `c`, path cells (a schema's transport is the ordered product of its relation frames, so P–A–P and P–S–P have different holonomies), and the per-instance weight `β_f`.
- **Heterophily** is handled at three levels, each with a proof of what it can express: rotations in the maps (nodes of different classes agree after transport without being equal, Thm 4), instance-conditioned trust in cells (`β_f`, R12), and ego separation plus the complementary high-pass at the head (R11, Prop. 11). Nothing is claimed about band-pass responses (L13).

### 3.2 WISP — the replacement of AMPSS (decided 1.3)
**Name.** WISP = **W**alk-sampled, **I**nstance-weighted **S**heaf **P**aths. Code/config namespace `wisp`. It answers three questions separately: (a) which instances *can* enter, (b) which are computed, (c) how strongly each counts. "Meta-path selection" is (c) aggregated by schema and is reported, not performed.

**Example (ACM, target type paper).** From paper P1 the sampler draws a length ℓ ∈ {2, …, ℓ_max} uniformly, then at each hop picks uniformly among the (relation, direction) actions that still have an unvisited neighbour (e.g. author, subject, term, cite, cited-by), then a uniform unvisited neighbour: P1 –author→ A7 –paper→ P9 is one walk and one cell (schema PAP is a *label of the cell*, not an input list). The cell's weight is `exp(g(ξ))` where ξ sees P1, A7, P9 and the two relations; a cell through a prolific, off-topic author can receive a low weight while another PAP cell receives a high one.

**(a) Candidates — walk-first, schema-free.** Anchors: every node of the target type (node classification); every node of the two endpoint types of the target relation, on the message graph with held-out facts removed in both orientations (link prediction); every node of the graph (graph classification). WISP is the path source of every task (1.15); the length-2 schema-free walks previously used by the LP and GC trainers are not part of the method. A walk is self-avoiding (an action is available only if it has an unvisited neighbour; a dead end before the drawn length discards the walk, i.e. the target is a sub-probability on simple walks).
**(b) Target measure and estimator.**
```
p(ω) = 1/(ℓ_max − 1) · Π_{j=1..ℓ} [ 1/|A_j(v_{j−1}, S_{j−1})| · 1/|N_j^unvisited| ]        # uniform length, uniform action, uniform neighbour
L_P^target = Σ_{a ∈ anchors} Σ_ω p(ω | a) · L_{f(ω)}
walk drawn from  ½ p + ½ q  (walk-level coin);   m_f = Σ_{walks → f} (1/r) · p(ω) / (½p(ω) + ½q(ω))  ≤ 2/r per walk
q(ω) = q_len(ℓ) · Π_j [ q_act(type(v_{j−1}), a_j) renormalised over A_j ] · 1/|N_j^unvisited|
```
`q` (optional, `proposal: adaptive`) is set at the start of each epoch from the previous epoch's share of path mass `w_f m_f` per length and per (node type, action); no gradient flows through it; it changes variance only, never the target. Evaluation uses one fixed draw from `p` alone (base seed), so every comparison arm sees identical evaluation cells. Identity and merge are D8's (canonical fact sequence, weights summed). One walk is one cell: prefixes are not sampled separately (removes nested double counting; PAP inside PAPAP enters as pair terms, Prop. K). Knobs: `ℓ_max` sets the **support** and `r` (walks per anchor in one draw) the **precision**; both are hyperparameters in the search space (1.15, author: `ℓ_max` ∈ {2, 3, 4, 5}, `r` ∈ {8, 16, 32, 64}; supersedes E11, E14 and the pre-registered `ℓ_max`). The ½ is fixed (it gives the bound 2), never tuned.
**(c) Weights.** `w_f = exp(g(ξ_f))`; `g` = one projection per length over `[h₀(v_0), …, h₀(v_ℓ), rel_emb(a_1), …, rel_emb(a_ℓ)]` (1.4: `h₀`, not `geom = [h₀, c]`), GELU, linear output with bias `b` (scalar optimizer group), `b` initialised to `log(path_weight_init)`. Length-neutral at initialisation by construction (uniform length target, constant `g`).
**Read-outs (evaluation only, never feed back into training):** `I_π` (share of `Σ w_f m_f` by full walk schema), `I_σ` (share of pair weight by sub-path schema, exact by Prop. K), per-node `I_{v,σ}`, `ΔL_σ` (validation-loss change when σ's pair terms are removed, `T` evaluation draws), overlap ratio (share of pair weight whose sub-path also occurs in another sampled cell), Kendall τ of schema rankings across seeds. Bootstrap CIs over seeds and a permutation null.
**What changed from AMPSS (v1):** Stage I (schema scoring from counts, endpoint diversity and type-blind label propagation; ≥ 18 settings; hard error past 128 candidates) is removed; Stage II (instance weights) is kept and becomes the whole mechanism; the DFS-with-quota sampler (no stated distribution) is replaced by the WISP target measure; selection becomes read-out.

**Known limits (stated in the paper):**
- **L1′ Influence is symmetric in strength.** `a_e` and `β_f` act equally on both endpoints / all members; direction enters only through the maps. "Listen without broadcasting" is not expressible. This is the price of an energy and a unique solution for all parameters (Prop. 4 of 1.10, detailed balance). Designated extension: skew-symmetric term, which gives up the energy.
- **L2** Geometry does not depend on propagated states (one sheaf). **L3** Propagation is linear; nonlinearity is in the head. **L4** Orthogonal maps; **L4′** `k = 2` reflections do not cover O(d); Thm 4 needs only a map taking one vector to another per incidence, which `k = 2` provides (a plane rotation), so the theorem holds for the production family.
- **L5** On the eight H2GB NC datasets and the two large LP tasks each target is predicted by the same model, with the same parameters, on its own scope (its facts and the cells sampled from it); degrees, relational context and normalisation are the scope's, so a node with many facts outside the scope weighs more there than in the whole graph, and information that no fact of the target and no sampled cell carries is not seen. Training and evaluation use the same rule. The gap to full batch is reported on ACM and DBLP (C5) (1.17).
- **L6** No instance-specific orientation (forced transport). **L7** Simple paths only. **L8** Unseen relations. **L9** Support `ℓ_max`. **L10** Proposal per node type.
- **L11** (Part K) Sparse decisive evidence needs a large weight range; with the node–cell term the range is structurally available (Prop. 7′ ii); whether `g` learns it is tested (S3).
- **L12** The eliminated fact state is exact only for facts on ≤ 1 cell; shared facts keep states (cost depends on `|E_shared|`, to be measured).
- **L13** No band-pass response in this version (R9′); multiple `τ` is the designated extension.
- **L14** Fact states carry no input information (HGB has no edge features); their content is the agreement of the cells sharing a fact. Whether this matters is C11; the paper does not claim it does.
- **L15** The node-level solve is a PPR resolvent (APPNP form); the contribution is the operator `Ŝ`, not the solver.
