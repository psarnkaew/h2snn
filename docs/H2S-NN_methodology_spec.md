## 0. Rules of this document
1. Every component of the method answers a requirement in §2. A component without a requirement is removed.
2. Every requirement has a stated reason (the hypothesis, a theorem, or a data/protocol fact). No requirement exists because a variant scored well.
3. Every claim in §5 is fixed before the protocol in §6 runs, with the comparison that tests it and the result that falsifies it, and with what the paper says if it is falsified.
4. Results never change the method within a protocol run. A design change requires a new version of this document, written and committed before new runs.
5. Exploratory runs (e.g. the D11 screen of 2026-11-07) are recorded as exploratory and are not used to choose between designs.
6. A known-answer task, oracle or gate is pre-registered with (a) **reachability**: the parameter change the expected result needs and the change the run's optimizer and schedule can make (for one scalar under Adam, about Σ_t lr_t); an unreachable expectation is redesigned before running; and (b) an **information-route audit**: every route by which the label can reach a target within the receptive field (own features, facts, cells, `K` applications of `A`), per arm, including memorisation routes (unique per-node features against the number of training targets). (1.6; four synthetic misses in Parts H–I came from skipping this.)

## 1. Problem setting

**Data.** A heterogeneous graph `G = (V, E, φ, ψ)` with node types `φ : V → T_V`, relation types `ψ : E → T_R`, and per-type node attributes of different widths (featureless types get a learned vector per node). Benchmarks store each fact twice when a reverse relation exists; the method works on **facts**: `ρ(r) = r′` iff `E(r′)` is exactly the reversal of `E(r)`, and `(u, r, v) ≡ (v, ρ(r), u)` (D7).

**Tasks.** Main: node classification of a target type. Secondary: link prediction on heterogeneous graphs (§6). Appendix: graph classification, reported only as evidence that the model covers the task (generalizability); it carries no heterophily claim, and its "types" are atom and bond labels, stated as such (1.5).

**Thesis (hypothesis H).** On heterogeneous graphs, and especially under heterophily, label-relevant information is carried by **typed path instances** — their intermediate nodes and the order of their relations — and is lost when an instance is collapsed to a relation between its endpoints.

H is falsifiable: if it is false, a model that uses only endpoint relations of the same instances matches a model that uses the instances (claim C2).

**Heterophily (fixed in 1.5; closes `OPEN-1`).** Two measures, each exactly as defined and implemented by its source; never changed after.
- **ℋ² index** (H2GB, Lin et al., arXiv 2407.10916): `ℋ²(G) = mean_{P ∈ M₂} H_adj(G_P)`, where `M₂` is the set of length-2 meta-paths from the target type to the target type, `G_P` the meta-path-induced graph on target nodes, and `H_adj` adjusted heterophily (one minus the adjusted homophily of Platonov et al. 2023, which corrects for class imbalance). Near 0: homophilic; near or above 1: heterophilic.
- **MLH** (meta-path-based label homophily, Hetero²Net, Li et al., arXiv 2310.11664; used in heterophily form by H2GB): `Agg_{P ∈ M₂} H_edge(G_P)`. The aggregation, de-duplication and self-loop conventions are those of the reference code (recorded in the J0 report).
- **Primary measure for C6: ℋ²** (it is corrected for class imbalance; MLH can look homophilic under imbalance, e.g. IEEE-CIS-G: MLH 0.135, ℋ² 0.985 in H2GB Table 2). MLH is reported next to it.
- **Where reported.** Every dataset of every task whose nodes carry labels: published values are cited (H2GB Table 2: ogbn-mag, mag-year, IEEE-CIS-G, H-Pokec; Hetero²Net Table 1 MLH: DBLP, ACM, IMDB, homophily form); all others are computed with the reference implementation, and the published MLH of DBLP, ACM, IMDB is recomputed as the implementation check and reported beside the published value. For link prediction additionally the task-level `H_edge` of the target relation where both endpoint types carry labels (Freebase book–book, with the same fill convention and the labeled-only diagnostic; PubMed disease–disease is not measurable because its labels are unavailable, 1.8). Without node labels (LastFM; graph classification) the paper states "not measurable" and why.
- **Multilabel (IMDB) (1.8).** HGB, SeHGNN and HetSheaf all treat IMDB's labels as five independent binary genres (a 0/1 vector per movie). The heterophily measures follow that partition: for each genre g, `H_adj` and `H_edge` are computed with the reference function on the binary label `1(g ∈ Y_v)`, and IMDB's ℋ² and MLH are the means over the five genres (and over `M₂`). Per-genre values are reported. Hetero²Net's exact-match rule (`1(Y_u = Y_v)`, which gives its published 0.24) is kept only as the reproduction check; Zhao et al.'s Jaccard label homophily (arXiv 2304.10398, Definition 1) is reported in the appendix for comparability.
- **Unlabeled target nodes (1.8; author decision: follow the reference code).** Target-type nodes without a label (Freebase: 32,448 of 40,402 books; IMDB: 359 of 4,932 movies) receive a uniformly random class exactly as H2GB's `calcHomophily` does (`H2GB/calcHomophily.py:110-113`, commit `d3b49db`), so the values are comparable with H2GB Table 2 (which uses the same code). For IMDB the fill acts on each binary genre label. The fill seed is fixed and recorded, and the spread over 5 fill seeds is reported. Because the fill dominates Freebase (80 % random labels; ℋ² ≈ 0.999), the labeled-only value (pairs whose two endpoints are labelled; Freebase ≈ 0.89) is reported beside it as a diagnostic, never as the primary value. Node types without labels play no role: `G_P` is built on target nodes only.
- **Meta-path set and graph (1.8).** `M₂` is H2GB's full set of length-2 target→target meta-paths for every dataset, on the symmetrised graph as H2GB's loaders build it (Freebase stores no reverse relations, so book→X→book needs it). Hetero²Net's per-dataset sets serve only the reproduction check. Self-pairs follow the reference code (they are what reproduces DBLP 0.87; 0.80 without), stated in the paper.

## 2. Requirements

| ID | Requirement | Reason |
|---|---|---|
| R1 | Path-instance information reaches **every** node of the instance, including intermediate nodes, during propagation | H. Lemma A′ (§4): linear Hodge dynamics on the 2-complex cannot carry 2-cell information to nodes, so a direct node–2-cell coupling is required |
| R2 | Each instance couples its nodes with transports **forced by its observed edges** (order-dependent; no instance-specific orientation), and with a **strength that depends on its intermediate nodes and relation sequence** (R12) | H (order and intermediates carry information). Rewritten in 1.3: order alone is not specific to cells, since diffusion over facts composes the same transports in order (Prop. E); what cells add is instance-conditioned strength |
| R3 | Adding path instances must not contradict the graph's own structure (no constraint that forces consistent states to zero) | Instances are additional evidence about the same graph, not new constraints on it |
| R4 | Influence between nodes may be asymmetric: a node can listen without broadcasting and broadcast without listening | Heterogeneous relations and hubs: e.g. a subject node shared by thousands of papers should inform them without being pulled toward each one. Undirected sheaf diffusion cannot separate the two (CSNN Prop. 3.1, VERIFIED-SOURCE) |
| R5 | Propagation is stable for **all** values of the learned parameters | Learned maps, gates and filters make the operator data-dependent; stability must not depend on luck in training |
| R6 | Each fact is represented once; no held-out fact (either orientation) is visible during training | Data faithfulness; leak-free evaluation |
| R7 | Memory and time linear in facts and path incidences; no per-edge `d × d` tensors; a mini-batch is a restriction of the same model | Target datasets (H2GB) have tens of millions of edges |
| R8 | Path instances are drawn from a stated distribution with an unbiased estimator of a stated target operator; **no schema list, label or trained model enters the target**; the number of candidate schemas does not enter the cost | Reproducibility; results must not depend on sampling luck. Schema lists may be absent or incomplete for a dataset, so candidates cannot depend on one (1.3) |
| R9 | Propagation is **frequency-selective, per stalk coordinate**: it can keep, suppress or amplify low, middle and high sheaf frequencies, with a different response per coordinate | Heterophily: part of the label signal lies in transported disagreement (high and middle frequencies). A fixed first-order update `(I − ηA)^K` only damps them (PolyNSD §3, VERIFIED-SOURCE); one shared response cannot serve coordinates that need different bands |
| R10 | The geometry (restriction maps, gates, path weights) depends on each node's **typed neighbourhood**, and is computed **once** | Two nodes with similar attributes can play different relational roles; NSD, CSNN and DNSD obtain context by recomputing maps from propagated states every layer. Computing it once from a pre-aggregation keeps one sheaf, so R5, R7 (mini-batch restriction) and Props. 2–7 hold |
| R11 | A node's own features reach the nonlinear head separately from propagated ones | Heterophily: mixing ego and neighbour features before the head hurts when neighbours disagree (ego/neighbour separation, Zhu et al. 2020) |
| R12 | Whether, and how strongly, an instance informs its nodes is a learned, non-linear function of the **whole instance** (all its nodes' own encodings `h₀` and its relation sequence), shared by all nodes and schemas; the endpoint-only and schema-only versions are nested restrictions of it. `g` excludes the neighbourhood context `c` (1.4): with `c`, an endpoint's input already averages over its neighbours, which include the instance's intermediates, so the `endpoints` restriction would not be free of them; maps and gates keep `[h₀, c]` (R10) in every arm, including the path-specific maps of `endpoint_edges` and `free_path_maps` and the pair-attention scores (1.6) | H operationalised. By Prop. E, uniform-weight cells are (in expectation, Markov case) a diagonally scaled polynomial of the fact diffusion; instance-conditioned strength is the only substantive freedom cells add (1.3) |

## 3. Method — each component from its requirement

```
h₀  = TypeEncoder(x)                                           # per-type linear encoder + type embedding
c   = RelCtx(h₀)                                               # per (relation, role): mean of neighbours' h₀; one sparse pass per relation
cells, m_f  ←  WISP sampler (§3.2)                              # schema-free walks from target nodes; 1 walk = 1 cell
F, g, b, w_f  ←  computed once from [h₀, c]                    # one sheaf: maps, listen/broadcast gates, w_f = exp(g(ξ_f))
A   = G Δ̂ B,   Δ̂ = D^{-1/2}(Δ₀ + L_P)D^{-1/2}                   # facts + path 2-cells (D4, D9), L_P weighted by w_f m_f; spectrum ⊂ [0, 2)
x   = Σ_{k=0..K} T_k(A − I) (I_n ⊗ W_k) h₀,   Σ_k ‖W_k‖₂ ≤ 1     # Chebyshev filter bank; W_k ∈ R^{d×d} mixes stalk coordinates
y   = head([x, h₀])                                            # MLP
```

### 3.1 Where direction, heterogeneity and heterophily live
- **Direction.** The complex is an oriented 2-complex: one oriented cell per fact (D7) and signed path hops. Orientation alone only fixes signs, and the Laplacian does not depend on it; direction changes the computation through the maps: separate frames per role (`R_{ψ,src} ≠ R_{ψ,tgt}`), a role code in the reflection input, and the adjoint transport on backward hops. Shared roles only for relations with `ρ(r) = r`. Ablation: `direction_blind_maps` (the analogue of DSNN's `q = 0`). This is pair-specific directional **geometry**; directional **strength** is node-level (gates).
- **Heterogeneity** lives in the sheaf: type encoder (node types and attribute widths), relation-and-role frames (relation semantics and direction), relational context `c` (typed neighbourhood), path 2-cells (composite semantics: a schema's transport is the ordered product of its relation frames, so P–A–P and P–S–P have different holonomies), and type-aware gates (through `h₀`).
- **Heterophily** is handled at four levels: rotations in the maps (structured disagreement instead of averaging), instance-conditioned trust in 2-cells (WISP `w_f`: heterophily differs by meta-path and by instance), listen gates (tune out a disagreeing neighbourhood), the filter bank (keeps disagreement frequencies, R9), and ego separation in the head (R11).

### 3.2 WISP — the replacement of AMPSS (decided 1.3)
**Name.** WISP = **W**alk-sampled, **I**nstance-weighted **S**heaf **P**aths. Code/config namespace `wisp`. It answers three questions separately: (a) which instances *can* enter, (b) which are computed, (c) how strongly each counts. "Meta-path selection" is (c) aggregated by schema and is reported, not performed.

**Example (ACM, target type paper).** From paper P1 the sampler draws a length ℓ ∈ {2, …, ℓ_max} uniformly, then at each hop picks uniformly among the (relation, direction) actions that still have an unvisited neighbour (e.g. author, subject, term, cite, cited-by), then a uniform unvisited neighbour: P1 –author→ A7 –paper→ P9 is one walk and one cell (schema PAP is a *label of the cell*, not an input list). The cell's weight is `exp(g(ξ))` where ξ sees P1, A7, P9 and the two relations; a cell through a prolific, off-topic author can receive a low weight while another PAP cell receives a high one.

**(a) Candidates — walk-first, schema-free.** Anchors: every node of the target type (node classification). A walk is self-avoiding (an action is available only if it has an unvisited neighbour; a dead end before the drawn length discards the walk, i.e. the target is a sub-probability on simple walks).
**(b) Target measure and estimator.**
```
p(ω) = 1/(ℓ_max − 1) · Π_{j=1..ℓ} [ 1/|A_j(v_{j−1}, S_{j−1})| · 1/|N_j^unvisited| ]        # uniform length, uniform action, uniform neighbour
L_P^target = Σ_{a ∈ anchors} Σ_ω p(ω | a) · L_{f(ω)}
walk drawn from  ½ p + ½ q  (walk-level coin);   m_f = Σ_{walks → f} (1/r) · p(ω) / (½p(ω) + ½q(ω))  ≤ 2/r per walk
q(ω) = q_len(ℓ) · Π_j [ q_act(type(v_{j−1}), a_j) renormalised over A_j ] · 1/|N_j^unvisited|
```
`q` (optional, `proposal: adaptive`) is set at the start of each epoch from the previous epoch's share of path mass `w_f m_f` per length and per (node type, action); no gradient flows through it; it changes variance only, never the target. Evaluation uses one fixed draw from `p` alone (base seed), so every comparison arm sees identical evaluation cells. Identity and merge are D8's (canonical fact sequence, weights summed). One walk is one cell: prefixes are not sampled separately (removes nested double counting; PAP inside PAPAP enters as pair terms, Prop. K). Knobs: `ℓ_max` sets the **support** (a modelling choice, pre-registered per dataset; the shape of the target inside the support is largely absorbed by `g`, which sees the relation sequence) and `r` (precision only). The ½ is fixed (it gives the bound 2), never tuned.
**(c) Weights.** `w_f = exp(g(ξ_f))`; `g` = one projection per length over `[h₀(v_0), …, h₀(v_ℓ), rel_emb(a_1), …, rel_emb(a_ℓ)]` (1.4: `h₀`, not `geom = [h₀, c]`), GELU, linear output with bias `b` (scalar optimizer group), `b` initialised to `log(path_weight_init)`. Length-neutral at initialisation by construction (uniform length target, constant `g`).
**Read-outs (evaluation only, never feed back into training):** `I_π` (share of `Σ w_f m_f` by full walk schema), `I_σ` (share of pair weight by sub-path schema, exact by Prop. K), per-node `I_{v,σ}`, `ΔL_σ` (validation-loss change when σ's pair terms are removed, `T` evaluation draws), overlap ratio (share of pair weight whose sub-path also occurs in another sampled cell), Kendall τ of schema rankings across seeds. Bootstrap CIs over seeds and a permutation null.
**What changed from AMPSS (v1):** Stage I (schema scoring from counts, endpoint diversity and type-blind label propagation; ≥ 18 settings; hard error past 128 candidates) is removed; Stage II (instance weights) is kept and becomes the whole mechanism; the DFS-with-quota sampler (no stated distribution) is replaced by the WISP target measure; selection becomes read-out.

**Not claimed for the filter:** energy monotonicity (holds only for responses in `[0, 1]`) and the gradient-flow reading (holds only for the nested first-order case).

**Known limits (stated in the paper):**
- **L1 Strength ratios are node-determined.** The ratio strength(u←v)/strength(v←u) is fixed by the two nodes' gates; pair-specific ratios and cyclic trust are excluded. By Prop. 4 this is the exact price of a self-adjoint operator (real spectrum, frequency response). Directional geometry is pair-specific (§3.1). Designated extension, **not part of this method**: a sheaf skew-symmetric term `K_uv = κ_uv Q_{u←v}`, `κ` antisymmetric — continuous-time norm non-increasing (DERIVED; numerical min Re λ = 0), but an explicit step amplifies (gain 1.69 at step 0.9), so it needs an implicit or norm-preserving step, and it gives up the real spectrum (R9's response).
- **L2 Geometry does not depend on propagated states** (one sheaf); context enters once through `c`.
- **L3 Propagation is linear;** nonlinearity is in the head (decoupled design).
- **L4 Orthogonal maps** (diagonal maps would lose order-dependence). DNSD reports orthogonal maps hard to train **at depth** (12–16 layers); we are not deep.
- **L5** Path cells act within K applications; mini-batch is an approximation outside the receptive field.
- **L6 No instance-specific orientation.** An instance's transports are forced by its edges (Prop. 1); it cannot rotate or flip what its own edges do not. Instance-specific freedom is positive only (`w_f`; candidates `κ`, `A_fᵀA_f`). This is the exact price of consistency (R3, Prop. 2); free per-incidence maps (`free_path_maps`) are the control that drops it.
- **L7 Linear chains only.** Cells are simple walks; branching meta-structures (meta-graphs) are not represented.
- **L8 Unseen relations.** The relation embeddings and frames exist only for relations in the training graph.
- **L9 Support `ℓ_max`.** Instances longer than `ℓ_max` do not exist for the model; `ℓ_max` is pre-registered and the accuracy-vs-`ℓ_max` curve is reported (U3), not tuned.
- **L10 Proposal per node type.** The adaptive proposal `q` is a table over (node type, action) and length, not per node; it affects variance only.
- **L11 Sparse decisive evidence needs a large weight range** (1.7, Part K). A cell acts through its share of its nodes' `D`. With one decisive instance among 64, the model used it on 3/3 seeds when its weight was e^6.2 above the others (≈ 0.87 of `D`) and on 2/3 at e^4.2 (≈ 0.45). `g` must therefore learn log-weight gaps of this size; nothing is clamped, and the max log-weight stop level (30) is far above it.
