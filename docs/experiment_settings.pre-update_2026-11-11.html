1 · Mini-batch training

ตอนนี้ทำไม่ได้ สำหรับ node classification และ link prediction. Trainer ทั้งสองเป็น full batch (หนึ่ง optimizer step ต่อ epoch). Graph classification วน DataLoader ของกราฟเล็กหลายกราฟอยู่แล้ว ซึ่งเป็น mini-batch โดยธรรมชาติ

ข้อสังเกตเรื่อง graph classification กับ v3-B DERIVED: batch ของหลายกราฟคือกราฟที่มีหลาย component. ถ้าใช้ PCG ที่มี inner product รวมทั้ง batch คำตอบของแต่ละกราฟยังถูกในระดับ tolerance แต่ iterate ขึ้นกับกราฟอื่นใน batch. ถ้าต้องการให้ prediction ของกราฟหนึ่งไม่ขึ้นกับ batch ต้องส่ง scope_rows เป็นหนึ่ง scope ต่อกราฟ ซึ่งเป็นการใช้งาน per-scope PCG ครั้งแรก และต้องมีเทส bit-identity (addendum §4 ข้อ 2) ก่อน. ยังไม่ได้ตรวจว่า path anchored รันใน graph classification trainer ได้แล้วหรือไม่ UNVERIFIED

ต้องใช้ mini-batch กับ dataset ไหน: ตาม spec F3 คือ ogbn-mag, mag-year, H-Pokec และ IEEE-CIS-G ถ้า full batch ไม่พอ. ตัวเลข L7 บน RTX 4060 (DBLP 5.0 GB ที่ d = 32) บอกว่า HGB ทั้งสามชุดเป็น full batch ได้ ส่วน Freebase (180k nodes, 1.06M links) ยังไม่ได้วัด

งานที่ต้องทำ: task card mini-batch ตาม decisions §8 + addendum §4 (unit แรกคือ E14 ซึ่งทำแล้วใน config). เทสหลัก: batch = รวม scope ที่แยกกัน → prediction เท่ากับรันทีละ scope แบบ bit-identical, prediction ตอน evaluation ไม่ขึ้นกับ batch size, harness ที่ใช้ทั้งกราฟต้องได้ logits เท่ากับ full batch

2.4 ข้อควรระวังของ MDE

  • ขึ้นกับสเกลของ feature. Hetero²Net ใช้ x ดิบ (footnote 1 บอกว่าสเกลควบคุมได้เฉพาะเมื่อ normalise feature). Bag-of-words binary กับ embedding 128 มิติให้ค่าคนละช่วง (MAG 0.04 กับ DBLP 0.80). จึงเทียบ MDE ข้าม dataset เป็น "ระดับ heterophily" ไม่ได้ ใช้ได้แค่เป็นค่าบรรยาย dataset. ตัวแปรที่ใช้แบ่งผลใน C6 ยังเป็น ℋ² ตาม spec DERIVED
  • Link prediction ที่ endpoint ต่าง type (P–A, A–P, M–A): MDE ต้องเลือก type A. ข้อเสนอ: รายงานต่อ endpoint type ที่มี feature
  • D1: กฎ F17 ตัด feature ของ author (ACM, DBLP) และ actor (IMDB) ในไฟล์ LP. (a) วัดบนกราฟต้นฉบับ: เป็นค่าบรรยาย dataset และเทียบกับ NC ได้. (b) วัดบนไฟล์ LP: ตรงกับสิ่งที่โมเดลเห็น แต่ type ที่ถูกตัดเป็น "–". ผมแนะนำ (a) และระบุในตารางว่าวัดบนกราฟเต็ม

2.5 Graph classification

ภายใต้ preprocessing ของ HetSheaf (§6) ทั้งสามค่านิยามไม่ได้ตามแหล่งที่มา DERIVED:

  • MLH และ ℋ² ต้องใช้ node label ของ target type แต่ graph classification มีแค่ label ระดับกราฟ
  • H2GB และ Hetero²Net ต้องมี target type เพื่อสร้าง meta-path; กราฟโมเลกุลไม่มี
  • หลังแปลง type แล้ว HetSheaf แทน feature ด้วย 1 ทุกโหนด (graph_classification.py ExtractTypes, node_feature_type: constant). เมื่อ x = 1 ทุกโหนด E = ¼ Σ (1/√d_u − 1/√d_v)² เป็นการวัดความต่างของ degree ไม่ใช่ attribute. และถึงจะใช้ one-hot atom label เป็น feature โหนดใน type เดียวกันก็มี feature เหมือนกันหมด จึงเหลือแค่ degree อีกเช่นกัน

D2: (a) ใส่ "–" สำหรับ graph classification (สอดคล้องกับ spec 1.5 ที่บอกว่า graph classification ไม่มี heterophily claim) หรือ (b) นิยาม MDE ใหม่ที่ใช้ attribute จริงของ PROTEINS (1 มิติ) และ ENZYMES (18 มิติ) โดยรวมทุก type pair. (b) เป็นนิยามของเราเอง ไม่ใช่ของ Hetero²Net และขัดกับ HetSheaf ที่ทิ้ง attribute เหล่านี้. ผมแนะนำ (a)

5.4 เอาค่า baseline จาก HetSheaf มาใช้ได้ไหม (D6)

6.3 จุดที่ต้องตัดสินถ้าทำตาม HetSheaf (D7)

  • Test set เล็กมาก: MUTAG test 20 กราฟ หนึ่งกราฟเท่ากับ 5 คะแนน accuracy. ใช้ split เดียวทุก seed ทำให้ std สะท้อนแค่ initialization ไม่รวมความแปรปรวนของ split DERIVED

  • Batch size 1: ช้ามาก (NCI1 3,288 step ต่อ epoch) แต่เป็นสิ่งที่เขาใช้
  • ขัดกับ spec 1.5 (stratified 10-fold CV): ถ้าตาม HetSheaf ต้องแก้ spec

(b) ตามเรื่อง data (dataset, type, feature, split 80/10/10 seed 42) แต่ใช้ budget, checkpoint selection และ 10 seeds ของเราเหมือน task อื่น. ผมแนะนำ (b) เพราะตารางของเรารันใหม่ทุก method อยู่แล้ว และ (b) ทำให้ graph classification ใช้กฎเดียวกับ task อื่น (economy rule ของ spec 1.10)
