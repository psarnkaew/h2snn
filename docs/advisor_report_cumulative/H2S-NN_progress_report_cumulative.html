Scalability and path coupling

Lighter restriction maps, meta-path faces coupled directly to nodes, fact storage, path sampling and computation, node gates, cost

H2S-NN Revision: Progress Report

Making the model scalable, letting path information reach the nodes, and fixing the data pipeline

8 November 2026Measurements: ACM dataset, NVIDIA RTX 4060 Laptop GPU (8 GB)

Overview

The reviewers' main concerns included whether H2S-NN scales to larger graphs. While preparing the revision, we also found a structural problem: in the submitted model, the term that was meant to carry information from the meta-path instances (the 2-cells) to the nodes had exactly zero effect during diffusion. Two main changes address these, followed by three supporting changes (Section 3):

  1. Lighter restriction maps. Each edge no longer stores its own full d×d matrix.
  2. Meta-path faces coupled directly to nodes. Each meta-path instance is still a face (2-cell) of the model. It now passes information straight to every node on it, through maps that the face itself determines, and the edge-level machinery of the old model is removed.

1. Lighter restriction maps

Before

For every edge, the model learned two restriction maps, one for each endpoint. Each map was a full d×d matrix. On ACM there are 547,872 edges, so at d = 32 the maps alone need about 1.1 billion numbers (4.2 GB). This is the main reason the submitted model could not run on large heterophilic benchmarks such as ogbn-mag.

After

We split each map into three parts, and only the small parts are stored per edge:

map for node v on edge e  =  c_e  ×  R_relation  ×  (k reflections built from node features)
  • A rotation per relation type (R): for example, all paper→author edges share one. ACM needs only 16 such matrices in total, instead of two per edge.
  • k reflections per edge: these make the map depend on the actual nodes. A reflection is a d×d matrix, but it is fully described by a single vector of d numbers. It can be applied to a feature vector directly (x − 2u(uᵀx)/‖u‖²), so the matrix is never built. We use k = 2.
  • One scale per edge (ce): a single positive number, shared by both endpoints. Sharing it keeps the transport along a path a pure rotation, so long paths cannot blow up numerically.

Figure 1. What is stored for each edge at d = 32. The large matrices become shared per relation type; each edge keeps only a few vectors.

Choosing k

k sets the trade-off between flexibility and memory. With k = d reflections, the map could be any rotation, which is as expressive as the old model but saves nothing. With a small k, edges of the same relation share the rotation and differ only in a few directions.

Result of this change alone

At d = 8, whole-model GPU memory halved (6.08 → 3.00 GB) and a training step became 1.8× faster (3.18 → 1.73 s). The part of the computation that builds and applies the maps became 5× faster. Total memory did not fall by the full 15.9×, because the rest of the old model (edge states and the dense maps on the path side) still dominated. The second change removes that part.

2. Meta-path faces coupled directly to nodes

What a meta-path face means

Each meta-path instance, for example P₁–A–P₂ (two papers with a common author), is a face (2-cell). Its boundary is the instance itself together with a closure edge P₁–P₂, which stands for the meta-path relation "P₁ and P₂ are related through Paper–Author–Paper". The face states a coherence condition: going from P₁ to P₂ along the meta-path relation must agree with going through the instance. In sheaf terms, this condition forces the map of the closure edge to equal the composition of the maps along the instance (the path's holonomy). The meta-path relation is therefore not a new relation learned freely, as in HAN, but is fixed by the instance that witnesses it, including its intermediate node and the order of its relations. This meaning is the same before and after the change; what changes is how the face reaches the nodes.

Before

The face had its own term, but that term influenced the nodes only indirectly: face → states stored on edges → nodes. This route has a mathematical problem. When the diffusion is linear, which it is in our model, the face term's influence on the nodes is exactly zero. This holds for any number of diffusion steps, and we also confirmed it numerically. Path information still reached the prediction through two other routes:

  • the closure edge P₁–P₂, used as an ordinary edge of the graph operator. Its map was the holonomy, as the face requires, but the face's own term added nothing beyond this edge;
  • a single average of the edge states in the final classifier.

In addition, the edge route required storing a large tensor on every edge and every path, which used most of the GPU memory.

After

The face is now coupled directly to every node on its boundary path: both endpoints and the intermediate node(s). The coupling uses the face's own restriction maps. These are not new parameters: the face's coherence condition forces them to be the transports along the path, T_i = Q₁Q₂⋯Q_i, the same maps that fix the closure edge. Each diffusion step does two things:

  1. It forms the face's value z_f: the average of its nodes' features after transporting them into the face, so that relation order and direction matter. z_f lives in the face's own space.
  2. It pulls every node on the path toward z_f (transported back to that node), together with the usual pull toward its graph neighbours.

Both pulls together form a single sheaf Laplacian. The cellular sheaf on the 2-complex (nodes, edges, closure edges and faces, with their maps) is kept as it was. What is removed is the computation on edges: the edge states, the edge Laplacian and the dense path-side matrices.

Figure 2. How a meta-path face (Paper–Author–Paper) influences the nodes, before and after. In both, the face f is bounded by the instance P₁–A–P₂ and the closure edge P₁–P₂, whose map the face fixes to the holonomy of the path. After the change, the face is coupled to every node on the path through the maps T, which the face also fixes; information flows both ways.

Properties we proved and checked numerically

  • It respects the sheaf structure. The new term never contradicts the graph's own sheaf: any assignment that is consistent on the graph stays consistent. If the maps on the path were chosen freely, as in a hypergraph model, this property would be lost. We checked both cases.
  • It is stable. After normalization, the operator's largest eigenvalue is at most 2, so the diffusion step cannot diverge for any learned step size. The largest value observed over 60 random test graphs was 1.99999. Without normalization, values reached 1016.
  • The face reaches the nodes. In one step, the face carries information between all nodes on the path. In the old model the face term had zero effect on the nodes.
  • The intermediate node shapes the meta-path relation. The holonomy from P₁ to P₂ is the composition of the maps of both boundary edges, and these depend on the intermediate node's features. Two Paper–Author–Paper instances with different authors therefore give different relations between their papers. (The intermediate node also reaches the endpoints in one step through the ordinary edges; that part is not new.)

What this change gives up, and what it keeps

The face term can be rewritten exactly as pairwise terms between all nodes on the path (n = number of nodes on the path):

Σ_i ‖T_i x_i − z_f‖²  =  (1/n) Σ_{i<j} ‖T_i x_i − T_j x_j‖²

For P₁–A–P₂ the three pairs are P₁–A and A–P₂, with exactly the maps of the existing edges, and P₁–P₂, with the holonomy map, that is, the closure edge. So the face reaches the nodes through the meta-path relation it defines and by strengthening the edges of its own instance, each pair with weight γ·w_f/3. This is what a meta-path face is meant to do. The difference from HAN-style meta-path edges is therefore not that the endpoint relation is absent; it is that the relation's map is fixed by the instance instead of being learned freely. Several consequences follow, and the paper will state them:

  • Values on edges and faces are no longer evolved. The sheaf on the 2-complex is unchanged, but the model no longer runs the Hodge Laplacian on edge and face values. In the submitted model that part never reached the nodes (see Before), so no effect on the nodes is lost. What is lost is the option to read edge or face values out directly.
  • The face is a definition, not a measurement. The closure edge is not observed in the data; its map is defined by the face, so every face is consistent by construction. A face cannot detect conflicting relations. It imposes that the meta-path relation agrees with its instance.
  • The same operator could be written without faces, as transports along paths. The face is what justifies this choice: its coherence condition allows only the path transport as the map of the meta-path relation, and a free choice breaks the sheaf property listed above.
  • The meta-path relation may now be weaker. In the submitted model the closure edge was a full edge of the graph operator; now it carries weight γ·w_f/n. Whether this helps or hurts accuracy has not been measured. The ablations in Section 5 compare the two directly.

3. Further changes: graph encoding, path sampling and node gates

Once faces were coupled directly to nodes, three more parts of the pipeline needed attention: how the graph's edges are represented, how path instances are sampled and computed, and whether influence between nodes has to be symmetric.

3.1 Each fact is stored once

Before

The HGB benchmarks store every relation in both directions. In ACM, for example, the relation paper → author (PA) has an exact mirror author → paper (AP) that contains the same pairs reversed. All 10 relation pairs in ACM, DBLP and IMDB are exact mirrors of this kind. Standard message-passing GNNs need both directions, because messages flow from source to target only. The old model inherited this and treated the single fact "paper p is written by author a" as two separate edges, each with its own unrelated maps.

Why it is a problem

The sheaf Laplacian is already symmetric, so the second copy adds no direction, only a second, conflicting constraint. For one fact, the energy has two terms:

E(x) = ‖F¹_src x_p − F¹_tgt x_a‖²  +  ‖F²_src x_a − F²_tgt x_p‖²

A consistent assignment (E = 0) must satisfy x_a = Q₁x_p and x_a = Q₂x_p at the same time. With two independently learned maps, Q₁ ≠ Q₂, and generically only x = 0 survives. On a single link at d = 8, the space of consistent assignments collapsed from 8 dimensions to 0, which makes the theory's guarantee that "path cells never contradict the graph sheaf" empty.

After

Each fact is now one edge. Two relations are recognised as inverses by one exact, parameter-free rule:

ρ(r) = r′   if and only if   the pairs of r′ are exactly the pairs of r reversed
a fact:  (u, r, v) ≡ (v, ρ(r), u)   →   stored once, as one oriented edge

Direction is kept: when a path walks along an edge against its stored orientation, it uses the reverse transport Qᵀ instead of Q. If two relations are not exact mirrors, they stay separate.

Result

  • ACM goes from 547,872 stored edges to 273,936 facts, so the graph operator is half the size.
  • We found a data leak in link prediction. When a link (p, a) was held out for testing, the old split removed it from PA but left its mirror (a, p) in AP, so the model could see the answer. On a test case, 8 of 21 held-out links leaked. Splits are now made per fact. Earlier link-prediction numbers, ours and the baselines', may be inflated on datasets with mirror relations and will be rerun.
  • We also found a loader bug in MUTAG. Bond types were assigned by position after PyTorch Geometric had reordered the edges, so 1,771 of 7,442 bonds had the wrong type, in all 188 graphs. All earlier MUTAG results will be rerun.
  • Baselines still receive the standard stored graph with both directions, so every method sees the same facts.

3.2 Path instances: unbiased sampling and faster computation

Before

Path instances were collected by depth-first search with a fixed quota of r paths per starting node. This has three problems.

  • It is biased. Take a paper with 3 authors, each with 30 papers, and r = 20. The search fills the quota through the first author and never reaches the other two. In 200 of 200 random seeds, only 1 of the 3 authors was used as the middle node. With one author who has 300 papers, 48–50 of 50 paths went through that author. The question "does the middle node matter?", which the reviewers raised, cannot be answered if the sampler always picks the same middle node.
  • Duplicates are counted twice. The path p₁–a–p₂ and its reverse p₂–a–p₁ became two cells (3,690 of 16,300 in a test), so their weight depended on chance.
  • It is slow: it is a Python loop per starting node, and was the preprocessing bottleneck for larger graphs.

After: sampling

Paths are drawn by random walks that follow the meta-path's relation types and directions. Each step picks uniformly among the allowed neighbours, so every path has a known probability:

p(path | start a, meta-path π)  =  ∏ over steps j  of  1 / (number of allowed neighbours at step j)
r walks per (start node, meta-path), each with weight 1/r
identical paths (in either direction) are merged by ADDING their weights:  m_f = Σ weights

Adding rather than discarding duplicates makes the sampled operator an unbiased estimate of its expected value: on a test, the error was 0.005 with summing versus 0.47 with discarding. In the example above, each of the 3 authors is now chosen with probability 1/3. Paths are resampled every training epoch; validation and test use one fixed draw.

After: computation

For a path v₀, …, v_L with step transports Q₁, …, Q_L, the transport of node i into the path is T_i = Q₁Q₂⋯Q_i. The old code built each T_i separately: L(L+1) transport applications per path. Because each T_i is a scaled rotation (T_iᵀT_i = s_i² I), the same result follows from two passes of L steps each:

path term at node i:   w_f · ( s_i² x_i − T_iᵀ z_f ),        z_f = (1/n) Σ_i T_i x_i
forward pass:    Σ_i T_i x_i = x₀ + Q₁( x₁ + Q₂( x₂ + ⋯ + Q_L x_L ) )      (L steps)
backward pass:   T₀ᵀz = z,   T_iᵀz = Q_iᵀ ( T_{i−1}ᵀ z )                  (L steps)

A Paper–Author–Paper path (L = 2) needs 4 transport applications instead of 6, and a path of length 4 needs 8 instead of 20. The output is identical (difference ≤ 2·10⁻¹² in double precision).

Result of 3.1 and 3.2 together

On ACM at d = 32, a training step now uses 1.49 GB and 1.06 s, down from 2.52 GB and 1.77 s after Section 2, on the same GPU. This figure includes the gates of Section 3.3. The two measurements also differ in the number of sampled paths, so the reduction should not be attributed to one change alone.

3.3 Listen and broadcast gates (proposed, under test)

Before

The diffusion x ← x − η Δ̂ x is symmetric: node u pulls node v exactly as hard as v pulls u.

Why we are considering a change

In heterogeneous graphs, influence is plausibly unequal. In ACM, one subject node is linked to as many as 1,195 papers. It should be able to inform its papers without being pulled toward each of them. Under heterophily, a node should also be able to stop listening to dissimilar neighbours. This is a hypothesis, not yet an observed effect.

Proposal

Each node gets a listen gate g and a broadcast gate b, both between 0 and 1, computed from its input features h₀:

g_v = σ(a_gᵀ h₀_v + β_g),     b_v = σ(a_bᵀ h₀_v + β_b)
x ← x − η · G Δ̂ B x,          G = diag(g),  B = diag(b)
influence of v on u  =  g_u · b_v          (no longer symmetric)

Example: if a subject node learns b ≈ 1 and g ≈ 0.1, it informs its papers fully but is pulled only weakly by them.

Non-symmetric operators usually have complex eigenvalues and can be unstable. This one cannot, because it is similar to a symmetric matrix:

with S = (G⁻¹B)^{1/2}:     S (G Δ̂ B) S⁻¹  =  (GB)^{1/2} Δ̂ (GB)^{1/2}      (symmetric, positive semidefinite)
⇒ all eigenvalues are real and lie in [0, 2·max g·b) ⊂ [0, 2)  ⇒  the step is stable for any η < 1

On 200 random test graphs, the largest imaginary part of any eigenvalue was 7·10⁻¹⁷. The comparable operator of Cooperative Sheaf Neural Networks reached 2.6·10⁴ on the same graphs. The gates add 0.6% to the time and 0.5% to the memory of a training step.

Status. We do not yet know whether the gates improve accuracy. The gates are currently part of the model. They will be compared against the symmetric model (all gates equal to 1) over 10 seeds with paired tests, and that comparison will be reported in the paper.

H2S-NN Revision: Progress Report

Letting the model keep disagreement, giving it a view of each node's neighbourhood, and testing the path mechanism directly

8 November 2026 (second report)Measurements: ACM dataset, NVIDIA RTX 4060 Laptop GPU (8 GB)

Overview

The previous report made the model fit in memory and coupled each meta-path face directly to every node on it. This stage asked what the model does with that information once it reaches a node, and whether the path mechanism does what the thesis claims. Two changes and two checks came out of it:

  1. A frequency-selective encoder. The diffusion step could only smooth. A learned filter now lets each feature channel keep, damp or sharpen the disagreement between neighbours.
  2. Geometry that sees the neighbourhood. The restriction maps, gates and path weights now read a summary of each node's typed neighbours, not only the node's own features. The submitted paper describes this term, but the code did not implement it.

Two checks support these changes (Section 3): the data pipeline against the official benchmark, and a synthetic test of the path mechanism in which we know which path instance holds the answer.

1. A frequency-selective encoder

Before

Propagation was K small diffusion steps. Each step pulled every node toward its neighbours, after transporting the neighbours with the restriction maps:

x  ←  (I − η A)K h₀          A = gated, normalised sheaf Laplacian of edges and path faces

A signal on the graph can be read as a mix of frequencies. A low-frequency signal is one where each node agrees with its transported neighbours. A high-frequency signal is one where it disagrees. The operator A measures this, with eigenvalues from 0 (full agreement) to 2 (strong disagreement). Each step multiplies a component at frequency λ by (1 − ηλ), so K steps multiply it by (1 − ηλ)K.

Why it is a problem

The old update can only smooth, and it smooths every feature channel in the same way. With the step size the model learned (η ≈ 0.45) and K = 4:

  • a component at λ = 1 keeps about 9% of its size;
  • a component at λ = 1.5 keeps about 1%.

Under heterophily, the disagreement itself can carry the label. A paper whose subject is shared mostly by papers on a different topic is informative because it differs from them. The old update erases exactly this signal.

After

The output is a learned polynomial filter of the same operator:

x  =  Σk=0..K  Tk(A − I) · Wk h₀          with   Σk ‖Wk‖ ≤ 1
  • Tk are the Chebyshev polynomials, a standard, numerically well-behaved basis.
  • Wk are small d×d matrices, one per degree, that mix the feature channels.

Each channel therefore gets its own frequency response (Figure 1). The filter applies A K times, as the old K steps did, and adds only small per-node matrix products, so the memory savings of the previous report are kept.

Figure 1. How strongly each frequency survives propagation. Before: one fixed curve for all channels, shown with the learned η ≈ 0.45 and K = 4. After: each channel has its own curve. The three curves on the right are example shapes the filter can represent, not learned values.

Example. One channel can carry a paper's topic with a smoothing response, so papers that share authors move toward agreement. A second channel can use a high-pass response. A paper whose topic differs from the other papers on its subject then keeps that difference, instead of losing 99% of it as in the old update.

Properties we proved and checked numerically

  • It is stable for every parameter value. The gated operator has a real spectrum in [0, 2), as the previous report showed. With the bound on the Wk, the filter's gain is at most 1, whatever values are learned.
  • The old update is a special case. Setting every Wk to a fixed multiple of the identity gives (I − ηA)K exactly. At initialisation the new model computes the same output as the old one, to within 10−10.
  • The listen and broadcast gates keep their meaning through the whole filter. A node whose listen gate is closed receives nothing from any other node, and a node whose broadcast gate is closed sends nothing. The corresponding blocks are exactly zero.
  • The node's own signal is never washed out. The degree-0 term keeps the input, so adding degrees cannot make the output vanish. Deep sheaf diffusion models are known to suffer from that problem.

What this change gives up, and what it keeps

  • The energy reading is lost. The old update could be read as a flow that lowers the sheaf energy at every step. The filter can favour disagreement, so this reading no longer holds and the paper will not claim it. Stability and the real spectrum are kept.
  • The stability bound limits what can be learned. In a short smoke run, the unconstrained filter weights exceeded the bound within five epochs (sum 1.067) and were scaled back. Training pushes against the guarantee. That is the price of a guarantee that holds for every parameter value, and we will measure it rather than assume it is free.

2. Geometry that sees the neighbourhood

Before

The restriction maps, the listen and broadcast gates and the path weights were all computed from a node's own input features h₀. The submitted paper includes a neighbourhood-context term for the maps, but the code did not implement it, so paper and code disagreed.

Why it is a problem

Two nodes with similar features can play different roles in the graph. If the geometry sees only the node itself, it cannot tell them apart, and both receive the same maps and gates.

After

Each node gets a typed neighbourhood summary: for each relation type, the average input features of its neighbours through that relation. The geometry reads both parts:

cv  =  [ mean of h₀ over v's authors ,  mean over v's subjects ,  … ]        (one average per relation type)
maps, gates, path weights  =  functions of  [ h₀v , cv ]

The summary is computed once, before propagation. Other sheaf models (NSD, CSNN, DNSD) recompute their maps from the propagated states at every layer, which creates a new sheaf at each layer. Computing the summary once keeps a single fixed sheaf. The guarantees of Section 1 and the mini-batch argument of the previous report therefore still hold.

Figure 2. Two papers with similar abstracts. Before, they receive the same maps and gates. After, the summary of their authors separates them.

Example. P₁ and P₂ have nearly identical abstracts. P₁'s authors publish mostly in databases and P₂'s mostly in machine learning, so their summaries differ. P₂ can then learn, for instance, to listen less to a subject node that is shared mainly with database papers.

Properties we proved and checked numerically

  • Nothing else changes when the summary is switched off. The model then reproduces the previous model's outputs exactly.
  • The summary reaches the geometry, and only where it should. Changing one neighbour's features changes that node's maps and gates when the summary is on, and changes nothing when it is off. The summary uses only the stored facts and respects each relation's direction.

What this change gives up, and what it keeps

  • The geometry does not follow the propagated states. It is fixed before propagation, by design: this keeps one sheaf and all its guarantees. Models that recompute their maps at every layer can adapt their geometry during propagation; ours cannot.
  • It is the most expensive change of this stage (Result, below).
  • It overlaps partly with the path faces. The summary gives each node a view two hops away: an author's summary contains its papers, and a paper reads that summary through its author. Section 3.2 shows that this alone solved a task we had designed to test path faces. This is not a defect, but it raises the bar for the thesis. Path faces must add information beyond edges plus neighbourhood summaries. We therefore keep the summary on in every arm of the path comparison, which is the stricter test, and the paper will say why.

3. Further checks: the data pipeline and the path mechanism

3.1 The data pipeline matches the benchmark

Before changing the model, we checked that our data matches the HGB benchmark (ACM, DBLP, IMDB) exactly. We read the official files with HGB's own loader and compared them item by item:

  • Splits: our test nodes are exactly HGB's test nodes. Our training and validation nodes together are exactly HGB's labelled set, with HGB's 20% held out for validation.
  • Labels: all 3,025, 4,057 and 4,573 labels agree, including IMDB's multi-label vectors.
  • Edges: our graph stores one edge per fact. Expanded back to both directions, it reproduces HGB's stored edge list exactly.

We could not reproduce HetSheaf's published rerun of R-GCN, for three reasons:

  • their selected configuration came from a 150-run search that is not published;
  • their paper states HGB's 24/6/70 split, but their code uses 27/3/70;
  • their code duplicates every relation, giving ACM 14 relation types instead of 8 and twice the edges.

Their own pipeline also misses the published number with the configuration in their repository.

Decision. We use HGB's official split. Every baseline, HetSheaf included, will be rerun under our protocol. Published numbers will appear only in a clearly labelled note, not in the comparison tables.

3.2 A test of the path mechanism with a known answer

Our thesis is that a meta-path instance carries information through its intermediate node and the order of its relations, and that this information is lost when the instance is reduced to a relation between its two endpoints. Before running large comparisons, we wanted to see the mechanism do this on a graph where we know which instance holds the answer.

First design: the label is a co-paper's class, reached through the lead author

Each paper has a lead author and a second author, and each author has one other paper, a co-paper. The paper's label is the class of the co-paper reached through its lead author.

A model without path faces scored 0.996, so the task leaked. The cause was the neighbourhood summary. The lead author's summary already contains its co-paper's class, and the paper reads that summary through an ordinary edge. With the summary set to zero, the same trained model fell to chance (0.488). This is the overlap described in Section 2.

What the result shows

  • The rest of the model is not the bottleneck. When we set the path weights to the correct answer and train everything else as usual, the model solves the task. The transports along the path, the filter and the classifier carry the information.
  • Learning the path weight is the bottleneck.
    • The learned weights did separate lead-author instances from second-author ones. That depends on a property of a single node.
    • They never separated instances whose codes match from those whose codes do not. That needs a comparison between two nodes on the path.
    • The weight network sees all three nodes and has a hidden layer, so it can represent this rule in principle. It did not learn it from 500 papers in 200 epochs at default settings.
    • Its weights did not differ between training and test papers, so it was not memorising instances.

Status. The test neither confirms nor refutes the thesis on real data. The task is deliberately hard (an exact 6-bit match learned from 500 examples), and we did not tune for it, because tuning on a known-answer task would make a pass meaningless. It does show where the risk sits. Path instances add information beyond graph diffusion only when they are weighted by their content, and part of that content is a relationship between nodes on the path. The weight function's ability to learn such comparisons is therefore central to the thesis. We carry this question, and both test tasks, into the next stage.

H2S-NN Revision: Heterophily of the Evaluation Datasets

How heterophilic is each dataset we evaluate on, measured the way the source benchmarks define it

9 November 2026Computed on CPU with the benchmarks' own published code

Why this chapter

The revised paper relates the model's gains to how heterophilic a dataset is. That comparison is only meaningful if every dataset is measured the same way. We therefore fixed two published measures and computed them with the reference code released by their authors, instead of writing our own versions. Before computing any new value, we checked that this pipeline reproduces a published number.

1. What the two measures capture

Both measures look at pairs of labelled nodes of the target type, for example two papers, that are linked through a meta-path: a short typed route such as paper–author–paper ("two papers share an author"). MLH (meta-path label homophily) is the share of such pairs whose two nodes carry the same label, averaged over all meta-paths of length two that start and end at the target type. We report it as heterophily, one minus that share. Higher means connected nodes disagree more often. The ℋ² index asks the same question but first subtracts the agreement that class sizes alone would produce if links ignored labels, and rescales the result (adjusted heterophily). A value near 0 means homophilic; near or above 1 means heterophilic. We use ℋ² as the primary measure because MLH can look homophilic merely because one class dominates.

A small example

Four papers P1–P4 have topics A, A, B, A. Two authors wrote them: author X wrote P1 and P2, author Y wrote P2, P3 and P4. Through "shares an author", including each paper with itself as the reference code does, there are 12 ordered paper pairs, and 8 of them agree on the topic. Agreement is 8/12 = 0.67, so MLH heterophily is 0.33, which looks homophilic. But topic A covers three of the four papers. When each paper is weighted by how many pairs it appears in, A accounts for 9 of 12 pair-ends and B for 3. Random pairing would agree with probability (9/12)² + (3/12)² = 0.625. The observed 0.67 is barely above that chance level: the adjusted homophily is (0.67 − 0.625)/(1 − 0.625) = 0.11, so ℋ² for this meta-path is 0.89, i.e. clearly heterophilic. The same links look homophilic to MLH and heterophilic to ℋ², because most of the agreement comes from class imbalance.

The values in the example are computed by hand. The reference code reproduces them exactly in our tests.

2. Check against a published value

Hetero²Net (Li et al., TPAMI 2025), which introduced MLH, reports for DBLP a homophily of 0.87 over its meta-path author–paper–author. Running the released code of ℋ²GB (Lin et al., KDD 2025), which defines ℋ², on the same public DBLP graph gives 0.872. We had fixed a tolerance of ±0.01 before running. The match depends on a detail: each author also counts as paired with itself, as in the released code. Without these self-pairs the value would be 0.80. The same pipeline also reproduces the published ACM value (0.60; ours 0.596) and IMDB value (0.24; ours 0.237). That paper's own ablation table lists these two values with the datasets swapped. Its main table and our results agree with each other.

Notes.

  • IMDB (multi-label). A movie can have several genres. The MLH code treats two movies as agreeing only when their full genre sets are identical. The ℋ² code assumes one label per node, and neither benchmark defines a multi-label version. That choice (for example, genre sets as classes, or an average over genres) has not been made, so no value is reported yet.
  • Freebase. Only one book in five carries a label. The reference code assigns random labels to the unlabelled books, which pushes both measures towards "heterophilic" whatever the graph looks like. Its result for Freebase is close to 1, and it changes when only labelled books are counted. Because which rule applies is a decision, not a measurement, no value is reported yet.

4. Datasets without node labels: not measurable

Both measures compare the labels of linked nodes, so they need node labels.

  • LastFM (link prediction): users, artists and tags carry no labels, so the measures are not measurable.
  • PubMed (link prediction): the public release has no labels. The disease labels exist only in a separate release that is no longer publicly downloadable, so the measures are not measurable at present.
  • Graph-classification datasets: labels belong to whole graphs, not to nodes, so node-level heterophily does not apply. These datasets serve only to show that the model covers the task.
