# Task card — Legacy removal (LR): v3-B defaults, fail-closed legacy settings, removal of v1/v2 code

**Binding:** `docs/working_preferences.md` (all; in particular "Review, approval and branch flow (2026-11-15)" and "Everything runs on the cluster"); `docs/H2S-NN_cluster_setup3_report.md` (CS8: pinned kernel environment E, 1 thread, cluster references); `H2S-NN/AGENTS.md`/`CLAUDE.md`. Spec **v1.22** is the design authority and is **not** touched: this card changes no method behaviour of v3-B. Every v3-B output must stay bit-identical.
**Author decisions (2026-11-15, design session B; `docs/open_items_ablation_legacy_2026-11-15.md` §A):** A1 = fail-closed **and** removal; A2 = keep `identity_maps` (a candidate sheaf-vs-no-sheaf ablation control, not yet decided); A3 = after Part M3a, before Part M3b (M3a had already started and barely touches legacy code).
**Why.** (1) `ModelConfig` defaults are still v2 (`propagation: "chebyshev"`, `encoder: "filter_bank"`, `coupling: "cooperative"`, `src/configs/config.py:1167-1177, 1371`): a configuration without `propagation: anchored` silently runs the v2 model; the tuning and ablation campaigns will write hundreds of configurations. (2) The frozen code is released with the paper; v1/v2 machinery (filter bank, gates, Chebyshev propagation, v2 arms, v2-only samplers) must not sit next to the method. (3) The ablation table needs one set of arms.
**Branch:** `legacy-removal`, created from `v3b` at the SHA given in the prompt (the approved Part M3a head), then `git merge --no-ff` of the pinned `design-docs` SHA (a conflict is a stop). **Report:** `docs/H2S-NN_legacy_removal_report.md`; evidence `docs/legacy_evidence/`.

## Rules
- Correctness only: unit tests, golden compares, mutation checks (each against its target test only), the full suite. No run on real data, no metric, no comparison between methods.
- Everything in `h2snn-b` with E exported and, for bit-exact checks, 1 thread (CS8 rule R2); every computation in a SLURM job; tests through `scripts/slurm/run_tests.sbatch`. Every job script (kept in `docs/legacy_evidence/`) prints `git rev-parse HEAD`, `hostname`, `$SLURM_JOB_ID`, CPU model, `torch.backends.cpu.get_cpu_capability()`, `torch.get_num_threads()`. Never mutate a file that a running job reads.
- **v3-B is the subject, v2 is the object.** Code that any v3-B configuration reaches (every value of `V3B_ARMS`, every `path_weight_input`, `geometry_context: false`, `path_weight_context: true`, `direction_blind_maps`, `map_family` factorized and dense, `path_source` wisp and schemas, NC/LP/GC heads, full batch and mini-batch, the analysis read-outs of spec §6) is **kept**, even when it lives in a v2-named file or class (e.g. `PathTerm`, `HolonomyEdgeTerm`, `PathCellTerm` in `src/models/vertex_path_laplacian.py`; the `endpoints` rung's path in `h2snn_model.py`). Moving kept code to another module is allowed only as a pure move (no edit of its body).
- **Kept by decision, not removed here:** `identity_maps` (A2); the G0b diagnostics `feature_normalization`, `h0_only_readout`, `compute_relation_diagnostics` (G0b is still open, handoff item 8); `no_path_cells`; the baseline data pins in `src/baselines/bundles.py:62-68` (`fact_layer: untied`, `path_sampler: dfs`, `resample_paths: false`, `path_source: schemas`) and the code they need (the `dfs` sampler, the untied fact layer): changing what baselines read is out of scope; every baseline test must pass unchanged.
- Forbidden: changing any v3-B output; loosening tolerances; deleting or skipping a test that exercises kept code; silencing exceptions; editing the spec, cards or the decisions log; overwriting `docs/heads_evidence/v2_golden*.pt`, `docs/partMB_evidence/mb0_reference*.pt` (both stay as history); touching vendor clones or the author's untracked files (`H2S-NN/scripts/slurm/run_use_dataset.sbatch`, `docs/lab-gpu-cluster.html`, the dirty `vendor/H2GB`).
- `H2S-NN/CLAUDE.md` and `H2S-NN/AGENTS.md`: this card authorises one edit (identical text in both): remove or correct statements that name removed settings as options, and add one line "v1/v2 settings are removed (legacy-removal card); a configuration that names one raises".
- Git: one commit per unit, explicit paths; push `legacy-removal` after each unit; never push or move any other branch; never force-push, rebase, amend or stash.

## Units

Then write `docs/legacy_evidence/inventory.md`: one row per legacy item with file:line, what it is (v1/v2 component, which spec version removed it), every reference to it (src, tests, scripts, configs, docs/*.py evidence scripts that tests import), and a class: **delete**, **keep (reason)**, or **unclear**. Start from this list (found by grep at `design-docs` `8c4f1c5`; complete it):
- values: `propagation: chebyshev`; `encoder` (`filter_bank`, `first_order`); `coupling` (`cooperative`, `listen_only`, `symmetric`, `pair_attention`); `path_weight: sigmoid_gamma`; `path_mode: endpoint_edges`; `path_sampler: uniform_instance`;
- keys: `K`, `layer_dropout`, `eta_init`, `gamma_init`, `coupling_gate_init`, `per_side_scale`, `free_path_maps`, `holonomy_edges`, `uniform_path_gate`, `num_label_prop_steps`, `face_sample_k`, `exclude_identity_metapaths`, `metapath_templates`, `overlap_sampling` (check each; `NEVER_TUNED_LEGACY_KEYS`, `config.py:42-49`);
- modules: `src/models/filter_bank.py`, `src/models/pair_attention.py`, the v2 operator in `src/models/vertex_path_laplacian.py` (`VertexPathSheafLaplacian`, `EdgePairTerm`, `FreeIncidenceOperator`, and `src/models/coboundary_ops.py` if only it uses them), `src/analysis/wisp_readouts.delta_loss` (v2 operator; spec §6 says it is not reported), filter-bank diagnostics in `src/trainers/trainer.py` and `link_prediction_trainer.py`, `scripts/analyze_kernel.py` (check);
- configs: every `configs/experiments/*.yaml` without `_v3b` (incl. the removed datasets amazon, amazonbook, youtube);

LR-1 replaces them by a v3-B golden.
An **unclear** item is kept and listed for the author; it is not a stop.

### LR-1 — v3-B golden on the unchanged code (capture before any deletion)
New script `docs/legacy_evidence/v3b_golden.py capture|compare <file.pt>` (same pattern and tensor-diff report as `mb0_reference.py`; prints every differing name; exit 1 on any difference, exit 2 if E or 1 thread is missing). Synthetic fixtures only (reuse `tests/partO_fixtures.py`, `tests/test_wisp.py` fixtures). For each configuration below: evaluation logits, one training step's loss, every parameter gradient, and the solver iteration counts of that forward:
- NC full batch, anchored: each value of `V3B_ARMS` (7); `path_weight_input` ∈ {endpoints, schema, uniform}; `geometry_context: false`; `path_weight_context: true`; `direction_blind_maps`; `map_family: dense`; `identity_maps` with `no_path_cells`; `h0_only_readout`; `path_source: schemas`; IMDB-style multilabel head;
- LP: decoder dot and DistMult (after M3a); GC: each pooling;
- mini-batch: one batch of scopes (NC) and one LP batch with scopes, as in the Part MB tests.
Capture on g2n01 with E and 1 thread → `docs/legacy_evidence/v3b_golden_cluster.pt`; compare on g2n01 again and on g3an01: **expected 0 differences** (CS8 R2). If a configuration cannot be built on the unchanged code, it is left out and reported (not a stop). New test `tests/test_v3b_golden.py` runs the compare (asserts E and 1 thread first, as the CS8 golden tests). Also run `mb0_reference.py compare … mb0_reference_cluster.pt`: `differing: none`.
**Mutation:** change one constant in one arm's code path (e.g. the `covering_only` degree term) → the golden test fails naming that arm's tensors; restore.

### LR-2 — v3-B defaults (no deletion yet)
`ModelConfig` defaults become the v3-B model: `propagation: anchored`, `arm: full`; `encoder`/`coupling` defaults stop selecting a v2 component under `anchored` (state how). Tests or fixtures that relied on the v2 default set the v2 values explicitly (adapt, listed), until LR-3 deletes them. New test: a `ModelConfig` built from an empty model section resolves to the anchored v3-B model. **Gate:** v3-B golden and mb0 compare `differing: none`; targeted tests of the changed files pass. **Mutation:** default back to `chebyshev` → the new test fails.

### LR-3 — Removal and fail-closed
Delete every **delete** item of LR-0 with its tests. Every removed value or key, when present in any configuration (YAML, dict, tuning space), raises `ValueError` naming the setting and "removed by the legacy-removal card (v1/v2)"; `PROPAGATIONS` keeps only `anchored` (the key stays so existing v3-B YAMLs parse). One test per family (removed value; removed key; removed key in a tuning space). **Gate:** v3-B golden and mb0 `differing: none`; every baseline test passes unchanged; targeted tests pass. **Mutations:** remove the raise for one value → its test fails; remove it for one key → its test fails.

### LR-5 — Full suite on two node types, report
`run_tests.sbatch` once on g2n01 and once on g3an01. Expected: the only failure is the notebook check (as CS8-5); test count = CS8's 697 − deleted + added, with both lists in the report. Then stop and wait for the review.

## Stop conditions
Hash mismatch or merge conflict at LR-0; any difference in the v3-B golden or mb0 compare after LR-2, LR-3 or LR-4; a kept item that cannot work without code of a delete item, other than by a pure move (report file:line); a test of kept code that would have to be deleted; a baseline test that changes or fails; a legacy YAML or script that a kept test or script needs; the card is wrong or ambiguous. **Not stop conditions:** unclear items (kept and listed); a configuration that LR-1 cannot build on the unchanged code (left out, reported); a node being down (use the other CPU type and say so).
