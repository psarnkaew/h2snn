### CS7-1 — Environment `h2snn-b`: torch 2.4.1, DGL 2.4.0, torch_householder
**(a) Lock and install script.** Edit `H2S-NN/requirements/linux-lock-b.txt`: remove the dead `-f https://data.dgl.ai/...` line; keep `dgl==2.4.0+cu124` as a check line with the comment "installed by conda from the dglteam package by scripts/setup/install_env_b.sh; pip must not install this line". New `H2S-NN/scripts/setup/install_env_b.sh ENV_NAME DGL_FILE`: (1) `pip install --no-cache-dir` torch from the cu124 index; (2) the PyG extensions from `https://data.pyg.org/whl/torch-2.4.0+cu124.html`; (3) every other line of the lock **except** `dgl` (filtered from the file, not hand-copied); (4) checks `torch.__version__ == "2.4.1+cu124"` and exits 1 otherwise; (5) checks the DGL file's sha256 against the value in the lock comment and exits 1 on a mismatch; (6) `conda install -n ENV_NAME --no-deps --offline DGL_FILE`; (7) `pip check` (output kept, exit code not used). Idempotent; refuses to run without `ENV_NAME`; never touches `h2snn`.
**Tests (unit, no install):** a test that reads the lock: no `data.dgl.ai` line, exactly one `dgl==` line, `hyper-connections==0.4.2` present, `torch==2.4.1`; a test that reads the script: it filters `dgl` from the pip step, checks sha256 before `conda install`, uses `--no-deps`, refuses an empty env name, never names `h2snn` as a target. **Mutations:** the sha256 check removed → the script test fails; `dgl` not filtered → fails.
**(b) Build `h2snn-b`** in one job (CPU node is enough; `--time=2:00:00`, `--mem=16G`): `conda create -n h2snn-b python=3.12 -y`, then the script. Keep the full log. Then `python scripts/setup/check_env.py --lock requirements/linux-lock-b.txt` (expected: 0 differences, notes for local tags only) and `pip freeze > docs/cluster_evidence2/h2snn-b_pip_freeze.txt`; `conda list -n h2snn-b dgl`.
**(c) DGL known-answer checks** (`docs/cluster_evidence2/cs7_dgl_check.py`), one job on a `2080ti` node (sm_75) and one on a `3090` or `a6000` node (sm_86), `python -W default`: print torch, numpy, dgl versions, `dgl.__version__`, `importlib.metadata.version("dgl")`, the paths of the loaded `.so` files (from `/proc/self/maps`); then on `cuda`: (i) a fixed 6-node directed graph with float32 features, `update_all(copy_u, sum)` and `(copy_u, mean)` versus `torch.index_add_` / count division computed in plain torch: `torch.allclose(rtol=1e-6, atol=1e-6)`; (ii) a 3-type heterograph, `multi_update_all` with sum versus the plain-torch sum per relation, same tolerance; (iii) `dgl.nn.GraphConv` and `dgl.nn.GATConv` forward and backward (finite outputs and gradients; GraphConv `norm='none'`, no bias, identity weight, versus the plain-torch sum: same tolerance); (iv) a graph built from a numpy array and from a `scipy.sparse` matrix (numpy 2.4.6, scipy 1.18.0) equals the graph built from torch tensors (`torch.equal` on `edges()`); (v) `import dgl.graphbolt` and `import dgl.sparse` succeed. Also run `src/baselines/runtime/dependencies.py`'s DGL CUDA report and record it. Tolerance 1e-6 is fixed here (float32 sums of ≤ 6 terms).
**(d) torch_householder**: in a job, `TORCH_EXTENSIONS_DIR=~/.cache/torch_extensions/h2snn-b`, `python -c "import torch_householder"` (JIT compile with g++ 14.2 and ninja; record the compile time and the compiler line). Known answer: for random parameters of shape (8, 5) (float64), `torch_householder_orgqr(param)` is orthogonal (`max|QᵀQ − I| < 1e-10`) and equals the product of the 5 reflectors computed in plain torch (`allclose(atol=1e-10)`).
**(e) Re-run the CS5 failures** in one GPU job in `h2snn-b`: `tests.test_baselines`, `tests.test_partP_freebase`, `tests.test_partP_derived_lp`, `tests.test_partPfix_data_root`, `tests.test_check_env`, and the new tests of (a). Report each CS5 row ("dgl", "torch_householder") as pass / still failing with the first error line. A failure of `DglCudaGateTests` caused by how the gate reads the conda build's version string is reported (with `dgl.__version__` and the metadata version), not fixed.
