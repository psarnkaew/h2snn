## Key findings so far (functional, not performance)
- G0: our HGB splits/labels/edges/metric are exact; HetSheaf's code uses a 27/3/70 split and duplicated relations (paper says 24/6/70); HetSheaf is rerun as a baseline, its published numbers are not comparable.
- G0b: untuned H2S-NN fits training nodes from own features early (gates close); hypotheses H1 (h₀ shortcut in head), K, weight decay, per-node ID embedding are **deferred to the cluster**.
- Weight channel `w_f` never yet shown to learn (D12 G3c: oracle 1.0 but learning failed; Part H S1′: oracle was flawed). Transport channel works (S1 solved by every arm) — **but `no_path_cells` also solved S1 (0.996), so S1 is not evidence that cells help**; no known-answer task yet shows cells beating no cells. S1′ (I3) is the direct test.
- WISP sampling: 33/52/30 % of epoch time (gate 25 %), but faster than the old schema sampler; overlap sampling planned in I6. Adaptive proposal: −4.9 % variance → `uniform`; re-measure on the cluster.
- Part I I3: every S1′ arm memorises the 250 training targets by epochs 24–41 (unique noise features on targets); `full` raises all log-weights uniformly (≈ +4.4, path share up to 74 %) with no selection. The "readout without `h₀`" arm does not remove the ego route (filter `k = 0` term `h₀W₀`), so it says nothing about G0b H1. "β ≈ 7–9 needed" is only a sufficient figure; the idealised one-application estimate is e^β ≈ 10 for 0.9 (tested in K2).
- Part I I4: σ\* = `a b c d` and its sibling `a b c e` are lifted together (×8.5–11) on 2 seeds; seed 42 lifted `f g h k` first. The length-3 prefix `a b c` (same M3) is not lifted, so a shared-node route does not explain it; tested in Part K K2b (1,000 training targets).
- Pattern: four synthetic misses (H5 oracle, H5 S2 length confound, I3 reach and memorisation, I4 siblings) came from test design, not the model → spec §0 rule 6 (reachability + information-route audit).
