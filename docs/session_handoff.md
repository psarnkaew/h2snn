- G0b: untuned H2S-NN fits training nodes from own features early (gates close); hypotheses H1 (h₀ shortcut in head), K, weight decay, per-node ID embedding are **deferred to the cluster**.
- Weight channel `w_f` never yet shown to learn (D12 G3c: oracle 1.0 but learning failed; Part H S1′: oracle was flawed). Transport channel works (S1 solved by every arm) — **but `no_path_cells` also solved S1 (0.996), so S1 is not evidence that cells help**; no known-answer task yet shows cells beating no cells. S1′ (I3) is the direct test.
- WISP sampling: 33/52/30 % of epoch time (gate 25 %), but faster than the old schema sampler; overlap sampling planned in I6. Adaptive proposal: −4.9 % variance → `uniform`; re-measure on the cluster.
- Part I I3: every S1′ arm memorises the 250 training targets by epochs 24–41 (unique noise features on targets); `full` raises all log-weights uniformly (≈ +4.4, path share up to 74 %) with no selection. The "readout without `h₀`" arm does not remove the ego route (filter `k = 0` term `h₀W₀`), so it says nothing about G0b H1. ## Mini-batch design brief (for the next session; written 2026-11-09 21:50 JST by the review session)
Start here when designing the mini-batch card. Nothing below is decided except where marked "author"; discuss with the author before writing it into the spec.

**Why it is needed.** Spec v1.8 §6 (F3): ogbn-mag, mag-year, H-Pokec (and IEEE-CIS-G if full batch does not fit) need mini-batch training; R7 requires that "a mini-batch is a restriction of the same model"; Lemma R (§4): a batch is a closed subcomplex, its operator is the restriction, Props. 2–7 hold on it; equality with full batch only if the batch covers the receptive field.

**Facts checked in code (2026-11-09).**
- Node-classification training is full-batch only; there is no mini-batch code in `src/` (only baseline adapters mention minibatches).
- The WISP sampler already takes an arbitrary anchor subset: `sample_wisp_walks(graph, node_type, anchors, walks_per_anchor, max_length, generator, …)` (`src/data/wisp_sampler.py:141`), `build_wisp_path_groups(…, anchors, …)` (`:326`).
- Receptive field: one application of `A` reaches one fact or a whole cell (up to `ℓ_max = 4` hops); the filter applies `A` K times (K = 4 in the configs, OPEN-4 undecided), so the field can reach ~K·ℓ_max = 16 hops — essentially the whole graph. Exact full-batch equality is impossible on the large graphs; any mini-batch is an approximation or a redefinition, stated in the paper.
- Stability with any degree choice (DERIVED, check numerically): for the batch subcomplex, `L_sub ≼ 2 D_sub ≼ 2 D'` for any diagonal `D' ≥ D_sub` (e.g. full-graph degrees), so `λ_max(D'^{-1/2} L_sub D'^{-1/2}) ≤ 2` and Prop. 5's gain bound still holds.

**Options discussed (author leaning: A, 2026-11-09).**
| | How | For | Against |
|---|---|---|---|
| **A. Local scope** (ShaDow-GNN-style) | batch = target anchors + their WISP cells (drawn from the stated target `p`, unbiased per anchor) + their 1-hop facts (+ facts among batch nodes); run the same model on that subcomplex; the same rule at train and evaluation | WISP stays unbiased; Lemma R applies; train/test consistent; testable locally | everything beyond the scope is cut |
| B. Layer-wise neighbour sampling (GraphSAGE) | sample per hop | standard | does not fit one operator applied K times |
| C. Graph partition (Cluster-GCN) | METIS clusters | memory | walks crossing clusters are lost → WISP's target measure is biased (violates R8) |
| D. No mini-batch | full graph on a large GPU | exact | may not fit (maps alone ≈ 10 GB on ogbn-mag, UNVERIFIED estimate) |
Plan (author agreed in principle): implement A locally now (8 GB RTX 4060); on TSUBAME measure memory, use full batch where it fits, A elsewhere; the paper states which per dataset.

**Open questions for the design discussion.**
1. Degrees: `D` of the subcomplex itself vs full-graph fact degrees (+ how the path part of `D` is defined for non-anchor nodes, whose own cells are not in the batch).
2. Scope depth: 1-hop facts only, or more; how it interacts with K (decide OPEN-4 first or together).
3. Evaluation rule: the same local-scope procedure with the fixed evaluation draw (base seed), per target batch.
4. Batch composition and size; anchors per batch; memory model per batch.
5. Validation (pre-registered): batch = whole graph ⇒ bit-identical to full batch; Lemma R tests (restriction = subcomplex operator; spectrum/gain bounds with the chosen `D`); memory/time scaling (C5 slopes); on the cluster, mini-batch vs full batch on ACM/DBLP within 1 std (C5).
6. First unit of the card: spec v1.7 E14 (`r` is 0 or the calibrated value in every config, for datasets with a calibrated table).
7. Link prediction anchors in batches: later (LP card), but keep the interface general.
