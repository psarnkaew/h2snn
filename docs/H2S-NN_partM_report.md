## M4 — WISP on every task (J1)

**Done.**
- New `src/data/wisp_tasks.py`: `link_prediction_anchors` (every node of the target relation's head type and tail type; one range when they are equal), `build_link_wisp_path_groups` (one WISP draw on the message graph from those anchors), `build_graph_wisp_path_groups` (every node of each graph is an anchor; each graph is drawn alone with its own action graph and a generator seeded `draw_seed · 2^24 + graph_id`, then all walks are merged by D8 identity; cells never cross graphs, so a graph's cells do not depend on its batch), `require_walks_per_anchor`.
- `link_prediction_dataset.build_link_path_groups` (was `build_free_path_groups(length=2)` at `:914`): WISP under `path_source: wisp`; the pinned DFS row only under `path_source: schemas` + `path_sampler: dfs` (baseline bundles, whose adapters never read cells); the length-2 walk branch is removed and raises. The loader still runs `assert_no_held_out_facts` on the evaluation draw. `LinkPredictionTrainer.training_draw` resamples with `seed + epoch` through the same function.
- `GraphClassificationTrainer.batch_path_groups` (was `:203`): WISP per graph; same DFS/raise rule. Evaluation draw seed = run seed for every epoch (`draw_seed`), training = `seed + epoch` under `resample_paths`.
- Config (`DataConfig.resolved`): unset `path_source` resolves to `wisp` for every task (was `schemas` for LP/GC); the "wisp is node classification only" error is removed. `ℓ_max` and `r` are read from the config. NC keeps the calibrated table for `r = 0`; LP/GC have no table, so `r = 0` (unset) is allowed at config load (data-only uses: negatives, validation files, the M1 gate) and a draw with `r` unset raises (`require_walks_per_anchor`). No calibrated-`r` enforcement for LP/GC.
- Model dims: `build_link_prediction_model` and the GC fold's `ModelDims` get `face_lengths = 2..ℓ_max` and `path_actions` under WISP (as NC).
- **Deviation (reported, small):** the LP and GC trainers now pass `epoch` to `model.encode` for training forwards and `-1` for evaluation, as the NC trainer does. Before, LP/GC solves always used the final tolerance 1e-4, so the fixed schedule of spec §6 (1e-3 for the first 10 epochs, then 1e-4; evaluation 1e-4) did not apply to them. This implements the fixed schedule; nothing about the solver changed.

## M5 — GC protocol and readout (J6, spec §6 GC)

**Done.**
- Readout (`src/models/graph_readout.py`): `[x*, h0]` → pooling ∈ {mean, max, add, attention} → **one** `Linear(2d, C)`; BatchNorm and the MLP are removed. `attention` is a port of HetSheaf's `AttentionPooling` (`hetsheaf/graph_classification/pooling.py`, commit `6964e1e`: Linear(h, h) → Tanh → Linear(h, heads, bias=False), per-graph softmax, 2 heads averaged, as `GraphClassifier` builds it). New `model.graph_pooling` (default `mean`; `GRAPH_POOLINGS` in `config.py`). The GC head no longer reads `classifier_hidden_dim` or `classifier_dropout`.
- Protocol (`src/data/graph_classification_dataset.py`, `config.py`): new `split_protocol: hetsheaf_random` = HetSheaf's `torch.randperm(n, Generator().manual_seed(42))`, train `perm[:int(0.8n)]`, validation the next `int(0.1n)`, test the rest (`hetsheaf/datasets/graph_classification.py:240-251`), the same for every training seed; the four TU presets now use it with `split_seed 42` (the stratified/CV protocols stay as legacy options). Node features are replaced by the constant 1 (`constant_node_features`). New `data.graph_batch_size` (default 1; train shuffled, val/test not, as HetSheaf's loaders). TU still through PyG `TUDataset` with `use_node_attr=False`.
- Node types: the existing code reads the raw TU label file and compacts it. VERIFIED-RUN (scratch check, then a permanent test): on MUTAG, PROTEINS, ENZYMES and NCI1 these types are **identical** to HetSheaf's argmax of the one-hot label columns (types 7 / 3 / 3 / 37), and MUTAG's 4 bond types equal the edge-attribute argmax; the code was therefore kept.
- Trainer (`GraphClassificationTrainer.fit`): early stopping on the **validation loss** (strict improvement, patience `early_stopping_patience`; the GC value 50 is set in M9's budget); the reported record (`best_test_metrics_run{i}.json`) is the **final weights'** epoch, with its validation Macro-F1 (what selects configurations); `best.pt` is still written by `checkpoint_metric` as an artifact and its epoch is recorded (`best_checkpoint_epoch`). Epochs stay configurable (open O4: 200 vs 500).

**Tests (VERIFIED-RUN).** New `tests/test_gc_protocol.py` (8 tests): mean/max/add pooling by hand; attention pooling against a hand computation (tanh scores, per-graph softmax, two heads averaged); the readout is pooling then one Linear (no BatchNorm, train and eval outputs equal, output = `decoder(pool(x))`); `graph_pooling` values and rejection; on real MUTAG: the split equals `randperm(188, seed 42)` order for training seeds 0 and 3 (test set 20 graphs), batch size 1 on all loaders, constant feature 1, `in_channels` 1; node and edge types equal the one-hot argmax on all four TU datasets; early stopping on validation loss with the final weights reported.
- `tests/test_graph_classification_trainer.py`: its one test asserted the replaced protocol (stop on validation AUROC, report the best epoch); it now checks the new one (stop on validation loss, report the final weights, `best.pt` epoch still by AUROC).
