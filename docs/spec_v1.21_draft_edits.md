## V-1 §6 Baselines — HetSheaf and H2G-former after Part P
**Insert after:** `Supersedes the adapter's restriction to `Hetero_Raw` (`src/baselines/adapters/h2gformer.py:19-25`).`
> (1.21, author) **HetSheaf** (code `vendor/Heterogeneous-Sheaf-Neural-Networks` at `6964e1e`; Part P P0) is **one row**, as its paper's main tables report one "HetSheaf" row chosen by sweeps over restriction-map families: the map family (diag, bundle, general, attention, poly) and the sheaf learner are tuned as categoricals inside the shared 100-trial budget. Its code is run **as written**, with these stated points: the shared protocol replaces its optimizer settings (AdamW with the shared `lr`/weight-decay/dropout axes; no `CosineAnnealingLR`; its LP and GC scripts never pass the swept `lr`/weight decay to the model, and `initial_dropout`/`output_dim` have no effect in its code); its data transforms are applied except those that would change shared splits (`SubsetTrainSplit`, `datasets/hgb.py:55`, and its own LP and GC splits are not applied); the per-type input projection, NC L2 normalisation and LP JKNet that its paper describes are absent from its code and are not added. Graph classification uses its own readouts, including `late_token` (SheafPool), which its main GC row uses (the readout is part of its method). **H2G-former details:** IMDB has no label channel (H2GB's `Hetero_Label` encoder takes one label per node, `hetero_label_encoder.py:49-59`; IMDB is multi-label); width `hidden_dim` ∈ {64, 128, 256, 512} and, when the MetaPath2Vec channel is on, `dim_pe = min(128, hidden_dim/2)` (H2GB's configs: 64/32 on PDNS, 256/128 and 512/128 elsewhere), so no combination is invalid; node types that no listed meta-path visits get a zero positional encoding; MetaPath2Vec is pretrained with H2GB's `SparseAdam` (lr 0.01), a stated exception to AdamW, which governs the training of every model, not the preprocessing of input encodings (AdamW does not accept sparse gradients).
