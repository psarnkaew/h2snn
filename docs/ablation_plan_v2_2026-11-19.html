คำถาม 3

Meta-path เกี่ยวกับ heterophily ไหม และ sampler เรียนรู้ meta-path ที่มีความหมายไหม

คำนวณจาก run หลัก (seed 0–4) และ run ของ full ใน ablation (seed 1–10) ไม่ต้องเทรนเพิ่ม ทุก face มี schema เป็นป้ายกำกับ เช่น PAP จึงรวมผลตาม schema ได้

c_σ = coverage : ส่วนของมวล face ที่ sampler สุ่มได้ใน schema σ (ถ้าทุก w_f = 1) I_σ = learned : ส่วนของมวลหลังใช้น้ำหนักที่เรียนได้ w_f ρ_σ = I_σ / c_σ : > 1 แปลว่าโมเดลให้น้ำหนัก σ มากกว่าความถี่ที่ถูกสุ่ม

รูปที่ได้ (ต่อ dataset)

  • Bar ของ schema ยาว 2 ที่มี coverage ≥ 1 % ไม่เกิน 10 อัน เรียงตาม ρ_σ
  • Scatter ของ coverage เทียบกับ learned share (เส้นทแยงคือ "แค่สุ่มตามความถี่")
  • Meta-path ใน HGB ที่ตีพิมพ์แล้วได้ ρ_σ > 1 ไหม

การทดสอบ

  • "เรียนได้ ไม่ใช่สุ่ม": ranking ของ ρ_σ เสถียรข้าม seed ใช้ค่าเฉลี่ย Kendall τ-b ≥ 0.5 กับ permutation test (p < 0.05, Holm m = 4) และรายงาน τ ของ c_σ คู่กัน เพื่อแสดงว่าความเสถียรไม่ได้มาจาก coverage อย่างเดียว
  • เกี่ยวกับ heterophily: Spearman ระหว่าง ρ_σ กับ homophily ของกราฟที่ σ สร้าง ค่าบวกแปลว่าโมเดลชอบ schema ที่ homophilic ค่าใกล้ศูนย์แปลว่า transport จัดการ schema ที่ heterophilic เอง
คำถาม 4

โมเดลเกี่ยวกับระดับ heterophily ไหม และ robust เมื่อ heterophily เปลี่ยนไหม

Perturbation study แบบ semi-synthetic: ใช้กราฟจริงแล้วเปลี่ยนแค่ระดับ heterophily ไปที่เป้าหมาย 20 / 40 / 60 / 80 % (heterophily = 1 − MLH บน meta-path ความยาว 2)

ขั้นทำอย่างไร
กราฟACM (ตอนนี้ heterophily ≈ 40 %) และ DBLP (≈ 13 %) เป็น single-label และ label ครบ ส่วน IMDB เป็นทางเลือก (multi-label ใช้ค่าเฉลี่ยต่อ genre)
เพิ่ม heterophilyเพิ่ม edge เฉพาะ relation ที่มีอยู่จริง (เช่น paper–author) ที่ทำให้เกิดคู่ meta-path ต่าง class และสุ่มปลายแบบสม่ำเสมอจาก class อื่นทั้งหมด edge ใหม่จึงบอกได้แค่ว่า "ไม่ใช่ class เดียวกัน" ไม่ได้ชี้ไป class ใด
ลด heterophilyตัด edge ที่สร้างคู่ต่าง class ได้ไม่เกิน 50 % ของ relation ห้ามเพิ่ม edge ระหว่าง node class เดียวกัน เพราะเท่ากับเอา test label ไปสร้างกราฟ ซึ่งทำให้ทุกโมเดลดูดีขึ้นจากการรั่ว
Controlทุกระดับมีกราฟคู่ที่เพิ่มหรือตัด edge จำนวนเท่ากันแบบสุ่ม ผลของ heterophily = ผลบนกราฟตามเป้า − ผลบนกราฟสุ่ม
MethodH2S-NN full และ no_path_cells กับ GCN, HAN, SeHGNN, Hetero²Net และ HetSheaf ใช้ config จากกราฟเดิม (ถ้า baseline ยังไม่ได้ tune เองให้ใช้ config ที่ตีพิมพ์ไว้ และบอกในเปเปอร์) ไม่ tune ใหม่ และ 5 seed
ที่คาดไว้ (ตั้งไว้ก่อนรัน)H2S-NN เสียความแม่นน้อยกว่า GCN, HAN และ SeHGNN เมื่อ heterophily สูงขึ้น และ full − no_path_cells โตขึ้นตาม heterophily ถ้าไม่เป็นตามนี้ก็รายงานตามจริงและไม่เคลมเรื่อง robustness
ระดับที่ไปไม่ถึงจะรายงานตามจริง เช่น ACM อาจลงไม่ถึง 20 % เพราะติดเพดานการตัด เราจะไม่ขยายเพดาน 50 % หลังเห็นผล ในเปเปอร์จะเขียนว่าเป็นกราฟ semi-synthetic และเทียบ curve ระหว่าง method เท่านั้น ไม่เทียบกับตารางหลัก

Face effect: face เปลี่ยน embedding จนทำนายถูกได้อย่างไร

ตอบประโยคของอาจารย์ "edge แบบ heterophilic สร้าง face แล้ว embedding เปลี่ยนจนทำนายถูก" จากเชิงคุณภาพไปเป็นเชิงปริมาณและเชิงเหตุผล ใช้ checkpoint ของ full และ no_path_cells บน 4 dataset และ seed 1–10

ส่วนทำอะไรได้อะไร
F1 ใครถูกแก้เทียบ full กับ no_path_cells ทุก test node ใน seed เดียวกัน นับ node ที่เปลี่ยนจากผิดเป็นถูกและจากถูกเป็นผิด แยกเป็น 4 ช่วงตาม η_v (สัดส่วนเพื่อนบ้านทาง meta-path ที่ label ต่าง)face แก้ node ที่ heterophilic ได้มากกว่าไหม
F2 embedding เปลี่ยนอย่างไรmargin = ระยะจาก x* ไปจุดศูนย์กลางของ class อื่นที่ใกล้ที่สุด − ระยะไปจุดศูนย์กลางของ class ตัวเอง เทียบแบบมี face กับไม่มี face ตาม η_vface ดัน embedding เข้าหา class ที่ถูกไหม และดันมากขึ้นใน node ที่ heterophilic ไหม
F3 ปิด face ทีละ node (causal)ใช้ full ที่เทรนแล้ว ตอน evaluate ให้ β_f = 0 เฉพาะ face ที่ผ่าน node นั้น แล้วดูว่าคำทำนายกลับไปผิดไหม และ margin หายไปเท่าไร ไม่ต้องเทรนใหม่face เป็นเหตุที่ทำให้ทำนายถูก ไม่ใช่แค่สัมพันธ์กัน

รูป case study: เลือก node ด้วยกฎตายตัว

  • ACM, seed 1
  • เลือกจาก test node ที่มี edge ตรงไปหาเพื่อนบ้านต่าง class และใน F3 การปิด face ทำให้ทำนายผิด
  • ในกลุ่มนั้นเลือก node ที่ margin ลดลงมากที่สุดเมื่อปิด face ถ้าเสมอกันให้เลือก id ที่น้อยกว่า
  • เลือกด้วยกฎ ไม่ได้เลือกด้วยมือ

สิ่งที่แสดงในรูป

  • Edge ไปหาเพื่อนบ้านต่าง class และ face 3 อันที่น้ำหนัก w_f สูงสุด พร้อม node ตรงกลาง
  • Embedding 2 มิติ (PCA ที่ fit บน x* ของ test ทั้งหมด): h₀, x* ตอนปิด face และ x* ของ full พร้อมจุดศูนย์กลางของแต่ละ class
  • ความน่าจะเป็นของ class ที่ถูก ตอนปิด face เทียบกับตอนเปิด

รูปนี้ใช้แทน Fig. 1 ที่อาจารย์และ lab บอกว่าซับซ้อนได้ F3 ต้องมี hook ใน src/ สำหรับปิด face ที่เลือกตอน evaluate อย่างเดียว จึงต้องเข้า card 5

Two-regime analysis: โมเดลเดียวใช้ได้ทั้ง homophily และ heterophily โดยไม่ดูแค่ตัวเลข

อาจารย์ขอสามอย่างในการประชุม คือ proof, energy ที่สัมพันธ์กับ performance และ representation และการแสดงที่ไม่ใช่แค่ตัวเลข ส่วนนี้รวมทั้งสามอย่างเข้าด้วยกัน ทฤษฎีบอกว่าโมเดลมีสองโหมด analysis แสดงว่าโมเดลที่เทรนแล้วเลือกโหมดตาม edge จริง

ทฤษฎี (เขียนในเปเปอร์ ไม่ต้องรัน): proposition "ใช้ได้ทั้งสองแบบ"

  • Homophily: เมื่อ Q_e = I สมการ solve กลายเป็น personalized PageRank คือ smoothing ตามปกติ และ h₀ ที่สอดคล้องกันเป็น fixed point (Thm 6)
  • Heterophily: สำหรับ labelling ใด ๆ มี maps ที่ทำให้ node ต่าง class สอดคล้องกันโดยไม่ต้องเท่ากัน และแยก class ได้ด้วย linear classifier บน x* (Thm 4)
E(x*) = sheaf energy ของ solution e_v = ส่วนของ E ที่แตะ node v Ẽ = E(x*) / ‖x*‖² θ_e = มุมหมุนของ transport Q_e (‖Q_e − I‖)
ส่วนวัดอะไรถ้าเป็นตามทฤษฎีจะเห็น
R1 transportθ_e ต่อ edge แยกตามปลายสองข้างเป็น class เดียวกันหรือต่าง class (เฉพาะ edge ที่ปลายมี label) พร้อม τ ที่เรียนได้ต่อ datasetedge แบบ homophilic มี Q_e ใกล้ I (smoothing) ส่วน edge แบบ heterophilic หมุนมากกว่า โมเดลเดียวเลือกเองว่าจะ smooth หรือหมุน
R2 energy กับ performancee_v ของ node ที่ทำนายถูกเทียบกับที่ผิด (AUROC) และ Spearman ระหว่าง e_v กับ η_venergy ต่ำสัมพันธ์กับการทำนายถูก และ node ที่ heterophilic ยังได้ energy ต่ำได้ ซึ่งแปลว่า "ต่างแต่สอดคล้อง"
R3 energy กับ representationfull เทียบกับ S2 (maps = I): Ẽ และความแยกกันของ class (linear probe และอัตราส่วนระยะในและข้าม class) บน x* เทียบกับบน h₀ฝั่ง homophilic ทั้งสองโมเดลแยก class บน x* ได้ดีกว่า h₀ ส่วนฝั่ง heterophilic full ยังแยกได้แต่ S2 ปน class ซึ่งตอบตรง ๆ ว่า "diffusion ละลายข้อมูลไหม"

ทำบนสองแกน: (1) ข้าม node ตาม η_v ใน 4 dataset และ (2) ข้ามระดับของกราฟ 20/40/60/80 % จาก perturbation จึงเห็นกลไกเปลี่ยนต่อเนื่อง ไม่ได้เห็นแค่สองจุดปลาย

R1 ต้องอ่าน Q_e จากโมเดลที่เทรนแล้ว และ R2/R3 ต้องอ่าน e_v ทั้งสองอย่างเป็น hook แบบอ่านอย่างเดียวที่ต้องเข้า card 5
