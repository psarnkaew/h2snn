# Task card — Baselines on the H2GB datasets: adapters for the 8 NC datasets and the 2 large LP tasks, PDNS loader, Hetero²Net MAG embeddings, on the lab cluster

**Design authority:** spec **v1.22** §6 (baselines, protocol); `docs/minibatch_design_v3B.md` (MB2 batch range and epoch, MB3 evaluation on whole splits, MB4 large LP, §7 what H2GB's code does, §13 "their own samplers stay"); decisions log rows "Part M3b review" (2026-11-16, author decisions 1–7) and "Part P review" (D-P3, D-P6, D-P9: H2G-former); `docs/H2S-NN_partM3b_report.md` and `docs/partM3b_evidence/` (`b7_metapaths.md`, `b8_budget_and_cells.md`, `pdns_protocol.md`). `H2S-NN/AGENTS.md`/`CLAUDE.md` bind for environment, coding, testing, evidence tags. `docs/working_preferences.md` binds for the cluster and git, and for **"follow the source's code exactly"** (every deviation is a stated decision with the source's file:line).
**Branch:** `baselines-h2gb`, created from `v3b` at the SHA given in the prompt, then `git merge --no-ff` of the pinned `design-docs` SHA (a conflict is a stop). **Report:** `docs/H2S-NN_baselines_h2gb_report.md`; evidence `docs/baselines_h2gb_evidence/`.

## Goal
Every baseline cell on the eight H2GB NC datasets and the two large LP tasks either runs under the shared protocol (budget table of Part M3b B8: batch range `{32, 256, 1024}`, 1 epoch = 8,192 training targets, 500 epochs, no early stopping, best validation epoch, evaluation on whole splits in batches; large LP: 8,192 positives per step, 40 epochs, patience 40) with its mini-batch scheme fixed below, or carries a stated reason. **Correctness only:** synthetic-graph tests, mutation checks, the full suite. No training run on real data, no metric reported as a result, no comparison between methods.

## The mini-batch scheme of each baseline (rule; author decisions D1–D2 in the prompt)
Principle (mini-batch design §13): a method's own sampler is part of the method and stays. Three classes, from the vendor code (VERIFIED-CODE by the design session, 2026-11-16; the agent re-checks each file:line in C0 and stops on a difference):

| Class | Methods | Scheme |
|---|---|---|
| **A — H2GB benchmarks the method with its own configs** | GCN, GAT, HAN, H2G-former | H2GB's `hgt` sampler with the fan-out of H2GB's config of that method and dataset (`vendor/H2GB/configs/<dataset>/<dataset>-<Method>.yaml`: e.g. ogbn-mag/mag-year 512 per hop, OAG and IEEE-CIS 64, PDNS 256, Pokec `neighbor_sizes_dict`), sampler depth = the method's number of layers (tuned value; H2GB's per-hop fan-out repeated) |
| **B — the method's source has its own large-graph code** | SeHGNN (`SeHGNN/ogbn/main.py`: precomputed propagated features, batches of targets), PSHGCN (`PSHGCN/ogbn-mag/main.py:36-87`: same), ChebNetII (`ChebNetII/ogb/large_train.py`: precomputed polynomial bases, batches), Hetero²Net (`Hetero2Net/main.py:64, 147-170`: PyG `NeighborLoader` on MAG/RCDD), HINormer (its per-node context sequences: batches of targets) | the source's own scheme; only the batch size (from the shared range) and the epoch length (8,192 targets) are imposed. Where the source has a second stage the shared protocol does not have (e.g. SeHGNN/PSHGCN label-propagation "enhance" stages, `PSHGCN/ogbn-mag/main.py:78-87`), keep what the HGB adapters already keep and state it |
| **C — no mini-batch scheme in the source** | NSD, CSNN, H2SGNN | **D1:** if the method's forward is node-wise on precomputed features (check H2SGNN: decoupled propagation), batches of targets on the precomputed features (exact; like class B); otherwise H2GB's `hgt` sampler with the dataset's H2GB fan-out (the GCN config of that dataset) and depth = the method's layers, as H2GB itself runs full-batch methods; a stated deviation |

Exceptions decided by the author (2026-11-16): SeHGNN on H-Pokec = N/A ("out of memory under its own code", reason in the registry, no run); PSHGCN on H-Pokec: search range restricted to `K = 1`, `hidden ≤ 64` (a per-dataset override in `search_grids.py`, stated in the paper; every other range unchanged).

**Large LP (D2):** class A and C message-passing methods use link-level neighbour sampling (as PyG `LinkNeighborLoader`: the endpoints of the step's links as seeds, the class's fan-out and depth) on the **message graph of the task** (held-out facts removed in both orientations, Part M3b B6 files); decoupled methods (PSHGCN, H2SGNN where node-wise) compute per-node features once on the message graph and batch the links. Decoder, negatives, budgets as the six local LP tasks and spec §6. Methods without LP in their source keep their "no link prediction implementation" reason.

## Units (in this order; a unit that stops is reported and the next independent unit starts)

### C0 — Preconditions (no code)
Read the documents above, `src/baselines/` (registry, budget, `training.py`, every adapter named above and its `_lp` module), `src/data/h2gb_nc.py` and the large-LP builder of Part M3b, the vendor files of the scheme table. Record per method (table, file:line): its class, the exact sampler or batching code in its source, the layer-count parameter that sets the sampler depth, what the adapter does today on HGB, and what changes. A file:line that contradicts the scheme table is a stop (card error). Create the branch.

### C1 — Shared mini-batch infrastructure for baselines
One module (e.g. `src/baselines/minibatch.py`) that every adapter uses: `batch_plan` from the budget table (steps per epoch = 8,192 / B, loss mean over the B targets of a step), H2GB's `hgt` sampler called through H2GB's code with a fan-out read from H2GB's YAML (parsed, never retyped), evaluation over the whole validation/test split in batches with a fixed order, best-validation-epoch selection, evaluation every `eval_period` epochs as the budget table says. AdamW, no scheduler, no clipping (M9) unchanged.
**Tests:** steps per epoch for each B; fan-outs equal H2GB's YAML for every (class-A method, dataset) pair; evaluation covers every node of the split exactly once; **full-fan-out equivalence:** on a synthetic heterogeneous graph, a class-A model (GCN and HAN) with fan-out = all neighbours and depth = its layers gives the same target outputs as its full-batch forward (float64, `atol 1e-10`, fixed in advance), with a negative control (fan-out 1 differs). **Mutation:** evaluation drops the last partial batch → the coverage test fails.

### C2 — PDNS loader (author decision 1)
Following H2GB's code exactly (`pdns_dataset.py`, `master_loader.py:604-617`, Part M3b `pdns_protocol.md`): one graph over windows 0–59, `ToUndirected`, labels from `domains2.csv`, random 70/20/10 split by `torch.randperm` after seeding the run seed as H2GB does (`H2GB/main.py:87-100`), loaded from `raw/` each time (H2GB has no processed file). The split is recorded per seed (sizes, class counts, a checksum of the index sets). The PDNS NC cell of H2S-NN and of every adapter leaves "data pending".
**Tests (synthetic fixture with H2GB's file layout):** split sizes 70/20/10; the split is a function of the seed only (same seed → identical, different seed → different); equals calling H2GB's own code on the fixture. **Real-data check (job):** seed 0 counts equal Part M3b `b5_pdns_check.json`.

### C3 — Class-A adapters: GCN, GAT, HAN, H2G-former (NC)
Each reads the B2/C2 bundle and trains through C1 with its H2GB fan-out. H2G-former runs H2GB's own encoder stack per dataset as H2GB's configs (D-P3: H2GB datasets exactly as H2GB's configs, label channel training labels only, MetaPath2Vec `dim_pe` per D-P6, `SparseAdam` for MetaPath2Vec pretraining per D-P9). HAN on H2GB uses raw relations as H2GB's HAN (`hetero_gnn_model.py:128`; no predefined meta-path list on H2GB, decisions log 2026-11-13).
**Tests:** per adapter, on a synthetic graph: forward and backward finite, parameters move in one step, every parameter receives a gradient; batch independence in eval mode (a target's output does not depend on the other targets of its batch under a fixed sampler seed); the label channel of H2G-former reads training labels only (route test: permuting validation/test labels does not change any output). **Mutation:** H2G-former's label channel reads all labels → the route test fails.

### C4 — Class-B adapters: SeHGNN, PSHGCN, ChebNetII, Hetero²Net, HINormer (NC)
The source's own batching (scheme table), batch size and epoch length from C1. SeHGNN H-Pokec: N/A reason. PSHGCN H-Pokec: the per-dataset search-space override. **Hetero²Net on ogbn-mag/mag-year (author decision 2):** PyG `OGB_MAG(preprocess='metapath2vec')` embeddings for author, institution, field, as its MAG branch (`hetero2net/dataset.py:54-56`); paper features from the B2 loader (identical, Part M3b B7). Read PyG's `OGB_MAG` source in `h2snn-b` and write in the report the exact URL, file name and the path under `data/NC/mag/` where the file must be placed; the author downloads it. Until the file is there the two cells say "waiting for `mag_metapath2vec_emb.zip` (author download)"; this is not a stop. The loader checks the file's sha256 against the value recorded at first use and refuses a different file.
**Tests:** per adapter as C3 (finite, moves, gradients, batch independence); for the precomputed-feature methods (SeHGNN, PSHGCN, ChebNetII): the precomputed features of a target equal the full-graph precomputation (float64, `atol 1e-10`), and batching over targets is exact against the full forward; the PSHGCN override is in the generated sweep for H-Pokec only. **Mutation:** the SeHGNN H-Pokec cell made runnable → the registry test fails.

### C5 — Class-C adapters: NSD, CSNN, H2SGNN (NC; author decision D1)
Record for H2SGNN whether its forward is node-wise on precomputed features (file:line); apply the D1 rule. NSD/CSNN on H2GB's `hgt` sampler as the rule says; their homogeneous conversion as on HGB.
**Tests:** as C3; for a node-wise H2SGNN the exactness test of C4; for NSD/CSNN the full-fan-out equivalence of C1.

### C6 — Large LP adapters (D2): GCN, GAT, NSD, CSNN, HAN, PSHGCN, H2G-former, Hetero²Net, H2SGNN
Read the B6 split and negative files; link-level sampling on the task's message graph (or per-node precomputation for decoupled methods); decoder and budgets as the local LP tasks; evaluation on all validation/test links, node computations shared across links of an evaluation.
**Tests:** on a synthetic LP task with a known held-out set: no held-out fact (either orientation) in any sampled subgraph or precomputed feature (`assert_no_held_out_facts`); full-fan-out equivalence with the full-graph LP forward for GCN (float64 `atol 1e-10`) with negative control; the task's negatives are read from the files (not drawn). **Mutation:** sampling on the full graph instead of the message graph → the held-out test fails.

## Rules and stop conditions
- **Git:** one commit per unit, explicit paths, tests with the change; push `baselines-h2gb` after each unit; never push or move `v3b`, `design-docs` or any other branch; never force-push, rebase, amend, stash or reset. Never stage `data/`, `Claude outputs/`, `H2S-NN/paper/`, vendor clones, `docs/lab-gpu-cluster.html`. Gate on the commit being gated (an export is allowed; remove scratch exports at the end or list their path).
- **Forbidden:** loosening tolerances, deleting or skipping tests, silencing exceptions, special-casing inputs, editing the spec, the cards or vendor code, downloading data, changing a baseline's model code beyond what its mini-batch scheme needs (state every line changed in a model file).
- **Stop (the unit):** a vendor file:line contradicts the scheme table; a method's own scheme cannot be reached without editing its model; full-fan-out or exactness equivalence fails (report the first differing tensor; do not loosen); any full-batch output or HGB/local-LP/GC baseline output changes; a held-out fact reaches a sampled subgraph.
- **Not stop conditions:** missing Hetero²Net embedding file (the cells wait); memory or time of a job; any loss or metric value (none is reported).
