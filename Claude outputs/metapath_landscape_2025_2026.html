H2S-NN · literature review · 10 พฤศจิกายน 2026

งาน Meta-path บน Heterogeneous Graph ปี 2025–2026 และตำแหน่งของ H2S-NN

สรุปจากการเปิดอ่านเปเปอร์ 30 ชิ้น (ส่วนใหญ่ปี 2025–2026) ว่าแต่ละงานใช้ meta-path อย่างไร ใช้โหนดกลางของเส้นทางหรือไม่ และมีอะไรที่ทับกับ H2S-NN บ้าง เขียนจากมุมของ reviewer ที่ไม่เข้าข้างงานเรา

ขอบเขต: node classification เป็นหลักระดับการอ่านระบุทุกแถวยังไม่มีผลการทดลองของ H2S-NN ในหน้านี้
สรุปสั้น

สิ่งที่ต้องรู้ก่อนอ่านตาราง

  • ความเสี่ยงสูงตัวเข้ารหัส instance ของ MAGNN มีสูตรเดียวกับสถานะ cell ของเราเมื่อการหมุนขึ้นกับชนิดความสัมพันธ์อย่างเดียว ผลต่างที่ตรวจด้วยตัวเลขคือ 1.2×10⁻¹⁶ reviewer จะเห็นสิ่งนี้
  • ความเสี่ยงสูงRGCN ที่ tune ดี ๆ ชนะ HGNN ส่วนใหญ่งานปี 2025 ทำซ้ำ 20 โมเดลบน 21 ชุดข้อมูล สรุปว่าข้อมูลหลายชนิดช่วย แต่สถาปัตยกรรมไม่ช่วย
  • ต้องลดข้ออ้างการใช้โหนดกลางต่อ instance ไม่ใหม่MAGNN, MECCH, MPRW-HGNN, HAN-ME, MF2Vec และ MHCL ทำแล้ว ทุกงานส่งข้อมูลเข้าโหนดเป้าหมายเพียงทางเดียว
  • ต้องลดข้ออ้างการไม่ใช้รายการ meta-path ก็ไม่ใหม่MF2Vec สุ่ม walk โดยไม่แยกตาม schema, MHCL ใช้ BFS ทุก instance, AHGNN นับทุก meta-path จนถึงความยาวที่กำหนด
  • กระทบ C2bน้ำหนัก attention ของ meta-path ไม่ใช่คำอธิบายเสมอไปKDD 2026: HAN บน DBLP มี Kendall τ = 0.053 (p = 0.43) ระหว่าง attention กับความสำคัญจริง
  • ยังว่างไม่พบงานที่ใส่ instance ของ meta-path เป็น cell ใน sheafและไม่พบงานที่ให้เหตุผลเชิงทฤษฎีว่า instance ให้ข้อมูลอะไรเกินกว่าปลายทั้งสอง ช่องนี้คือที่ยืนจริงของเรา
คำศัพท์

คำที่ใช้ในหน้านี้

Meta-path (schema)
แบบแผนของเส้นทางตามชนิดโหนด เช่น Paper–Author–Paper (PAP) ยังไม่บอกว่าเป็นโหนดตัวไหน
Instance
เส้นทางจริงหนึ่งเส้นที่ตรงแบบแผน เช่น P1–A7–P9
โหนดกลาง
โหนดระหว่างปลายทั้งสองของ instance เช่น A7
Induced graph
กราฟใหม่ที่ลากเส้นตรงระหว่างปลายทั้งสองของทุก instance (P1–P9) แล้วทิ้งโหนดกลาง
Precompute
คำนวณค่าเฉลี่ยของเพื่อนบ้านตาม meta-path ไว้ก่อนฝึกครั้งเดียว แล้วใช้เป็น feature (SeHGNN)
Schema-free
ไม่ต้องมีรายการ meta-path จากผู้เชี่ยวชาญ โมเดลค้นหรือสุ่มเส้นทางเอง
Heterophily
โหนดที่เชื่อมกันมักมี label ต่างกัน
Sheaf
กติกาที่บอกว่าก่อนเทียบข้อมูลของสองโหนดที่เชื่อมกัน ต้องแปลง (หมุน) ข้อมูลของแต่ละข้างอย่างไร
Write-back
หลังรวมข้อมูลของ instance แล้ว ส่งผลกลับไปให้ใครบ้าง: เฉพาะเป้าหมาย หรือทุกโหนดใน instance
ตัวอย่างเดียวใช้ทั้งหน้า

บทความ P1 กับ P9 มีผู้เขียนร่วม A7

โจทย์: ทำนายสาขาของ P1 แต่ละตระกูลข้างล่างใช้เส้นทางนี้ต่างกัน ความต่างอยู่ที่สามคำถาม: (1) A7 ถูกใช้หรือถูกทิ้ง (2) น้ำหนักของเส้นทางนี้ขึ้นกับอะไร (3) ผลส่งกลับไปที่ใคร

หกตระกูล

งานปี 2025–2026 ใช้ meta-path แบบไหน

1 · Precompute ระดับ schema

เฉลี่ย feature ของเพื่อนบ้านตามแต่ละ meta-path ไว้ก่อนฝึก P1 ได้ค่าเฉลี่ยของ P ทุกตัวที่ผ่าน PAP A7 หายไปในค่าเฉลี่ย เร็วมากและขยายไปกราฟใหญ่ได้

SeHGNN · HetTree · AHGNN · Echoless-LP · RpHGNN

2 · Induced graph ต่อ meta-path + attention

สร้างกราฟ P–P ต่อ meta-path แล้ว GNN ต่อกราฟ รวมด้วย attention ระดับ schema เส้น P1–P9 ไม่รู้ว่าผ่าน A7

HAN · HGOT · HGMS · MUG · HGEN · MHCL (ส่วน view)

3 · เข้ารหัส instance พร้อมโหนดกลาง

เข้ารหัส P1–A7–P9 ทั้งเส้น (เฉลี่ย หมุน LSTM หรือ attention ตามลำดับ) แล้วให้น้ำหนักต่อ instance ส่งผลเข้า P1 เพียงโหนดเดียว

MAGNN · MECCH · MPRW-HGNN · HAN-ME · MF2Vec · MHCL

4 · ไม่ใช้ meta-path เลย

ใช้ชนิดความสัมพันธ์ ชนิดโหนด หรือโหนดเสมือนแทน เป็นกลุ่มที่โตเร็วที่สุดและมักได้คะแนนสูงสุดบน HGB

HeSRN · HypHGT · VN-HGCN · HGUL · RGCN (tuned)

5 · ค้นหาหรือสร้าง meta-path

หา meta-path ที่ดีที่สุดด้วย search, RL หรือ LLM แล้วส่งให้โมเดลอื่น

LMSPS · AutoGNR · EvoPath · HetGCoT · FHGE

6 · งานวิเคราะห์ที่ตั้งคำถามกับทั้งสาขา

ตรวจว่าสถาปัตยกรรมช่วยจริงไหม และน้ำหนัก attention อธิบายการทำนายได้จริงไหม

MAGNN กับ cell ของเรา คำนวณสิ่งเดียวกันในกรณีหนึ่ง

ตัวเข้ารหัส "relational rotation" ของ MAGNN (สมการ 10) หมุนสถานะของแต่ละโหนดตามความสัมพันธ์ที่ผ่าน แล้วเฉลี่ย สถานะ cell ของเรา zf ทำแบบเดียวกัน ถ้าการหมุนของเราขึ้นกับชนิดความสัมพันธ์อย่างเดียว ทั้งสองสูตรจะเท่ากันทุกตัวเลข

MAGNN:  o₀ = h(P1);  o₁ = h(A7) + o₀ ⊙ r₁;  o₂ = h(P9) + o₁ ⊙ r₂;  ผล = o₂ / 3
H2S-NN: z_f = ( T_P1·x_P1 + T_A7·x_A7 + x_P9 ) / 3     (T = การหมุนต่อกันไปที่กรอบของ P9)
ตรวจตัวเลข: max |MAGNN − z_f| = 1.2 × 10⁻¹⁶

ความเท่ากันนี้เกิดเฉพาะกรณีพิเศษที่ H2S-NN ไม่ได้ใช้ ส่วนที่ต่างจริงเหลือสี่ข้อ ข้อแรกที่เคยเขียนไว้ถูกถอน (ยังไม่มีหลักฐานว่าข้อใดช่วยความแม่นยำ):

  1. ลำดับของความสัมพันธ์ ถอน ใช้เป็นความต่างจาก MAGNN ไม่ได้ เพราะ MAGNN แยกประมวลผลทีละ meta-path อยู่แล้ว PAPV กับ PVPA จึงแยกกันตั้งแต่ต้น การหมุนที่สลับลำดับได้มีผลเฉพาะภายใน meta-path เดียว ซึ่งลำดับของชนิดถูกกำหนดแล้ว (ตัวเลขที่เคยใส่ไว้: การหมุนของ MAGNN เป็นการคูณทีละตัวเลขเชิงซ้อน จึงสลับลำดับได้: |rarb − rbra| = 1.1×10⁻¹⁶ ของเราเป็นเมทริกซ์หมุนที่สลับลำดับไม่ได้: |QaQb − QbQa| = 1.14 (ตรวจด้วยตัวเลข) ดังนั้นใน MAGNN เส้นทางที่ผ่านความสัมพันธ์ชุดเดียวกันแต่ลำดับต่างกันจะหมุนสถานะเท่ากัน ของเราไม่เท่ากัน เป็นจริงทางคณิตศาสตร์ แต่ไม่ทำให้แยกอะไรได้เกิน MAGNN)
  2. การหมุนขึ้นกับคู่โหนด ของเราอ่านจาก [h₀, c] ของทั้งสองปลายของแต่ละเส้น ของ MAGNN มีเวกเตอร์เดียวต่อชนิดความสัมพันธ์
  3. Write-back ผลส่งกลับไปทุกโหนดใน instance รวม A7 และ P9 ส่วน MAGNN ส่งเข้า P1 อย่างเดียว
  4. เรขาคณิตชุดเดียวกับเส้นเชื่อม การหมุนในเส้นทางคือ map ของเส้นเชื่อมตัวเดียวกับที่ใช้ใน Δ₀ (Prop. 1) จึงพิสูจน์ได้ว่าเพิ่ม instance แล้วไม่ขัดกับข้อมูลที่เส้นเชื่อมยืนยัน (Prop. 2) ใน MAGNN เวกเตอร์หมุนเป็นพารามิเตอร์แยก ไม่ผูกกับอะไร
  5. การประกอบทั้งโมเดล ของเราเป็น operator เชิงเส้นตัวเดียว ใช้ K รอบผ่าน filter bank ที่พิสูจน์ได้ว่าเสถียรทุกค่าพารามิเตอร์ (Props. 3, 5) น้ำหนัก instance เป็น exp(g) ไม่ normalise ด้วย softmax ส่วน MAGNN มี attention softmax ต่อเป้าหมาย, attention ระดับ meta-path ที่ใช้ร่วมทั้งกราฟ และ nonlinearity ต่อชั้น

สาขากำลังไปทางไหน

  1. งานใหม่ส่วนใหญ่เลิกใช้ meta-path HeSRN, HypHGT, VN-HGCN และ HGUL ใช้ชนิดความสัมพันธ์หรือโหนดเสมือนแทน และอ้างว่าได้คะแนนสูงสุดบน HGB งานที่ยังใช้ meta-path ส่วนใหญ่ย้ายไปที่ self-supervised หรือ pre-training (HGOT, HGMS, MUG)
  2. งานที่ใช้ instance พร้อมโหนดกลางยังเป็นกลุ่มเล็ก และทุกงานส่งผลเข้าโหนดเป้าหมายทางเดียว ไม่มีงานใดพิสูจน์ว่าโหนดกลางให้ข้อมูลอะไรเกินกว่าปลายทั้งสอง
  3. การไม่ต้องมีรายการ meta-path กลายเป็นเรื่องปกติ แต่ทำได้สองแบบ: นับทั้งหมดจนถึงความยาวที่กำหนด (HetTree, AHGNN, MHCL ซึ่งต้นทุนโตตามจำนวนเส้นทาง) หรือสุ่ม walk (MF2Vec ซึ่งไม่ระบุการกระจาย) ยังไม่พบงานที่สุ่มจากการกระจายที่ระบุพร้อมตัวประมาณที่ไม่ลำเอียงอย่าง WISP
  4. ความน่าเชื่อถือถูกตั้งคำถามมากขึ้น ทั้งเรื่องสถาปัตยกรรม (causal 2025) และเรื่องการอ่านความสำคัญของ meta-path (KDD 2026) reviewer ปี 2026 จะคาดหวัง baseline ที่ tune ดีและการตรวจข้าม seed
  5. การรั่วของ label เป็นประเด็นเปิด Echoless-LP แสดงว่าการเอา label ของเพื่อนบ้านมาเป็น feature ทำให้ label ของตัวเองย้อนกลับมาผ่าน walk H2S-NN ไม่ใช้ label เป็น input แต่ baseline บน ogbn-mag หลายตัวใช้ ต้องระบุใน protocol ว่าใช้แบบไหน

Novelty: meta-path ใน sheaf

สิ่งที่โมเดลทำกับ P1–A7–P9 ในหนึ่งรอบ

  1. หมุนเวกเตอร์ของทั้งสามโหนดเข้ากรอบเดียวกันแล้วเฉลี่ย: z_f = (x_P1 + T_A7·x_A7 + T_P9·x_P9) / 3 โดย T มาจาก map ของเส้น P1–A7 และ A7–P9 (Prop. 1 ไม่มีพารามิเตอร์ใหม่)
  2. ทุกโหนดใน instance ถูกดึงเข้าหา zf ด้วยความแรง w_f = exp(g(…)); g เป็น MLP ที่ให้ตัวเลขเดียว
  3. ทำซ้ำ K รอบผ่าน filter bank Prop. 2 พิสูจน์ว่าเทอมนี้เท่ากับ hub node หนึ่งตัวต่อ instance (D4 T2 ต่างกัน 2.6×10⁻¹⁵)

คำตอบสี่ข้อ

  • "งานแรกที่รวม meta-path เข้าใน sheaf" จริงเท่าที่ค้นได้ แต่เป็น novelty แบบประกอบสองอย่าง reviewer จะถามว่าการรวมนี้ให้อะไรที่ MAGNN หรือ HetSheaf ให้ไม่ได้
  • "แค่ MLP(meta-path) ใส่โหนดเป็น feature" ไม่ตรง MLP (g) ให้แค่น้ำหนัก สิ่งที่เข้าโหนดคือสถานะที่หมุนแล้ว คำวิจารณ์ที่แรงกว่าคือความเหมือน MAGNN (ส่วนด้านบน)
  • "meta-path ขึ้นกับ instance" มีแล้วตั้งแต่ MCRec (2018), MAGNN (2020), ConCH, MECCH, HAN-ME
  • ดีไซน์เก่าไม่ได้ป้องกันตัวได้ดีกว่า reviewer WSDM R2 W3 ชี้ว่า face term ของ v1 ไปถึงโหนดผ่าน closure edge เท่านั้น และ Lemma A′ พิสูจน์ว่าการดำเนินการเชิงเส้นแบบ Hodge บน 2D ส่งข้อมูลจาก 2-cell ไปไม่ถึงโหนดเลย

ความจริงหลังถูกท้าทาย

1 · เหมือน MAGNN ตรงไหน

เหมือนสูตรเดียว: เฉลี่ยสถานะของโหนดในเส้นทางหลังหมุนตามเส้นทาง เท่ากันทุกตัวเลขเมื่อการหมุนขึ้นกับชนิดความสัมพันธ์อย่างเดียว ไม่ได้ลอก: สูตรของเรามาจาก D4 (6 พ.ย.) ที่หาสถานะที่ทำให้พลังงานของ cell ต่ำที่สุด ส่วน MAGNN มาจาก RotatE ทั้งคู่ได้สูตรเดียวกันเพราะทำสิ่งเดียวกัน: รวม instance เข้าจุดกลางจุดเดียว ความผิดฝั่ง Claude: session ที่ออกแบบ D4 ไม่ได้เทียบกับ MAGNN ในระดับสูตร และเขียนข้อแตกต่างไว้หลวม ๆ ว่า "no consistency" โดยไม่มีใครตรวจ

2 · กราฟเรายังเป็น 2D ไหม

ในการคำนวณ ไม่ใช่ Prop. 2 พิสูจน์ว่าเทอม path cell เท่ากับกราฟธรรมดาที่เพิ่ม hub หนึ่งตัวต่อ instance แล้วตัด hub ออก (D4 T2: 2.6×10⁻¹⁵) ไม่มีสถานะบนเส้นเชื่อม ไม่มีการวัดรอบวง closure edge มีแค่ในนิยาม ส่วนเดียวของ 2D ที่ยังทำงานคือข้อบังคับว่าการหมุนของ hub ต้องมาจาก map ของเส้นเชื่อม ซึ่งเขียนเป็นภาษากราฟได้ทั้งหมด

v1 ก็ไม่ได้เป็น 2D ที่มีผลจริง Lemma A′: การคำนวณเชิงเส้นแบบ Hodge ส่งข้อมูลจาก 2-cell ไปโหนดไม่ได้ ใน v1 ข้อมูลไปถึงโหนดผ่าน closure edge เท่านั้น ซึ่งเท่ากับเส้นตรงระหว่างปลาย (reviewer WSDM R2 W3: "endpoint relation in disguise") คำอ้าง "2D เชิงโครงสร้าง" จึงเกินจริงตั้งแต่ v1

3 · Meta-path เป็นข้อมูลเสริมหรือโครงสร้าง

เป็นโครงสร้างในความหมายของกราฟ (เพิ่มการเชื่อมต่อใน operator) ระดับเดียวกับ hyperedge ไม่ใช่โครงสร้าง 2D และ Prop. E ของเราเองบอกว่าถ้าน้ำหนักเท่ากันทุก cell สิ่งที่เพิ่มแทบไม่ให้อะไรเกินการแพร่ผ่านเส้นเชื่อม ส่วนเดียวที่ให้ข้อมูลใหม่คือน้ำหนัก wf หลักฐาน: ยังไม่มีงาน known-answer ที่ cells ชนะ no cells (S1: no_path_cells ได้ 0.996); บน S1′ full ไม่เรียนรู้การเลือก; oracle พิสูจน์แค่ความจุ

4 · Novelty เมื่อเล่าด้วยภาษาคนทั่วไป

ใช้คนกลางของเส้นทาง: มีแล้ว · ให้น้ำหนักตามคนบนเส้น: MAGNN ทำแล้ว · ไม่ต้องกำหนดแบบแผน: มีแล้ว · heterophily: มีแล้ว สิ่งที่เหลือคือทฤษฎีความเสถียร ซึ่ง reviewer ส่วนใหญ่ไม่นับเป็น novelty ของงาน คำวิจารณ์ที่คาดได้: "MAGNN ที่เขียนใหม่ด้วยคณิตศาสตร์ยาก"
